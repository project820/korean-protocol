# Korean Protocol 0.7.0의 설치·배포 계약을 정의한다

이 문서는 **기존 0.7.0 상시 지침·서명 배포의 관리 계약**이다. 신규 사용자는 [v0.8.0 스킬 설치](../../INSTALL.md)를 따른다. 기존 사용자는 [상시 지침 전환](../../INSTALL.md#기존-07-상시-지침에서-전환한다)을 먼저 확인한다. 아래 계약은 수동 스킬 복사본에 적용하지 않는다.

0.7.0 상시 지침은 한 번 설치한 뒤 로컬에서 계속 사용한다. 서명 콘텐츠는 0.7.0·순번 3이며 엔진 0.2.0 이상을 요구한다. [기존 관리 절차](../../INSTALL.md#기존-07-관리-절차를-사용한다)는 0.7 설치·복구 경로를 설명한다.

## 콘텐츠·코드·패키지의 버전을 구분한다

| 대상 | 현재 기준과 갱신 범위 |
| --- | --- |
| 규약 원본 | V7 r2를 채택한 0.7.0-draft다. |
| 서명 콘텐츠 | 0.7.0·순번 3이며 원본은 `67f537e`다. |
| 관리 엔진 | 0.2.0이며 사용자가 검토한 설치 도구로 명시적으로 갱신한다. |
| 데이터 schema | 규칙·사전은 1.0이며 manifest의 호환 번호 1과 대응한다. |
| 사용자 패키지 | [v0.7.0 ZIP·채팅 파일](https://github.com/project820/korean-protocol/releases/tag/v0.7.0)은 `7e01d53`의 고정 산출물이다. 최신 main의 문서가 자동 반영되지 않는다. |

자동 갱신은 프로필 세 개·규칙 JSON·사전 JSON 두 개·규약 본문의 일곱 콘텐츠만 교체한다. manifest·서명은 인증 자료이며 Python 설치기·hooks·실행 코드·안내·원시 평가 로그는 콘텐츠 갱신 대상이 아니다. 콘텐츠 안의 명령을 설치기가 실행하지 않는다.

규약은 모델의 표현 지침이다. 구조 검사·서명 인증·파일 설치를 응답의 사실·양태·책임 보존이나 독자 이해도 보장으로 확대하지 않는다.

## 같은 대상과 상태를 보존한다

사용자·프로젝트 설치는 별도 상태 루트를 사용하며 한 상태 루트는 호스트 대상 파일 하나만 관리한다. 일반 에이전트 설치 도구는 Codex·Claude Code의 사용자 범위를 지원한다. 저수준 런타임은 프로젝트 범위와 Gemini 파일 adapter도 제공하며 실제 호스트 지원은 [지원표](host-support.md)를 따른다.

기본 런타임 상태 위치는 macOS의 `~/Library/Application Support/KoreanProtocol/`, Linux의 XDG 데이터 폴더 아래 `korean-protocol/`다. 에이전트 설치 도구는 호스트별 상태 폴더를 따로 선택하며 반환된 `state_dir`를 관리 기준으로 사용한다. 프로젝트 설치는 `--scope project`만으로 상태를 프로젝트 안에 만들지 않으므로 별도 `--state-dir`를 명시한다.

상태에는 설정·활성 버전·캐시 ID·호스트 문맥·관리 블록 hash·최고 순번·pin·신뢰 키·백업·저널·잠금을 저장한다. POSIX 디렉터리와 신뢰 파일은 사용자 소유·비공개 권한을 검사한다. symlink·hardlink·상위 경로 교체·공동 쓰기 경로를 우회 수단으로 수락하지 않는다.

호스트 파일은 로컬 adapter가 결정하며 원격 manifest가 지정하지 않는다. Codex·Gemini는 공유 지침의 관리 블록을, Claude Code는 전용 규칙 파일의 관리 블록을 소유한다. 블록 밖 바이트·줄바꿈·사용자 변경은 보존한다. 중복·손상 표식·다른 상태 소유·수정된 관리 블록은 덮어쓰지 않고 exit 7로 중단한다.

## 신뢰와 원격 수락을 구분한다

첫 신뢰는 검토한 로컬 저장소·별도로 확인한 Ed25519 키·지문이다. 같은 미확인 출처에서 받은 키와 해시만으로 발행자를 독립 인증하지 못한다. 신뢰 키를 원격 콘텐츠로 자동 교체하지 않는다.

서명은 release.json 원본 bytes를 SSHSIG namespace `kproto-release-v1`·principal `kproto-release`로 검증한다. 확인된 OpenSSH 검증기를 제한 시간·별도 인자로 실행하며 콘텐츠나 자격 정보 환경을 검증기 명령으로 실행하지 않는다.

HTTPS는 기본 인증서 검증을 유지한다. HTTP·userinfo·credential query·redirect·다른 origin·크기·시간 제한 초과를 거부한다. manifest를 먼저 인증한 뒤 고정 경로·역할·크기·해시의 일곱 파일을 받는다. 전체 네트워크 deadline은 60초이며 개별 worker 제한과 서명·로컬 쓰기 시간은 구분한다.

만료·미래 발행·낮은 순번·같은 순번의 다른 hash·현재보다 낮은 버전·호환 오류를 거부한다. 이미 설치한 캐시의 만료는 로컬 사용 기한이 아니다. 서명과 TLS만으로 더 최신 버전이 숨겨졌는지 알 수 없으므로 마지막 조회 성공·실패를 구분한다.

미서명 로컬 설치는 `trust=local-snapshot`으로 기록하고 자동 갱신을 끈다. 기존 서명 설치를 이 모드로 덮어쓰지 않는다. private endpoint는 같은 origin HTTPS와 명시한 환경 변수의 Bearer 값만 사용하며 토큰값을 설정·상태·로그에 저장하지 않는다. GitHub private Releases redirect·토큰 자동 탐색은 별도 adapter가 없다.

## 갱신 실행과 표현 설정을 분리한다

성공 후 기본 간격은 24시간이며 1~168시간을 선택한다. `interval`은 반환된 `run` wrapper로 호스트를 시작할 때만 주기를 확인한다. macOS `scheduled`는 설정 파일 생성과 OS 등록을 구분하며 실제 등록 작업은 로그인 시·매시 정각에 기한을 확인한다. Linux systemd·Windows 예약 등록은 제공하지 않는다.

자동 조회 실패의 재시도 간격은 1·2·4·8·16·24시간이다. 수동 `update`는 대기·자동 갱신 OFF와 별개로 조회하지만 pin은 조회·적용을 막는다. 캐시 rollback은 순번 최고값을 보존하고 선택 버전을 pin한다.

규약·높임말은 갱신·재설치·롤백에서 보존한다. **서명 재설치는 이번 `--autoupdate` 값으로 다시 설정하며 생략하면 OFF다.** 기존 예약·wrapper를 유지하려면 같은 방식을 명시하고 실제 연결을 확인한다. 콘텐츠 updater는 관리 코드를 교체하지 않는다.

## 원자 교체와 복구를 확인한다

쓰기 명령은 상태·대상 잠금을 잡고 저널을 확인한다. 검증한 캐시를 준비한 뒤 대상과 상태를 원자 교체하며 중단되면 저널의 원본·후보 hash를 대조한다. 다른 사용자 변경은 복구로 덮어쓰지 않는다. status는 복구 필요를 보고하며 읽기만으로 복구하지 않는다.

다운로드 시도별 임시 폴더는 정상 종료 때 정리한다. 강제 종료·전원 손실 뒤의 모든 잔여 폴더 정리나 파일시스템 내구성을 보장하지 않는다. 백업·검증 캐시는 자동으로 삭제하지 않는다.

제거는 소유한 관리 블록·예약 연결만 해제한다. 상태·백업·캐시·관리 도구는 남으며 새로 만들었던 빈 지침 파일도 남을 수 있다. 자동 diff·관리 블록 재소유·purge·키 rotation은 제공하지 않는다.

## 현재 명령과 종료 코드를 사용한다

```sh
python3 -B -m runtime.kproto --state-dir /ABS/STATE COMMAND
```

| 명령 | 동작 |
| --- | --- |
| `status --json` | 활성 버전·대상·충돌·캐시·설정·복구 상태를 읽는다. |
| `update`·`update --scheduled` | 수동 또는 주기 수락 조건으로 콘텐츠를 확인한다. |
| `update --pin CURRENT_VERSION`·`update --unpin` | 현재 버전을 고정하거나 해제한다. |
| `rollback --version CACHED_VERSION` | 인증된 보존 캐시로 전환하고 pin한다. |
| `autoupdate configure --mode off|interval|scheduled` | 자동 갱신 방식을 정하며 간격은 `--interval-hours`로 지정한다. |
| `scheduler register|status|unregister` | 소유한 macOS 예약 연결을 관리한다. |
| `recover`·`uninstall` | 저널 복구 또는 요청한 설치 제거를 수행한다. |
| `run -- codex` | 주기가 왔으면 갱신한 뒤 정상 로컬 프로필로 호스트를 시작한다. |

위의 `|`는 선택지이며 그대로 실행하는 shell 파이프가 아니다. 런타임의 `status --host`·응답 `check`·자동 diff는 없다. 호스트별 status와 표현 configure는 별도 에이전트 설치 도구를 사용한다.

종료 코드는 0 성공, 2 입력, 3 네트워크·인증, 4 설치·캐시 없음, 5 신뢰·해시·시간·순번, 6 호환, 7 소유·경쟁·잠금 충돌, 8 파일 쓰기·복구 실패다. run은 정상 호스트를 시작하면 그 호스트의 종료 코드를 반환하며 갱신 실패는 상태·진단으로 남긴다.

설치·간격은 [서명 설치](signed-install.md), 적용 설정은 [설정 안내](application-controls.md), 발행은 [게시자 안내](publisher.md), 확인 범위는 [검증 계획](verification.md)과 [실제 0.7.0 증거](public-0.7.0-verification.md)를 따른다.

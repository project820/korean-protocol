# 0.7.0의 규약 적용과 높임말을 전환한다

이 문서는 **기존 0.7.0 상시 사용자 지침**의 관리 명령을 설명한다. v0.8.0 스킬은 [스킬 설치·호출 안내](on-demand-skill.md)를 사용한다. 0.7에서 옮길 때는 [전환 절차](../../INSTALL.md#기존-07-상시-지침에서-전환한다)를 따른다.

0.7.0은 Codex·Claude Code의 사용자 지침에 설치하며 호출형 스킬이 아니다. 설치한 호스트와 홈 환경에서 규약이 ON이면 새 대화를 시작한 뒤 평소처럼 요청한다. 매번 “Korean Protocol을 써라”라고 호출할 필요는 없다.

신규 설치는 규약 ON·높임말 OFF로 시작한다. 기존 설치의 두 선택은 갱신·재설치·롤백에서 보존한다. 높임말 OFF는 새 설명·보고에 높임말을 요구하지 않는 설정이며 규약 OFF가 아니다.

## 에이전트에 복사해서 요청한다

아래 문구는 내장 명령이나 슬래시 명령이 아니라 에이전트에게 맡기는 작업 요청이다. 파일·명령을 다룰 수 있는 설치 대상 에이전트에 원하는 요청 하나를 보낸다. ChatGPT 첨부 방식은 [채팅 안내](../../distribution/CHAT-START.md)를 따른다.

설정은 바꾸지 않고 설치 상태와 적용 근거를 확인하려면 다음을 복사한다.

```text
설치된 Korean Protocol의 버전, 적용 대상, ON/OFF와 높임말 설정을 확인해줘.
설정은 바꾸지 말고 파일 검증 결과와 현재 대화의 로딩 확인 여부를 구분해 알려줘.
확인할 수 없는 항목은 확인하지 못했다고 표시해줘.
```

앞으로 시작할 대화에서 규약을 끄려면 다음을 복사한다.

```text
이 환경에 설치된 Korean Protocol의 영구 설정을 OFF로 바꿔 줘. 같은 설치의 관리 명령을 사용하고 변경 뒤 상태를 확인해 줘. 높임말과 자동 갱신 설정은 유지해 줘.
```

앞으로 시작할 대화에서 규약을 켜려면 다음을 복사한다.

```text
이 환경에 설치된 Korean Protocol의 영구 설정을 ON으로 바꿔 줘. 같은 설치의 관리 명령을 사용하고 변경 뒤 상태를 확인해 줘. 높임말과 자동 갱신 설정은 유지해 줘.
```

높임말만 켜려면 다음을 복사한다.

```text
이 환경에 설치된 Korean Protocol의 높임말 영구 설정만 ON으로 바꿔 줘. 규약과 자동 갱신 설정은 유지하고 변경 뒤 상태를 확인해 줘.
```

높임말만 끄려면 다음을 복사한다.

```text
이 환경에 설치된 Korean Protocol의 높임말 영구 설정만 OFF로 바꿔 줘. 규약과 자동 갱신 설정은 유지하고 변경 뒤 상태를 확인해 줘.
```

설정을 바꾼 뒤 설치한 호스트에서 새 대화를 시작한다. 특히 규약 OFF는 이미 현재 대화에 읽힌 지침을 지우지 않는다. 규약이 OFF인 동안 높임말 설정을 바꿔도 규약을 켜지 않는다. 자동 갱신 ON/OFF는 별도 설정이다.

## 설치 후 평소처럼 사용하고 확인한다

새 대화에서 “다음 문장을 뜻과 조건을 유지하며 다듬어 줘”처럼 평소 요청을 보낸다. 규약은 설치한 호스트·홈의 사용자 지침을 읽는 대화에 적용하며, 다른 앱이나 별도 홈 환경으로 자동 전달되지 않는다.

설치 파일 상태와 실제 출력은 따로 확인한다. 아래 상태 표는 파일·캐시 검사의 결과이며 모델이 지침을 로딩했다는 증거가 아니다. 새 대화에서 호스트가 제공하는 지침 로딩 정보나 읽기 기록을 확인할 수 있을 때 그 근거를 보고한다. 그런 정보가 없으면 로딩을 확인하지 못했다고 보고한다.

짧은 출력 점검에는 다음을 사용한다. 결과에서 대상·조건·수량·기한이 보존됐는지 확인한다. 한 번의 샘플이 모든 응답의 준수를 증명하지는 않는다.

```text
다음 문장을 뜻과 조건을 유지하며 다듬어 줘.
“승인된 주문만 10월 20일 오후 3시까지 출고한다. 미승인 주문은 출고하지 않는다.”
```

`protocol`은 규약 적용 여부, `honorifics`는 새 설명·보고의 높임말 여부를 저장한다. 직접 명령을 실행하는 방법은 아래를 따른다.

## 같은 설치의 지속 관리 명령을 사용한다

설치 결과의 `management_commands`에는 `protocol_on`·`protocol_off`·`honorifics_on`·`honorifics_off`·`status`가 있다. 반환된 경로는 원래 복제본을 옮겨도 사용한다.

검토한 checkout에서 관리할 때는 다음 명령도 사용할 수 있다. Claude Code에는 `--host claude-code`를 쓰고 기존의 별도 홈·상태 경로를 모두 전달한다.

아래 변경 중 원하는 하나만 선택한다. 규약을 끄려면 다음 명령을 사용한다.

```sh
python3 -B distribution/agent_install.py configure --host codex --protocol off
```

규약만 켜려면 다음 명령을 사용한다.

```sh
python3 -B distribution/agent_install.py configure --host codex --protocol on
```

규약 선택은 유지하고 높임말만 켜려면 다음 명령을 사용한다.

```sh
python3 -B distribution/agent_install.py configure --host codex --honorifics on
```

규약 선택은 유지하고 높임말만 끄려면 다음 명령을 사용한다.

```sh
python3 -B distribution/agent_install.py configure --host codex --honorifics off
```

선택한 변경 뒤 상태를 확인한다.

```sh
python3 -B distribution/agent_install.py status --host codex
```

`configure`에만 적용 옵션을 전달한다. 현재 선택 대상이 설치 당시 대상과 다르거나 관리 본문이 수정됐으면 덮어쓰지 않는다. 기존 설치에는 새 홈이나 상태 폴더를 임의로 만들지 않는다.

## 상태를 구분한다

| 상태 | 의미 |
| --- | --- |
| `host`·`target`·`state_dir` | 요청한 호스트·설치 대상 파일·상태 폴더와 같은지 확인한다. |
| `version`·`trust` | 설치 버전과 신뢰 방식을 확인한다. |
| `enabled=true` | 규약 적용 설정이 ON이다. 실제 파일 상태는 검증 결과와 함께 확인하며 모델 로딩이나 출력 준수를 증명하지 않는다. |
| `installed=true` | 관리되는 설치가 남아 있다. 규약 ON을 뜻하지 않는다. |
| `enabled=false` | 활성 프로필 대신 소유권 표지만 호스트 파일에 둔다. |
| `content_verified=true` | 활성 캐시의 콘텐츠 무결성 검사가 통과했다. 게시자 인증 여부는 `trust`도 확인한다. |
| `verified=false`와 규약 OFF | 콘텐츠를 검증했어도 현재 적용은 꺼져 있을 수 있다. |
| `target_matches=false` 또는 `recovery_required=true` | 정상 적용으로 보고하지 않고 경로·복구 문제를 해결한다. |

ON은 캐시를 다시 검증해 지침을 복원한다. 서명된 콘텐츠의 바이트는 높임말 전환으로 바꾸지 않으며 설치기는 호스트 본문에 설정을 반영한다. 짧은 상태형·인용·기존 제품 문체를 높임말 선택만으로 불필요하게 늘리지 않는다.

## 규약 OFF와 자동 갱신 OFF를 구분한다

규약 OFF는 신뢰 키·콘텐츠 캐시·높임말·자동 갱신 선택을 보존한다. 자동 조회도 멈추려면 반환된 `runtime_commands.configure_off`를 실행한다. 자동 갱신 OFF에서도 사용자가 명시한 수동 `update`는 원격 작업이다.

서명 `install`의 `--autoupdate`는 기본값이 OFF다. 재설치로 기존 예약·시작 갱신을 유지하려면 같은 방식을 명시하고 연결을 재확인한다. 규약·높임말이 보존됐다는 사실만으로 자동 갱신도 유지됐다고 보고하지 않는다. 실행 방식과 1~168시간 간격은 [서명 설치 안내](signed-install.md)를 따른다.

## 현재 대화와 영구 설정을 구분한다

“이번 답변만 높임말로 써 줘”나 “이번 답변은 규약 적용 없이 써 줘”는 해당 출력에 대한 요청이다. 이 요청으로 설치 파일의 영구 설정이 바뀌지는 않는다. 현재 대화의 상위 지침과 함께 해석하며, 문자열을 감지하는 별도 프로그램이나 출력 차단 필터는 없다.

앞으로 시작할 대화의 기본값을 바꾸려면 위의 영구 설정 요청이나 관리 명령을 사용한다. 영구 변경은 관리 명령 실행 뒤 `status` 결과로 확인한다.

현재 대화에 설치본을 적용할 때는 `status`가 검증한 관리 본문과 활성 캐시만 참조한다. 미검증 checkout을 대신 읽거나 규약 OFF를 임의로 켜지 않는다. 이미 읽은 지침은 파일 변경으로 대화 기록에서 지워지지 않으므로 새 세션에서 확인한다.

## 관리 엔진과 호출 경로를 이관한다

규약 0.7.0은 엔진 0.2.0 이상이 필요하다. [관리 도구 재설치](../../INSTALL.md#기존-설치의-관리-도구를-먼저-갱신한다)는 콘텐츠 자동 갱신과 별도다. 새 도구는 소유한 예약 파일·작업의 관리 경로를 확인하며 충돌·실패 시 이전 사용자 내용을 보존한다.

직접 만든 외부 wrapper는 자동 이관하지 않는다. 반환된 새 `runtime_argv.run` 또는 `runtime_commands.run`으로 호출 경로를 교체한다. 제거는 요청한 관리 블록과 소유 예약 작업만 해제하며 상태·백업·캐시를 남긴다.

원문·KP·STE 정식 비교는 미완료다. 이 문서의 파일럿·설치 검사는 품질 합격을 뜻하지 않는다.

### L1~L4 산출물과 참조 읽기 의무를 정의했다

`SKILL.md`의 description과 4A절에 단계별 산출물을 명시했다.
L2~L4는 작성 전에 지정한 참조 파일을 읽는다.
파일을 읽을 수 없을 때 지킬 하한도 본문에 뒀다.

| 단계 | 산출물 | 읽을 파일 |
| --- | --- | --- |
| L1 | 텍스트 | 별도 참조 파일을 요구하지 않는다. |
| L2 | 표·Mermaid 도식 | `references/output-formats.md`의 L2절을 읽는다. |
| L3 | 단일 `index.html` | `references/interactive-html.md`와 `assets/interactive-explainer.html`을 읽는다. |
| L4 | Manim 코드·내레이션 | `references/video-script.md`를 읽는다. |

L4는 사용자가 영상화·애니메이션 코드를 명시 요청할 때만 선택한다.

설치 파일은 v0.11.0과 같은 13개다. 바뀐 파일은 5개다.

### 같은 조건의 형식 준수 진단을 대조했다

원문은 회의실 예약 취소 안내 1종이다.
생성 모델은 Sonnet 5.5·Sol·Terra·Grok 4.7이다.
추론은 `medium`이다. 기본 실험은 KP·STE 모두 모델마다 2회 반복했다. Sonnet L3는 규칙 보강 뒤 KP만 2회 더 돌렸다.

STE 대조군도 같은 모델·요청·반복으로 L3 8건과 L2 4건을 생성했다.
STE L3는 8건 모두 입력 없는 정적 문서였다.
상세 기록은 [v0.11.1 형식 준수 진단](../../evaluation/kp-v0111-output-formats-20261113/README.md)에 보존한다.

- **남은 문제:** Sonnet은 `SKILL.md`만 받은 조건에서 원자료에 없는 수치 입력을 4/4회 만들었다.
- **해당 입력:** ‘이용 시작 몇 시간 전’과 ‘안내 후 경과 시간’을 만들었다.
- **참조 효과:** 규칙 보강 뒤 참조 포함 조건에서는 2/2회 모두 해당 입력이 없었다.
- **배치 한계:** `SKILL.md`만 받은 조건의 격자 CSS 사용은 0/10이었다.
- **진단 범위:** 수치 원문은 시험하지 않았다. 이 결과는 형식 준수 진단이다.
- **L1 회귀:** 파일럿 사례 5개를 4모델로 한 번씩 생성하고 Astra high가 가려서 1회 판정했다. v0.11.1의 의미 통과는 16/20(실패 3, 미해결 1)이고 1,000자당 문체 위반은 2.4다. 같은 검토에서 v0.10.1은 19/20, STE는 14/20이었다. v0.11.0의 이전 검토 값은 17/20, 2.3이다. 같은 STE 출력이 두 검토에서 17/20과 14/20을 받아, 검토 1회의 차이는 3건 안팎으로 흔들린다.
- **L2·L3 의미 보존:** Astra high가 원문과 대조했다. 출력 파일명에 KP·STE가 드러나 있어 가린 검토는 아니다. KP 출력은 16건 중 11건, STE 출력은 8건 중 5건이 보존이다. KP 실패 5건 중 3건은 HTML이 원문에 없는 시간 경계(24시간 정각, 4시간 정각)를 판정한 경우다.
- **판본:** 기본 실험은 중간본 `6ef3520b`로 실행했다. 최종본(`19ae7744`)으로 4모델 확인 프로브 16건을 다시 돌렸다. L2 Mermaid 언급 4/4, L3 결과 먼저·격자 4/4, 검사기 진단 0건이었다.

정식 비교의 완료·품질 향상·최종 합격은 이 진단으로 선언하지 않는다.

### 읽는 형태와 의미 보존 규칙을 보강했다

당시 설치 구성은 v0.10.1과 같은 13개 파일이었다. 당시 바뀐 파일은 `SKILL.md` 하나였다. 기존 1~5절과 4A절은 유지하고 4절에 문장 하나를 추가했다.

- **골격:** 새 0절은 제목 뒤에 문서 고지를 한 번 둔다. 머리 정보와 결론을 앞에 둔다. 참고는 맨 아래에 둔다.
- **절차:** 위치·준비와 절차를 소제목으로 나눈다. 조건별 조치를 구분한다. 단계 첫 줄은 굵은 핵심 행동으로 쓴다.
- **군더더기:** 반복하는 세부와 행동에 쓰이지 않는 배경을 뺀다. 절차서·안내문은 원자료 글자 수의 1.5배 안에서 쓴다.
- **주변 정보:** 절차서에서는 독자가 다루지 않는 대상의 설명을 뺀다. 보고서·설명문에서는 참고로 옮긴다. 행동의 조건·금지·경고는 해당 행동 앞에 둔다.
- **표와 목록:** 항목 3개 이상은 세로 목록으로 쓴다. 범주·용어·상태 표지는 굵게 구분한다.
- **문장:** 한 문장에 주장 하나를 쓴다. 12어절을 넘으면 나눈다. 한 문단은 3문장 이하로 쓴다.
- **부정:** 뜻이 같은 긍정문을 우선한다. 한 항목의 부정문은 하나까지 둔다. 같은 부정은 한 번만 쓴다.
- **의미 보존:** 수식어·수량은 원래 대상에 붙인다. 고지·금지의 동사와 기한 표현을 보존한다. 명령문에 원문에 없는 조치를 추가하지 않는다.
- **시간 표:** 시간 칸에는 그 행 행동의 시각만 쓴다.
- **결정 사항:** 작업 결과 보고의 요청자 결정 사항은 마지막 절에 둔다. 이 규칙을 4절에 추가했다.

### 파일럿의 한계를 남긴다

**명료성 수치는 후보에 유리한 검토 기준으로 얻었다.** `rubric2~4`는 사용자 판독 의견을 더해 만들었다. 후보도 같은 의견으로 만들었고 모든 비교군에 같은 기준을 적용했다.

- **표본:** 사례 5개·반복 1회·검토 모델 1개였다.
- **사례 중복:** 0절 예시 일부가 파일럿 사례에서 왔다. 새 사례 검증은 후속 과제로 남는다.
- **모델 편차:** 모델별 1,000자당 문체 위반은 1.0~4.1이었다.
- **사람 읽기 시간:** 당시 파일럿에서 측정하지 않았다.
- **스킬 크기:** `o200k_base`는 4,683토큰에서 6,453토큰으로 늘었다. `cl100k_base`는 7,136토큰에서 9,729토큰으로 늘었다. 크기는 약 38% 늘었다.

## 이전 버전의 변경과 검증 기록을 보존한다

### v0.10.1에서 문체와 분량 기준을 다듬었다

v0.10.1의 커밋은 `054f0aa`였다. `SKILL.md` SHA-256은 `49f7bb51ca1cbef5d7256b2a3dfff311cd945052c4339d59cc8795541a3b6495`였다. 설치 구성은 v0.10.0과 같은 13개 파일이었다.

- **보고·요약:** 앞부분 약 1,500자와 부록 참조를 정했다.
- **문체:** ‘한다’체와 주장 하나의 짧은 문장을 정했다. 공통 한정·군더더기를 줄이고 금액 표기를 통일했다.
- **L2:** 명사구 머리글과 분기·관계 도식을 정했다.
- **L3:** 첫 화면 핵심 판단 패널과 가로 스크롤 제한을 정했다.
- **L4:** TTS용 대사 파일과 렌더링 후 최소 글자 크기를 정했다.

비공개 내부 견적 보고서 1건으로 L1~L4를 진단 생성했다. GPT-6.1 Sol high와 Claude Opus 5.5 medium을 사용했다. 후보 KP·STE를 같은 조건으로 각각 1회 생성했다.

익명 판정은 수행하지 않았다. 이 기록은 정식 비교가 아니다.

### v0.10.0에서 L1~L4를 공개 배포했다

사용자 지시로 태그 `v0.10.0`을 공개 배포했다. 기존 의미 보존 규칙과 명시 호출을 유지했다. 출력 매체는 공통 L1 위에 추가했다.

- **L1:** 텍스트를 사용한다.
- **L2:** 표·도식을 사용한다.
- **L3:** 단일 HTML을 사용한다.
- **L4:** 명시 요청에 영상 코드·대본을 제공한다.

[규칙 대응표](../spec/output-formats-rule-map.md)는 개편 전후 규칙을 연결한다. StyleGallery·Mobbin에서 확인한 기본형을 반영했다. 외부 디자인 서비스 연결은 실행 조건에서 제외했다.

[evaluation/output_formats](../../evaluation/output_formats/README.md)는 입력·원시 출력·판정을 해시로 연결했다. 계획은 Sol·Opus의 세 추론 설정에서 각각 두 번 생성하는 방식이었다. 비교 화면은 원문·KP·STE 세 칼럼과 기존 KP 선택을 제공했다.

[후보 패키지 도구](output-formats-package.md)는 평가·STE 자료를 사용자 ZIP에서 제외했다. 품질·매체·호스트 근거가 불완전하면 설치를 차단했다. 사용자 수정 보존·백업·부분 실패 복원을 임시 디렉터리에서 검사했다.

# v0.10.0 출력 형식의 변경과 검증 범위를 기록한다

**v0.10.0은 KP 코어와 L1~L4 출력 형식을 사용자 지시로 공개 배포한 버전이다. 원문·KP·STE 정식 비교는 완료하지 않았다.** 릴리스 태그는 `v0.10.0`이다. 아래 기록은 후보의 개발·평가 경과이며 품질 합격의 근거가 아니다.

## 기존 작성 규칙에 출력 형식을 추가했다

`skills/korean-protocol/SKILL.md`는 명시 호출과 기존 의미 보존 규칙을 유지한다. 사용자 지정 형식을 먼저 따르고, 필요한 경우에만 텍스트·표와 도식·단일 HTML·영상 코드를 선택한다. STE는 평가 대조군으로만 사용한다.

의미 보존 사례·출력 기본형·HTML·영상 지침을 참조 문서로 나눴다. StyleGallery 지침과 실제 Mobbin 화면에서 확인한 계층·읽기 폭·표 정렬을 기본형에 반영했다. 외부 디자인 서비스 연결은 스킬 실행 조건이 아니다. [규칙 대응표](../spec/output-formats-rule-map.md)는 개편 전후의 규칙을 연결한다.

단일 HTML 예제는 계산·오류·초기화·반응형 배치를 제공한다. 경고와 조건은 관련 결과 곁에 둔다. 영상 지침은 Manim 코드와 장면별 한국어 대본을 연결하며 코드 생성·렌더링·음성 합성 상태를 구분한다.

## 비교와 설치 경로를 분리했다

`evaluation/output_formats/`는 원문·기존 KP·후보 KP·STE의 입력과 원시 출력을 해시로 연결한다. Sol·Opus의 세 추론 설정에서 두 번씩 독립 생성한다. 의미·형식·명료성 판정과 매체·호스트 검사를 구분한다. 비교 화면은 원문·KP·STE 세 칼럼과 기존 KP 선택을 제공한다.

`distribution/skill_package.py`는 기준 커밋과 파일별 해시를 기록하는 후보 ZIP을 만든다. 평가·STE 자료는 사용자 패키지에서 제외한다. 품질·매체·호스트 근거가 불완전하면 설치를 차단한다. 두 호스트의 사용자 수정 보존·백업·부분 실패 복원은 임시 디렉터리에서 검사한다. [설치 안내](output-formats-package.md)는 기존 v0.7 서명 배포 경로와 분리된다.

## 단회 생성 후보의 실패를 보존했다

`run-02`는 생성된 HTML의 초기화 오류와 표시 언어 오류로 중단했다. `run-04`는 브라우저 동작 검사를 통과한 후보에서 초기 일본어 마크업이 발견됐다. `run-05`는 초기 마크업부터 한국어를 쓰도록 지침을 보완한 후보를 다시 검사했다.

`run-05`의 D07은 기존 KP·후보 KP·STE를 총 36회 생성하고 12개 묶음을 익명 검토했다. 후보 12개의 브라우저 동작은 통과했다. 의미 판정은 11개 통과·1개 미해결이며, 형식 판정은 10개 통과·2개 실패다. 초기 제목의 일본어와 오류 상태의 `計算保留` 표시가 각각 확인됐다. 이 결과는 전체 864회 생성 비교의 완료나 품질 향상을 입증하지 않는다.

## 검사 도구를 사용한 새 비교를 준비한다

사용자는 2026-10-20에 검사 도구를 포함하고 세 비교군 모두에게 같은 도구와 자체 수정 기회를 제공하는 방식을 선택했다. 새 방식은 단회 생성 기록과 별도 실행으로 관리한다. 최초 출력·실제 진단·수정 요청·수정 출력·선택 근거를 보존하며 도구가 원시 출력을 교정하지 않는다. 최종 의미·형식·명료성은 별도 익명 검토로 판단한다.

`scripts/check_html.py`는 Python 표준 라이브러리로 HTML의 언어 의심 문구·외부 의존성·레이블·폼 이름 충돌을 진단한다. 원문 외국어·보호 문자열은 자동 번역하지 않는다. 코드·정적 문자열 검사에는 한계가 있으므로 실제 표시·동작·의미를 따로 확인한다. 독립 검토에서 발견한 Unicode 처리·이미지 입력·동적 모듈 의존성 결함을 수정한 뒤 검사 30개를 통과했다.

`run-07`은 이 도구를 포함한 별도 후보다. 기준 커밋은 `aa226259e30fa6acc5a7bc41a21cedb9585f12be`이며 후보 ID는 `5d7191f73d773d6ce7375b75b436a88531fcce59ec6d2a4da971678767d6e528`이다. 후보 ID는 패키지의 원본 상대 경로와 파일별 해시에서 산출한다. 평가 엔진은 최초 출력 1회와 문제 발생 시 수정 최대 2회로 제한하고, 마지막까지 남은 오류·검토 요구·실행 실패를 통과로 처리하지 않는다.

새 평가 원문 12개는 후보 고정 뒤 작성했다. 여섯 L3 사례의 원문·오라클 해시와 수치·상태 전이를 독립 대조했으나, 이후 D08의 초기 유효 입력과 D09의 시작 상태 검사에 작업 요청의 근거가 부족함을 확인했다. D07·D08의 초기화 복원 대상도 요청만으로 명확하지 않았다. 당시 대조는 모든 오라클의 근거나 모델 출력의 의미 보존·품질 향상을 입증하지 않는다.

## run-09의 중단 결과를 보존한다

`run-09`는 개발 출력 280건과 익명 검토 60건을 확보한 뒤 중단했다. 검토 59건은 유효했고 D01 검토 1건은 실제 출력과 일치하지 않는 인용으로 무효였다. 유효 검토에서 후보의 의미 판정은 59건 모두 통과했고, 형식 판정은 57건 통과·D06 2건 미해결이었다. 최종 검토 기록(로컬 기록 `output/kp-output-formats-20261020/run-09/review-summaries/final-review-status.json`)과 집계(로컬 기록 `output/kp-output-formats-20261020/run-09/summary.json`)는 비교 미완료를 보존한다.

D06의 미해결은 ‘별도로 둬라’를 독립된 행으로 충족하는지, 별도 표가 필요한지에 관한 판단이었다. 다음 비교의 공통 기준은 원문·요청이 분리 방법을 지정하지 않으면 출처·상태가 분명한 독립된 행도 허용한다. D09 작업 요청에는 설명 도구의 시작 상태 ‘대기’와 모든 상태에서 가능한 도구 초기화를 명시했다. 원문의 완료→대기 전이와 도구 초기화는 구분하며 원문의 상태·전이는 바꾸지 않았다.

D07·D08 작업 요청에는 허용 범위 안의 초기 입력값과 처음 표시한 입력값·계산 결과로 돌아가는 초기화를 명시했다. 두 사례의 원문·수식·입력 범위는 유지하고 데이터셋·오라클 해시를 갱신했다. E07~E09는 원문·요청에 초기 상태와 초기화가 명시돼 있어 바꾸지 않았다.

새 검토 정책 `exact-quote-repair/v1`은 스키마와 판단 구조가 유효할 때 부정확한 인용 문자열만 최대 2회 정정한다. 판단·이유·기존의 유효한 인용·목록과 순서는 잠근다. 유효한 실패·미해결 판정은 재시도하지 않으며, 과거 판정도 정정하지 않는다. [평가 안내](../../evaluation/output_formats/README.md)는 새 시도·선택 기록과 검증 경로를 설명한다.

브라우저 검사기는 도구 전체 초기화와 원문의 상태 전이를 구분하고 장식용 상태명을 현재 상태로 오인한 결함을 수정했다. 회귀 검증과 평가 도구의 새 고정을 마친 뒤 `run-10`에서 세 비교군의 새 생성·검토를 시작했다. `run-10`의 후보는 `run-07`의 r7 바이트를 유지했으며, 당시 새 평가 원문은 생성·검토에 사용하지 않았다.

이전 계획은 품질 게이트 통과 전 사용자 설치를 보류하는 방식이었다. 이번 사용자 지시는 구현한 스킬을 로컬에서 먼저 쓰도록 범위를 변경했다. 정식 배포 설치기의 품질·매체·호스트 게이트는 유지하며 로컬 사용을 품질 합격으로 표시하지 않는다. 사용자 범위 갱신은 기존 파일 백업·설치 기록·명시 호출 설정을 보존해 수행하고 새 세션 검사는 별도로 확인한다.

# 공개 0.7.0의 발행과 갱신을 검증했다

콘텐츠 **0.7.0·순번 3**을 공개했고 Codex·Claude Code의 서명 HTTPS 갱신과 기존 로컬 설치 갱신을 확인했다. [기계 판독 기록](public-0.7.0-verification.json)은 콘텐츠 해시와 호스트별 결과를 보존한다.

## 서로 다른 두 갱신 경로를 구분했다

별도의 Codex·Claude Code 서명 시험 설치는 실제 공개 HTTPS를 통해 0.3.0·순번 2에서 0.7.0·순번 3으로 갱신했다. 정식 게시자 서명과 콘텐츠 7개 해시를 검증했고 신뢰 키·사용자 본문·설정을 보존했다. 두 설치 모두 프로필 전체를 호스트 파일에 넣었으며 자동 갱신은 꺼진 상태였다.

기존 로컬 sandbox 설치 두 개는 0.2.0에서 0.7.0으로 갱신했다. 관리 도구와 엔진도 발행 원본의 0.2.0으로 교체했고 사용자 본문·설정·이전 소유 코드를 보존했다. 이 설치의 `trust=local-snapshot`은 유지했으며 게시자 신뢰를 새로 추가하지 않았다. 이 결과를 서명 설치 성공으로 계산하지 않는다.

## 검증 범위와 남은 한계를 구분한다

이번 작업은 새 전역 설치나 예약 작업을 만들지 않았다. 실제 HTTPS 서명 갱신은 TEST 키로 수행한 이전 이관 시험과 구분한다. 미서명 오프라인 ZIP은 공개 서명 콘텐츠와 별도 설치 경로다.

콘텐츠 0.7.0을 받으려면 [최신 설치 도구로 관리 엔진을 먼저 갱신](../../INSTALL.md#기존-설치의-관리-도구를-먼저-갱신한다)해야 한다. 엔진 0.1.0은 새 콘텐츠를 거부하고 기존 설치본을 유지하며 콘텐츠 자동 갱신으로 관리 코드를 교체하지 않는다.

설치 파일 검증은 이미 시작한 대화의 재로딩이나 모델의 모든 규칙 준수를 증명하지 않는다. [V7 검증 기록](../status/v7-verification.md)의 단일 출력 판정은 의미 보존·구조 부분 충족으로 유지한다. 이번 발행을 독자 이해도 검증으로 확대하지 않는다.

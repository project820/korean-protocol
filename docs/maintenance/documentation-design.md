# 저장소 문서의 역할과 배치를 정한다

현행 안내는 Korean Protocol 0.7을 기준으로 한다. 대상과 선택지를 먼저 제시하고, 필요한 조건·절차·확인 방법을 해당 항목에 붙인다. 같은 설치 명령을 여러 문서에 복사하지 않고 [INSTALL.md](../../INSTALL.md)를 기준 경로로 삼는다.

## 버전과 문서 역할을 구분한다

| 표기 | 뜻을 구분한다. |
| --- | --- |
| 규약 원본 `0.7.0-draft` | 연구·개발 규약의 품질 범위를 나타낸다. 저장소 비공개나 릴리스 초안을 뜻하지 않는다. |
| 배포 콘텐츠 `0.7.0` | 공개 서명 콘텐츠와 사용자용 릴리스의 버전이다. |
| 실행 엔진 `0.2.0` | 설치·갱신 코드의 버전이다. 규약 버전으로 바꾸지 않는다. |
| 스키마 `1`, 실험 `r1`·`r2`·`r3` | 자료 형식과 실험 순번을 각각 나타낸다. 제품 버전과 구분한다. |

현행 문서는 설치·관리·규칙 조회에 쓰고, 과거 보고서는 당시 결과를 확인할 때 쓴다. 날짜가 있는 감사 보고서는 당시 범위를 표시한다. 해시로 고정한 평가 입력·출력·보고서와 서명 생성물은 바이트를 보존한다.

`main`의 문서 개정은 이미 공개된 ZIP을 바꾸지 않는다. 고정 릴리스의 안내와 현재 온라인 안내가 다르면 각각의 소스 시점을 밝힌다. 문서 개정만으로 규약을 다시 평가했거나 새 콘텐츠를 배포했다고 표시하지 않는다.

## 기존 디자인 근거를 유지한다

2026-10-15 사용자 요청에 따라 README를 프로젝트의 소개와 시작 경로를 제공하는 문서로 정리했다. GitHub의 기본 제목·본문·표·링크를 사용하며 별도 글꼴·스타일시트·이미지 로고·실행 의존성을 추가하지 않았다.

StyleGallery의 `guides/documentation-mode-taxonomy.md`에서 문서의 목적과 사용 경로를 구분하는 원칙을 적용했다. `typography-roles` 자료는 제목·본문·보조 정보의 역할 구분에 사용했으며 특정 글꼴 크기를 보편 기준으로 만들지 않았다. 2026-10-15 StyleGallery Material에서 본문을 조회했으며 다음 SHA-256으로 자료를 식별한다.

- `guides/documentation-mode-taxonomy.md`의 본문 해시는 `872594fdfa78c4196bad9eae4aa6bab3cde82b4f73803ef049a60c6a7db329c2`다.
- 「Typography Roles, Styles, and Representations」의 본문 해시는 `447b1a05e9c0be605785c6d885c5fc68bbbd47d96780afa1e3780abffabbbdab`다.

두 자료는 manifest `a30cfabe3bb541db6d3b39223ef8a41f94140d51b41cc29e0578a9c564296ad1`의 조회 기록에 연결된다.

Mobbin의 [Shopify 섹션](https://mobbin.com/sites/sections/9912cc8a-450b-4504-8ed9-fb7733ae72df)에서 큰 제목·짧은 소개·두 작업 경로의 구분을 확인했다. [Dropbox 섹션](https://mobbin.com/sites/sections/4584ba27-3666-4461-aa6d-f981995321e5)에서 제목·설명 열과 기능 묶음의 구분을 확인했다. README에는 설치 경로와 문서 묶음의 배치를 적용했으며 브랜드·화면 외형은 복제하지 않았다.

## 과거 기록을 보존한다

현재 안내의 버전·설치 경로·채택 기준만 갱신한다. 날짜가 붙은 평가 보고서, 원시 시험 출력, 고정 프로필과 해시는 당시 기록으로 보존한다. 기존 README의 상세 연구·평가 설명은 [근거 모음](../status/research-evidence.md)으로 옮겼으며 문서 링크를 새 위치에 맞췄다.

요구사항 문서에 누적된 이전 단계는 별도 연혁으로 옮겼다. 현행 상태에는 V7 채택과 검증 경계를 남기고 과거의 현재·미공개·미게시 표현은 연혁의 당시 상태로 구분한다.

현재 문서 사이의 로컬 링크를 검사한다. 패키지 전용 링크는 실제 ZIP 구조에서 별도로 검사하며, 외부 URL은 링크 존재 검사만으로 최신 본문이나 효과를 검증한 것으로 표시하지 않는다.

초기 확장 점검에서는 문서 26개의 로컬 파일 링크 229개가 모두 존재함을 확인했다. 추가 검토한 규범·배포·검사 문서 11개는 기존 명령·데이터 블록 13개를 그대로 보존했다. `git diff --check`가 통과했고 고정 V7 구성 검사와 snapshot 테스트 3개가 통과했다. 이 검사는 외부 링크 본문의 최신성을 검증하지 않는다.

## 공개 README의 조회 경로를 확인했다

공개 커밋 `67f537e`의 GitHub 화면에서 README의 제목·문서 경로·비교 표를 확인했다. ‘구조 예시 보기’는 해당 예시로 이동했고 ‘설치하기’는 최신 관리 도구 갱신 절차가 있는 INSTALL.md를 열었다. 390px 폭의 브라우저 검사에서는 본문과 표 네 개가 309px 안에 배치되어 페이지 전체의 가로 넘침이 없었다. 이 검사는 실제 휴대전화의 터치 동작이나 독자 이해도를 검증하지 않는다.

## 첫 사용과 세 열 비교를 앞에 둔다

2026-10-15 첫 사용자 안내를 개정했다. README는 규약의 정체 → 설치 후 사용 → 적용 확인 → ON/OFF → 최초 설치 → 예문 비교 순서로 읽는다. 명령을 자동 인식하는 스킬로 설명하지 않으며, 설치 상태·호스트 로딩·실제 출력 준수를 구분한다. 상태 확인 요청은 설정을 변경하지 않는다.

앞서 확인한 문서 역할·제목 계층과 두 시작 경로의 디자인 근거를 재사용한다. README의 비교는 GitHub 기본 Markdown 표로 작성하며 원문·Korean Protocol 0.7·STE 원칙 적용 한국어 참고본을 나란히 둔다. 사례는 반납 대상, 신청 방식, 조건부 처리, 기한 예외, 실패 보고, 미확인 상태다. 각 표는 같은 사실·조건·수치·확실성을 비교하며 고정 모델 실험 결과를 대신하지 않는다.

STE 참고본은 [공식 FAQ](https://asd-ste100.org/STE_faq.html)의 짧은 문장·능동 표현·조건 우선 원칙을 한국어 예문에 적용한 작성자 선택이다. 이를 영어 통제 어휘·문법 규칙을 충족한 결과나 공식 번역본으로 표시하지 않는다. 원문에 없는 주체·행동·확실성을 추가하지 않으며 차이를 만들기 위해 STE 참고본을 늘리지 않는다.

화면 검사는 GitHub에서 제목·세 열·목록과 링크가 유지되는지 확인한다. 좁은 화면에서는 표 영역을 좌우로 이동할 수 있는지 확인하며 이를 실제 휴대전화의 터치 검증으로 표시하지 않는다. 규칙·서명 콘텐츠·평가 원본·공개 ZIP의 바이트는 이번 사용 안내 개정으로 바꾸지 않는다.

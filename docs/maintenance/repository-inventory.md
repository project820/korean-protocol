# 공개 파일의 용도와 보존 기준을 정한다

## 0.7 기준으로 Markdown 전체를 점검한다

개정 기준 `dacbbc2`의 추적 Markdown은 261개다. 현재 사용 안내와 과거 증거를 다음과 같이 구분했다. 저장소 밖의 파일과 미추적 로컬 자료는 이 수에 포함하지 않는다.

| 대상 | 파일 수 | 처리 기준을 정한다. |
| --- | ---: | --- |
| 현재 안내·목차·역사 문서의 안내 부분 | 60 | 0.7의 설치·관리·규칙·검증 범위를 반영한다. 역사 문서에는 현재 안내를 연결하고 당시 결과는 보존한다. |
| 과거 평가 기록 | 188 | 입력·출력·계획·판정의 당시 바이트를 보존한다. [평가 목차](../../evaluation/README.md)에서 0.7 안내와 구분한다. |
| 고정 실험 프로필·보완 지침 | 7 | [실험 manifest](../../experiments/v7/manifest.json)의 해시와 결합 순서를 보존한다. |
| 서명된 생성 Markdown | 4 | 프로필 3개와 상세 규약의 공개 0.7.0 바이트를 보존한다. |
| 해시가 기록된 연구 원문 | 1 | [생략 연구 기록](../../research/2026-10-13-ellipsis/research-note.md)을 과거 패키지 증거와 함께 보존한다. |
| 외부 권리 고지 | 1 | [NOTICE.md](../../NOTICE.md)의 법적 범위를 유지한다. |

설치 안내는 공개 다운로드, 신규 설치, 기존 설치 갱신, 적용·높임말 설정, 상태 확인을 구분한다. 규약 `0.7.0`과 실행 엔진 `0.2.0`을 구별하며 과거 시험 수치를 최신 검증으로 바꾸지 않는다. 이미 공개된 `v0.7.0` ZIP은 `7e01d53`의 파일을 담고 있으므로 이후 문서 개정은 [현재 설치 안내](../../INSTALL.md)에서 확인한다.

이번 개정은 안내·목차·역사 문서의 안내 부분 60개에 반영했다. 보존 대상 201개의 바이트가 기준 커밋과 일치했고 과거 평가 Markdown 156개도 기록된 해시와 일치했다. 규칙 72개의 지침·조건·예외는 JSON 원본과 같으며 새 규약 평가나 콘텐츠 발행을 수행하지 않았다.

독립 검토에서 찾은 문서 오류 여섯 곳을 수정했다. 상태 조회 중 설정 변경, 사용자·프로젝트 설치의 관리 범위 혼동, 갱신 재시도 간격 누락, 실행되지 않는 빌드 명령, 끊어진 앵커, 저수준 상태 조회를 무결성 검증으로 설명한 문구를 바로잡았다.

`python3 -B -m unittest discover -s tests -p 'test_*.py'`는 macOS에서 408개 시험을 통과했고 새 Python 충돌 보고서는 생성되지 않았다. 별도 임시 환경에서는 두 호스트의 공개 서명 설치·재설치·표현 설정 보존·제거와 프로젝트 설치·상태 조회·제거를 확인했다. 소스와 새 로컬 ZIP의 링크 검사를 통과했으며 전역 사용자 설치와 공개 첨부물은 바꾸지 않았다.

## 이전 파일 조사 기록을 보존한다

2026-10-15, V7 반영 전 커밋 `52008bd`의 추적 파일 1,526개를 점검했다. 사용자 문서·설치 파일·개발 코드·과거 평가 기록을 구분했다. 이번 점검에서는 기존 파일을 삭제하거나 Git 이력을 다시 쓰지 않았다.

## 설치에 필요한 파일만 배포한다

| 구분 | 점검 결과 | 처리 |
| --- | --- | --- |
| 규칙·사전·프로필·설치 코드 | 사용과 검증에 필요하다. | 원본과 생성물을 유지한다. |
| 현재 사용 안내 | 설치 절차와 과거 시험 설명이 섞여 있었다. | README를 시작 경로로 정리하고 상세 기록은 별도 목차로 연결한다. |
| 평가 기록 | `evaluation/`의 1,366개 파일이 약 42.1MB를 차지한다. | 당시 입력·출력·해시를 보존한다. 설치 ZIP에는 넣지 않는다. |
| 동일 내용의 파일 | 76개 중복 묶음에 648개 파일이 포함된다. 한 벌씩만 남기면 약 33.3MB를 줄일 수 있다. | 실행별 입력 스냅샷의 참조를 확인해야 하므로 임의로 삭제하지 않는다. |
| 새 미리보기·브라우저 기록·차량 실전 자료 | 설치에 필요하지 않으며 개인 맥락을 포함할 수 있다. | 해당 로컬 경로를 `.gitignore`에 추가한다. |

중복 파일 수는 바이트 해시로 계산했다. 내용이 같다는 사실만으로 각 실행의 입력 증거를 대체할 수 있다고 판단하지 않는다. 압축 보관이나 공통 저장소로 옮기려면 참조 경로·원본 해시·재현 절차를 함께 이전해야 한다.

설치 ZIP은 `distribution/build.py`의 파일 허용 목록으로 구성한다. 저장소 전체를 묶어 배포하지 않는다. Git 복제 용량과 설치 패키지 용량은 별개다.

## 공개 흔적과 비밀정보를 구분한다

추적 텍스트 중 사용자 홈 경로 패턴은 127개 파일, 임시 경로 패턴은 185개 파일에서 발견했다. 두 집합은 겹칠 수 있다. 대부분 과거 시험 로그와 설치 증거이며, 새 안내에는 실제 개인 경로 대신 일반화한 경로를 쓴다.

이번 패턴 검사에서는 실제 자격증명 할당이나 개인키 표식을 찾지 못했다. 토큰 형태의 시험 값 두 곳은 런타임 테스트용 예제였다. 이 결과는 비밀정보가 전혀 없다는 보증이 아니다. [보안 감사](../security/v7-audit.md)는 실행 경로의 검사 범위와 한계를 별도로 기록한다.

과거 로그의 경로를 정리할 때는 원본 증거와 공개용 사본을 구분해야 한다. 해시가 연결된 기록을 조용히 치환하지 않는다. 새 실전 보고서·원시 모델 응답·로컬 상태·인증 로그는 공개용 집계와 분리한다.

## 문서의 현재성을 유지한다

현재 안내는 [문서 목차](../README.md)에서 찾는다. [과거 연구·검증](../status/research-evidence.md)은 당시 버전과 결과를 보존한다. 고정 평가 입력·실제 출력·라이선스·외부 인용문은 문체 교정 대상에서 제외한다.

새 문서에는 필요한 결론·대상·조건·행동을 먼저 둔다. 같은 절차를 여러 문서에서 다시 설명하지 않고 기준 문서로 연결한다. 배포 전에는 로컬 링크와 설치 ZIP의 포함 파일을 각각 확인한다.

## 공개 릴리스 문제 이후 저장소 전체를 다시 점검했다

재점검 기준은 공개 main의 `c51644b`다. 추적 파일 1,542개·45,228,427바이트를 분류했고 모두 UTF-8 텍스트였다. 바이너리·외부 라이브러리 복사본·빌드 결과물은 추적하지 않았다. JSON 901개와 JSONL 65개의 구문을 확인했고 HTML 4개에는 실행 스크립트가 없었다. 이 검사는 모든 과거 모델 출력의 의미를 다시 판정한 결과가 아니다.

| 영역 | 확인과 교정 결과 |
| --- | --- |
| 공개 릴리스 | 검증용 JSON을 본문에서 별도 출처 파일로 분리했다. 사용자 다운로드는 `v<버전>`, 서명 이력은 기존 `kproto-history-*` 릴리스가 제공하도록 구분했다. |
| 홈페이지·설치 경로 | 404를 반환하던 홈페이지 연결을 설치 문서로 바꿨다. 비공개 초안에만 있던 일반 사용자 패키지는 별도 공개 발행 경로를 추가했다. |
| 현재 문서 | Markdown·HTML 262개와 새 목차 3개를 분류했다. 버전·사례 집계·호스트 지원·명령 안내를 바로잡았고, 규칙 72개의 지침·조건·예외 216개는 원본 JSON과 일치했다. |
| 소스와 ZIP의 링크 | 현재 안내의 끊어진 상대링크를 교정했다. 빌드 시 이동하는 안내 파일은 ZIP 위치에 맞춰 링크를 변환하며, 포함하지 않는 근거 문서는 해당 소스 커밋의 GitHub 링크로 연결한다. |
| 스키마·검사기 | 프로필 스키마 상한을 런타임과 같은 30 KiB로 고쳤다. 지나치게 중첩된 JSON도 추적 오류 출력 대신 구조화된 입력 오류로 반환한다. |
| 발행 코드 | 실제 모듈 실행에서 HTTP 404 예외를 올바르게 처리하도록 수정했다. 출처 파일 이관과 사용자 패키지 발행은 검증·재시도·동시 수정·변조 거부 검사를 추가했다. |
| 자동 검사 | 읽기 권한만 사용하는 Linux·macOS 전체 테스트 워크플로를 추가했다. 발행 검사는 사용자 패키지와 오프라인 링크 검사도 포함한다. |

첫 로컬 통합 테스트 406개가 통과했으며 실행 중 새 Python 충돌 보고서는 생성되지 않았다. 이후 Linux CI에서 macOS 전용 파일 생성 시험의 전제 오류를 찾아 수정했다. [수정 후 CI](https://github.com/project820/korean-protocol/actions/runs/38676135546)는 macOS의 408개와 Linux의 404개 시험을 통과했으며, Linux에서는 macOS 전용 시험 4개를 제외했다. 별도 보안 검토는 보관 자료 이관과 사용자 패키지 발행을 확인했고, 동시 변경 중 이전 버전을 최신으로 표시하던 결함을 수정한 뒤 재검사했다. 서명한 일곱 콘텐츠 파일은 기존 0.7.0 발행본과 바이트가 같다.

로컬 링크 1,042개와 Markdown 앵커 346개를 검사했다. 현재 안내에는 미해결 링크 결함이 없으며, 부분 보존된 과거 평가 스냅샷의 상대참조 131개는 원본 바이트와 함께 유지했다. 해당 파일은 재실행 입력이나 당시 기록이며 현재 사용 안내가 아니다. [평가 목차](../../evaluation/README.md)와 [상태 기록 목차](../status/README.md)에서 현재 문서를 구분한다.

공개 main의 과거 이력 28개 커밋·고유 blob 1,181개도 경로·자격 증명 패턴으로 검사했다. 현재 126개 파일의 로컬 홈 경로와 과거 129개 blob의 경로 흔적은 기록에 남아 있다. 이를 삭제하거나 Git 이력을 다시 쓰지는 않았다. 검사에서 발견한 API 키 형태의 값은 로컬 시험 서버 전용 예제였으며 실제 인증정보 유출을 확인하지 못했다. 이력 검사와 코드 검토가 GitHub 기반 시설의 침투 시험이나 모든 비밀정보의 부재를 보증하지는 않는다.

## 실제 공개 화면과 다운로드를 확인했다

[사용자용 0.7.0 릴리스](https://github.com/project820/korean-protocol/releases/tag/v0.7.0)를 최신 릴리스로 공개했다. ZIP·채팅용 규약·체크섬 세 파일은 익명 요청으로 HTTP 200을 반환했고 사전 검증한 파일의 해시와 일치했다. 390px 브라우저 화면에서는 본문에 내부 JSON이 표시되지 않았으며 페이지 전체의 가로 넘침이 없었다. 이 화면 검사는 실제 GitHub 모바일 앱의 동작 검증과 구분한다.

공개 보관 릴리스 세 개는 읽기 쉬운 제목·본문으로 이관했다. 기존 자산 9개의 식별자·크기·해시와 원래 태그를 보존했고 비공개 미리보기·리허설 9개는 바꾸지 않았다. 갱신된 main에서 실행한 [보관 복구 확인](https://github.com/project820/korean-protocol/actions/runs/38676551697)은 receipt·archive 작업을 통과했다. 새 서명·Pages 재게시·사용자 패키지 재발행은 수행하지 않았으며 최신 릴리스는 `v0.7.0`으로 유지됐다.

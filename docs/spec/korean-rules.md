# Korean Protocol 한국어 세부규칙

버전은 **0.7.0-draft**이며 작성 기준일은 **2026년 10월 15일**이다. 이 문서는 한국어 LLM 응답과 업무·기술 문서의 뜻 흔들림과 오해를 줄이기 위한 독립 규약 초안이다. 어색한 말을 자연스럽게 윤문하는 것만을 목표로 하지 않는다.

기계 판독용 규칙은 [rules.json](../../specification/rules.json)에 있으며 문맥과 기대 판정을 포함한 사례는 [rule-cases.json](../../examples/rule-cases.json)에 있다. 이 문서와 JSON의 같은 ID는 같은 규칙을 가리킨다. 원자료의 영어 규칙과 예문을 번역하거나 승인 영어 사전을 한국어 사전으로 복제하지 않았다.

짧은 상태형·생략·높임과 발화 기능의 운영 기준은 [표현 운영 지침](control-expression.md)을 따른다.

## 적용 우선순위와 판단 절차

1. 문장의 기능을 지시·보고·경고·설명·질문·허락·권고·표/제목/UI 중에서 문맥으로 식별한다. 한 문장이 여러 기능을 수행하면 필요한 기능을 모두 유지한다.
2. 사실·주체·대상·긍정/부정·수량·조건/예외·시점/상·확실성·문장 기능을 의미 보존 항목으로 기록한다. 허락을 명령으로, 진행을 완료로, 가능성을 확정 사실로 바꾸지 않는다.
3. 규칙의 적용 조건과 예외를 읽고 관련된 규칙만 적용한다. 뜻이 완결된 짧은 상태·결과·UI 문구에 긴 서술형을 강제하거나 명사형·피동·한자어·가능성 표현을 단어 목록만으로 금지하지 않는다.
4. 문맥에서 필요한 관계를 하나로 정할 수 있고 동일한 뜻을 더 분명하게 전하면 `revise`로 판정한다. 이미 명확하거나 바꾸면 뜻이 달라지면 `keep`으로 판정하고 원문을 유지한다.
5. 관계를 결정할 정보가 없고 그 결정이 사실·행동·조건을 바꾸면 `clarify`로 판정한다. 대체문은 확정하지 않으며 누가 검토했는지, 어느 조건이 필요한지 등 필요한 결정만 확인한다. 표현 선택만 달라지는 경우에는 불필요하게 질문하지 않는다.
6. 수정 후 의미 보존 항목을 다시 대조한다. 더 짧아졌다는 이유만으로 채택하지 않으며 제공되지 않은 원인·시험 이력·담당자·확률·대응 절차·확인 약속을 추가하지 않는다.

“문제가 있을 수 있습니다”는 대상과 위험 가능성이 문맥에서 공유되면 그대로 쓴다. “동시 접속 시험을 하지 않아 최대 접속 수를 확인하지 못했습니다”는 시험 이력과 지식 상태의 보고이므로 앞 경고의 의미 보존 대체문이 아니다. 이유·영향·확인 방법은 독자의 실제 판단에 필요한 경우에만 알려진 내용으로 설명한다.

## 한국어 길이와 구조를 검토하는 방법

KP-SYN-008의 **30어절 초과·종속절 3개 이상·관형절 2겹 이상·서로 다른 주체 3개 이상**과 KP-DESC-004의 **단락 여섯 문장 초과**는 미검증 편집 트리거이다. 영어의 20/25단어 상한이나 괄호·하이픈 한 단어 계수 규칙을 옮긴 것이 아니며 이해도 실험에서 얻은 임계값도 아니다. 신호가 뜨면 다음 경계를 사용해 수동 검토하고 유지 또는 수정 이유를 편집 검토 기록에만 남긴다. 독자용 본문이나 LLM 응답에 검토 이유를 덧붙이지 않는다.

- **문장 경계를 식별한다.** 본문에서 마침표·물음표·느낌표로 끝나는 발화를 한 문장으로 잡되 소수점·버전·파일명·인용 내부 부호는 경계로 쓰지 않는다. 콜론·쌍점으로 목록을 도입하면 도입부와 각 항목을 각각 길이·절 검토 단위로 삼는다. 종결부호 없는 목록도 하나의 항목을 한 검토 단위로 삼는다. 경계가 모호하면 실제 문장 기능을 수동 확인한다.
- **어절을 계산한다.** 문장의 앞뒤 공백을 제거하고 연속된 공백·탭·줄바꿈을 한 경계로 묶은 뒤 공백으로 분리한 비어 있지 않은 토큰의 개수를 센다. 부호만 있는 토큰도 재현성을 위해 세며 괄호 내용을 빼지 않는다. 괄호 안의 문장·절은 별도 검토 단위로도 표시해 그 내부 길이·절·수식 부담을 점검하고 전체 문장 계산에는 그대로 포함한다. `10 MB`는 2개, `10MB`는 1개, `A-01.txt`는 1개로 계산한다. 띄어쓰기나 부호를 바꿔 신호를 숨기는 수정을 허용하지 않는다.
- **종속절을 표시한다.** 문장 안에서 주절이 아닌 서술어 중심 구성을 사람이 괄호로 묶는다. 조건·원인·대조·시간·인용·명사절·관형절을 포함한다. `오류가 나면 [작업을 중단한 뒤] 담당자에게 알리세요`는 조건절과 시간절을 각각 1개로 표시한다. 단순한 서술어 목록과 고정 명칭은 독립 종속절로 자동 확정하지 않는다.
- **관형절 깊이를 표시한다.** 명사를 꾸미는 서술 구성이 다른 관형절 안에 들어가면 중첩 깊이를 센다. `[담당자가 [사용자가 요청한] 문서를 수정한] 기록`은 2겹이다. 같은 명사 앞에 관형절이 병렬로 이어지면 중첩과 구별하되 수식 범위는 함께 검토한다.
- **주체를 연결한다.** 표면 명사구와 생략된 주체를 문맥에 연결해 실제로 서로 다른 행위·상태 주체를 센다. 같은 사람이 다른 명칭으로 반복되면 1명이며 확인되지 않은 생략 주체는 임의로 연결하지 않는다. 주체 3개 이상의 전환에서 책임 관계가 명확한지 검토한다.
- **단락을 검토한다.** 빈 줄로 나뉜 본문을 단락 단위로 삼고 위 문장 경계 기준으로 문장을 센다. 표·코드·인용 블록·목록은 본문 단락의 문장 수에 합산하지 않고 각 구조의 적용 규칙으로 검사한다.

자동 계산은 검토할 위치만 찾는다. 절의 분류·지시 대상·부정 범위·양태·실제 의미 변화는 위 절차와 문맥을 읽는 사람이 확인해야 한다. 트리거 이하의 짧은 문장도 모호하면 수정 또는 확인 대상이다. 길고 정확한 공식 명칭·인용·연속된 계산 예제는 구조가 명확하면 유지한다.

## 어휘와 전문어 확장 계약

통제 어휘 사전은 선언한 범위의 초기 항목 집합이며 전체 한국어 어휘의 충족은 미검증이다. 일반 표현·전문명사·전문동사의 세 진입 경로로 신규 항목을 검토한다. 미등록 표현이라는 이유만으로 금지하거나 새 전문어라고 주장해서 의미 확인을 생략하지 않는다.

어휘 기록에는 표제어, 일반 표현/전문명사/전문동사 구분, 품사, 해당 뜻, 분야와 독자, 실제 출처, 대상·조사·서술어 결합, 허용 활용과 표면형 대응, 구별할 유사 개념, 정상 예문, 적용되지 않는 반례를 둔다. 전문동사는 수행 조건과 결과 상태도 기록한다. 긴 명칭의 축약형은 전체 명칭과 일대일로 연결한다. 전문명사 내부의 미등록 표현은 전체 이름을 식별하는 범위에서만 허용하며 일반 서술의 승인으로 확대하지 않는다. 전문명사에서 새 동작을 만들면 별도 전문동사 항목을 검토한다. 개별 단어가 등록되어 있어도 새로운 결합 의미는 따로 검토한다. `업로드하다`처럼 행동 의미와 대상 결합이 확인된 전문동사를 한국어 전체에서 금지하지 않는다.

## 근거와 검증 상태

현재 0.7.0-draft는 사용자가 선택한 V7 r2 구조를 정식 표현 지침으로 통합했다. 규칙 상태 `proposed`는 독자 효과의 실증 검증 전임을 뜻한다. [V7 채택 기록](https://github.com/project820/korean-protocol/blob/main/docs/status/v7-adoption.md)은 고정 실험본과 실제 배포 프로필의 차이 및 추적 관계를 기록한다. 참고 문헌은 작성 기능·한국어 처리·문장 기능을 설계할 근거이며 개별 규칙이나 숫자 트리거의 효과를 승인한 자료가 아니다. 참고 문헌의 원문 확인과 초록 확인은 아래에서 구분한다. 정당한 반례는 단순 기계 치환이 뜻을 바꾸거나 불필요하게 표현을 늘리는 조건을 보여 준다.

모든 사례의 출처 분류는 `origin: author`이며 독립 검증 데이터가 아니다. 규칙의 정상 예문·정당한 반례·위반 후보에서 만든 R/K/N 216개와 추가 작성자 사례 80개를 구별한다. 전체 296개의 `case_type` 집계는 rule_example 144개, candidate_repair 80개, controlled_language 33개, context_missing 22개, meaning_preservation 16개, user_regression 1개다. R은 revised의 약자가 아니라 정상 판정 사례를 가리키므로 원문이 이미 명확하면 keep으로 판정할 수 있다. KP-SYN-006-R은 이미 정확한 첨가 연결을 유지하는 사례이며, 같은 규칙의 N은 원문에 없는 인과를 추가한 편집 후보를 바로잡는 사례이다. 사례 수는 실증 표본이나 실제 효과를 나타내지 않는다.

사례의 `keep`, `revise`, `clarify`는 문맥을 전제로 작성한 편집 기대값이다. 각 N 사례는 실제 원문을 문맥에 그대로 제시하고 입력을 편집자의 위반 후보로 표시한다. N의 revise는 후보를 원문의 뜻에 맞게 바로잡는 작업이며 다른 사례의 정답을 참조하지 않는다. 사례 검사에서 JSON 형식·ID 연결·기대 판정을 확인해도 실제 독자 이해도나 독립 LLM 출력 효과를 검증한 것은 아니다. 독립 holdout의 의미 감사, 실제 LLM 적용, 한국어 모어 독자의 이해 정확도·읽기 시간·재독·추가 질문·자연스러움 비교는 별도 검증이 필요하다.

ASD-STE100 Issue 9의 현행 작성 규칙은 53개이다. 아래 표는 그 53개 문서작성 기능과 한국어 설계의 추적 관계를 기록한다. 구판 2.3은 현행 4.5로 이동했으므로 분모나 참조 ID에 넣지 않는다. **90%는 사용자 목표이며 아래 표나 참조 ID의 존재로 달성됐다고 판정하지 않는다.** 영어 고유 규칙의 비적용도 53개 분모에서 제거하지 않으며 대안과 남은 검증을 함께 평가한다.

#### KP-EDIT-001 · 수정 전후의 명제를 보존한다

**지침:** 편집 전 서술어별 행위자·행동·대상·관형절 속 주체/피수식어·긍정/부정·조건/예외·수량/빈도·시점/진행·확실성·허락·비교기준/방향/선호·권고·필요·의무·출처·모두/선택/만·기본/원칙/우선 등 한정을 추출한다. 수정 후 원문과 양방향 대조해 앵커의 누락·변경·추가를 채택하지 않는다. 출력 전 대상 우선·속성 분리·조건 범위·기한별 기산 사건과 대상을 각각 점검한다. 시간값·단위·경계가 같아도 기산 사건이 달라지면 원문의 시간 구절로 되돌린다. 새 사실·새 의무·누락·범위 변경은 고치고 검토 과정·합격 선언은 출력하지 않는다. 의미 보존을 구조·간결성보다 우선한다.

**적용 조건:** 간결화나 용어 교체로 문장을 수정할 때; 구조·목록·기한 표시로 재편한 결과를 출력할 때

**예외:** 사용자가 사실 정정이나 내용 변경을 요청한 경우에는 정정 근거를 확인하고 내용 변경으로 표시한다.

**정상 예문 문맥:** 가능성 경고의 대상은 앞 문맥의 저장 기능이다.

```text
원문: 이 저장 기능에서 문제가 발생하는 것이 가능할 수 있습니다.
판정 예문: 이 저장 기능에서 문제가 발생할 수 있습니다.
```

**위반 예문:** 이 저장 기능에서 문제가 발생합니다.

**위반 이유:** 가능성을 확정 사실로 강화했다.

**정당한 반례 문맥:** 저장 기능의 실패 가능성을 짧게 경고한다.

**유지할 반례:** 문제가 있을 수 있습니다.

**허용 이유:** 가능성이 전달 목적이며 대상도 문맥에 있어 추가 설명이 필요하지 않다.

**설계 근거:** 편집의 실패는 짧아진 문장에서도 발생한다. 사실·양태·조건을 독립 보존 항목으로 두어 단정의 강화나 행동의 변경을 먼저 차단한다.

**STE 기능 참조:** 9.1, 9.2의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

**지침:** 수정·실행에 필요한 주체·조건·기준이 없을 때만 확인한다. 있어야 할 역할은 누가 맡았는지 묻고, 배정을 위임받지 않았으면 배정을 제안하지 않는다.

**적용 조건:** 해석 후보에 따라 행동이나 사실이 달라지고 문맥으로 하나를 고를 수 없을 때

**예외:** 문장만 고칠 때는 뜻을 유지해 수정할 수 있으면 실행용 정보를 묻지 않는다. 같은 뜻의 표현은 맡긴 범위에서 정돈한다.

**정상 예문 문맥:** 검토자는 이 대리로 확인되어 있다.

```text
원문: 김 대리가 이 대리에게 문서를 보냈습니다. 그가 검토했습니다.
판정 예문: 김 대리가 이 대리에게 문서를 보냈습니다. 이 대리가 검토했습니다.
```

**위반 예문:** 김 대리가 문서를 검토했습니다.

**위반 이유:** 문맥에서 확인된 검토자를 바꿨다.

**정당한 반례 문맥:** 담당자가 한 명이며 직전 문장에서 식별된다.

**유지할 반례:** 담당자가 문서를 받았습니다. 검토를 시작했습니다.

**허용 이유:** 경쟁하는 주체가 없고 두 번째 문장의 주체를 회복할 수 있다.

#### KP-WRD-003 · 품사와 한국어 결합 패턴을 함께 기록한다

#### KP-VER-006 · 상태 관형어와 행동 관형어를 구별한다

```text
원문: 닫혔던 문을 점검하세요.

```

**위반 이유:** 현재 상태 기준을 과거 이력 기준으로 바꿨다.

**정당한 반례 문맥:** 목록은 현재 상태를 보여 주며 잠긴 파일을 골라야 한다.

**적용 조건:** 두 겹 이상의 관형절이 주체와 대상을 서로 다른 방식으로 연결할 때

**예외:** 단일 관형절이나 정확한 대상 선택에 필요한 짧은 중첩은 이해 관계가 명확하면 유지한다.

**정상 예문 문맥:** 사용자는 지난주에 문서를 요청했고 담당자는 오늘 그 문서를 수정했다.

```text
원문: 담당자가 오늘 수정한 사용자가 지난주에 요청한 문서를 확인하세요.
판정 예문: 사용자가 지난주에 요청한 문서를 담당자가 오늘 수정했습니다. 그 문서를 확인하세요.
```

**위반 예문:** 사용자가 오늘 수정한 문서를 확인하세요.

**위반 이유:** 주체와 시점의 연결을 바꿨다.

**정당한 반례 문맥:** 사용자가 요청한 문서 하나를 지정한다.

**유지할 반례:** 사용자가 요청한 문서를 여세요.

**허용 이유:** 관형절 하나가 대상 선택에 필요한 정보를 전한다.

**설계 근거:** 관형절 중첩의 부담은 구조에 따라 달라진다. 중첩 자체를 금지하지 않고 주체·대상·시점이 얽히는 부분만 풀어 쓴다.


#### KP-SYN-007 · 나눈 문장의 조건 범위를 보존한다

#### KP-KO-002 · 은·는과 이·가의 대비를 보존한다

**지침:** 주제·대조·초점이 사실 구별에 쓰이면 은·는과 이·가를 기계적으로 바꾸거나 지우지 않는다.

**적용 조건:** 조사 정돈으로 포함 범위나 책임 대비가 달라질 때

**예외:** 대조나 초점이 없고 문법과 의미가 같으면 자연스러운 문맥상의 조사를 고른다.

```text
원문: 저장은 완료가 되었지만 배포는 완료가 되지 않았습니다.
판정 예문: 저장은 완료됐지만 배포는 완료되지 않았습니다.
```

**위반 예문:** 저장과 배포가 완료됐습니다.

**위반 이유:** 대조와 미완료 사실을 지웠다.

**정당한 반례 문맥:** 사건을 처음 보고하며 다른 주체와 대비하지 않는다.

**유지할 반례:** 서버가 응답하지 않습니다.

**허용 이유:** 새 사건의 주체를 이·가로 나타내는 것이 적절하다.

**설계 근거:** 은·는과 이·가는 주제·초점·대조를 달리 표시한다. 표면 조사를 통일하기 전에 상태의 대비가 지워지는지 확인한다.

**STE 기능 참조:** 4.2, 9.2의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

- [이홍식: 문장의 주요 성분, 새국어생활 13권 4호(2003), 인쇄 160~161쪽](https://www.korean.go.kr/nkview/nklife/2003_4/2003_0410.pdf)를 참고했다. 확인 범위는 2026-10-12 국립국어원 공개 원문에서 예문 (24)의 능동 목적어/피동 주어 대응과 예문 (26)의 사동 내포절 주체를 확인함. 글 전체의 논의를 검증한 것은 아니며 모든 피동을 능동으로 바꾸라는 지침으로 사용하지 않음.

**사동·피동 역할의 판정:** 사동을 만들거나 줄일 때 원인이 되는 사동주, 실제 실행자 또는 상태 변화를 겪는 참여자, 행동 대상을 각각 연결한다. '팀장이 검사원에게 밸브를 닫게 했다'에서는 팀장과 검사원이 다르므로 팀장이 직접 닫았다는 서술로 바꾸지 않는다. 지시 사실과 실행 완료는 따로 확인하며 확인되지 않은 완료를 덧붙이지 않는다.

일반 피동을 능동으로 바꾸거나 피동을 줄일 때도 누가 행동했고 누가 영향을 받았는지 유지한다. 표면 주어가 행위자라는 가정이나 조사만으로 역할을 확정하지 않는다. 실제 동사의 뜻과 문맥을 함께 읽고 행위자가 없으면 새로 넣지 않는다. 이미 분명한 일반 피동을 능동으로 고칠 의무는 없다.

'-게 하다'와 어휘 사동의 형태만으로 명령·허락·원인 관계를 확정하지 않는다. 농담으로 사람을 웃긴 문맥과 열로 물을 끓게 한 문맥은 원인을 보고하며 명령을 창작할 근거가 없다. 동사 형태에 따라 직접·간접 실행을 자동 확정하지 않고 실제 참여 관계를 확인한다. 기존 행위자·원인·수혜·의도 차이를 검토하는 예외도 유지한다.

작성자 사례 KP-A-KO007-01~08은 사동주와 실행자의 구별, 어휘 사동의 원인과 명령 구별, 비인간 원인, 일반 피동의 유지와 역할 뒤집힘, 허락/명령의 정보 부족을 다룬다. 이 사례들은 독립 평가 자료가 아니다.

#### KP-PROC-001 · 한 단계에 하나의 실행 단위를 둔다

**지침:** 한 단계에는 독자가 따로 완료·검사할 독립 행동 하나를 둔다. 동시에 수행·유지할 행동은 한 실행 단위로 쓴다.

**적용 조건:** 한 문장·단계에 지시가 여럿 있을 때

**예외:** 열어서 확인하다처럼 하나의 즉시 행동으로 이해되고 별도 확인점이 없는 결합은 유지한다.

**정상 예문 문맥:** 파일 저장 후 닫기가 별도 완료 단계이다. 기본 문체의 번호 절차로 정돈한다.

```text
원문: 파일을 저장하고 창을 닫으세요.
판정 예문: 1. 파일을 저장한다.
2. 창을 닫는다.
```

**위반 예문:** 창을 닫고 파일을 저장하세요.

**위반 이유:** 필요한 실행 순서를 뒤집었다.

**정당한 반례 문맥:** 번호 절차의 한 단계이며 버튼 누름을 유지한 채 덮개를 여는 행동이다.

**유지할 반례:** 잠금 버튼을 누른 상태에서 덮개를 연다.

**허용 이유:** 동시 유지 조건을 분리하지 않아야 한다.

**설계 근거:** 현재 지침·적용 조건·예외를 함께 판정한다. 문체 선택과 의미 보존을 구분하며, 새 기본 문체와 짧은 상태형의 사용 범위는 [표현 운영 지침](control-expression.md)에 따른다.

#### KP-PROC-002 · 지시는 실행할 동작으로 끝낸다

**지침:** 지시 단계는 실행 동사로 끝내고 대상·필수 조건을 밝힌다. 상태 설명·희망을 지시 대신 쓰지 않는다.

**적용 조건:** 독자가 실제 수행할 번호·목록 절차 단계

**예외:** 허락·권고·질문은 지시로 강제하지 않고 기존 문장 기능을 유지한다.

**정상 예문 문맥:** 절차가 케이블 연결을 필수 행동으로 지정했다. 기본 문체의 절차 단계로 쓴다.

#### KP-PROC-003 · 선행 조건을 실행보다 먼저 제시한다

**지침:** 행동의 실행 여부를 정하는 조건을 행동 앞에 둔다. 하나의 조건 아래 여러 후속 행동·결과가 있으면 조건을 제목이나 도입 줄로 올려 해당 항목만 묶는다. 순서가 있으면 번호로 나누고 항목마다 하나의 행동·결과를 둔다. 자동 처리·보고를 독자의 지시로 바꾸지 않는다. 항목별 주체·조건을 남기고 확인된 공통 역할은 제목에 둘 수 있다. 범위 밖 규칙은 동급 제목으로 분리한다. 조건의 참조 대상·범위가 미정이면 원문 연결을 유지하며 제목으로 새 범위를 정하지 않는다.

**적용 조건:** 조건 충족에 따라 해야 할 행동이 달라질 때; 하나의 조건 아래 두 개 이상의 후속 행동·결과가 있을 때

**예외:** 설명문에서 이미 실행한 행동과 사후 조건을 분석하는 순서는 독자의 질문에 맞춘다.

**정상 예문 문맥:** 온도가 60도 이상일 때만 작동을 중단한다.

```text
원문: 작동을 중단하세요. 온도가 60도 이상이면 그렇습니다.
판정 예문: 온도가 60도 이상이면 작동을 중단하세요.
```

**위반 예문:** 온도가 60도 이하이면 작동을 중단하세요.

**위반 이유:** 조건의 수치 방향을 뒤집었다.

**정당한 반례 문맥:** 정지 명령의 조건은 앞선 단계에서 확인됐다.

**유지할 반례:** 작동을 중단하세요.

**허용 이유:** 공유된 조건을 단일 단계에서 무조건 반복할 필요가 없다.

**설계 근거:** 선행 조건을 뒤늦게 읽으면 먼저 실행할 수 있다. 해당 조건을 행동 전에 보이되 알려지지 않은 조건을 만들지 않는다.

**STE 기능 참조:** 5.4, 7.2의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

#### KP-PROC-004 · 예외의 적용 행동을 특정한다

**지침:** 예외가 면제하는 조건·행동을 같은 문장이나 공통 도입부에 밝히고 단독 단서를 뒤로 떨어뜨리지 않는다. 대상·조건별 기본 기한과 예외 기한은 같은 블록의 별도 항목에 두어 각각의 적용 범위를 드러낸다. 원문이 정한 대체 관계를 중복 의무로 바꾸지 않는다. 대체·추가 관계가 미정이면 기본·예외 라벨로 임의 결정하지 않는다. 지연·미응답의 후속 처리는 해당 기한과 연결해 별도 단계로 나눈다.

**적용 조건:** 단·다만·제외 등의 예외가 절차에 붙을 때; 대상·조건에 따라 기한이 달라질 때

**예외:** 예외가 없는 단순 절차에는 예외를 만들어 추가하지 않는다.

**정상 예문 문맥:** 자동 백업이 완료된 경우에만 수동 백업을 생략한다.

```text
원문: 수동 백업을 하세요. 자동 백업이 끝나면 제외입니다.
판정 예문: 자동 백업이 끝나지 않았으면 수동 백업을 하세요.
```

**위반 예문:** 자동 백업 기능이 있으면 수동 백업을 생략하세요.

**위반 이유:** 완료 조건을 기능 존재 조건으로 바꿨다.

**정당한 반례 문맥:** 모든 장비에 같은 점검이 적용되며 예외는 없다.

**유지할 반례:** 모든 장비를 점검하세요.

**허용 이유:** 독자가 필요하지 않은 예외를 덧붙이지 않는다.

**설계 근거:** 예외는 무엇을 면제하는지 식별되어야 한다. 실제 완료와 기능 존재를 혼동하지 않으며 예외 없는 절차에 새 예외를 넣지 않는다.

**STE 기능 참조:** 5.4, 4.4의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

<a id="kp-proc-005"></a>
#### KP-PROC-005 · 순서와 동시성의 표지를 남긴다

**지침:** 전·후·동안·상태에서·동시에의 관계를 보존하고 번호 목록으로 바꿀 때도 먼저/이후/유지를 드러낸다.

**적용 조건:** 실행 시점이나 지속 상태가 결과를 바꾸는 절차

**예외:** 순서가 자유로운 독립 점검은 번호가 우선순위나 선후를 뜻하지 않는다고 필요한 경우 밝힌다.

**정상 예문 문맥:** 잠금 버튼을 계속 누른 동안만 덮개가 열린다.

```text
원문: 잠금 버튼을 누르고 덮개를 여세요.
판정 예문: 잠금 버튼을 누른 상태에서 덮개를 여세요.
```

**위반 예문:** 1. 잠금 버튼을 누르고 놓으세요.
2. 덮개를 여세요.

**위반 이유:** 지속해서 눌러야 하는 조건을 없앴다.

**정당한 반례 문맥:** 순서가 정해지지 않은 두 소모품의 상태 점검이다.

**유지할 반례:** 필터와 호스의 상태를 확인하세요.

**허용 이유:** 문맥상 독립 확인이며 임의의 순서를 추가하지 않는다.

**설계 근거:** 순서대로 나누기만 하면 동시에 유지할 조건이 사라질 수 있다. 전후와 동안의 차이를 실행 단위에 남긴다.

#### KP-PROC-006 · 행동 기준과 재량을 구별한다

**지침:** 정해진 절차가 필요한 지시는 기준이나 참조 절차를 밝히고 방법을 독자에게 맡긴 지시는 목적과 확인된 제약을 유지한다.

**적용 조건:** 적절히·알아서·충분히가 실행 판단을 맡길 때

**예외:** 독자가 공통 기준을 알고 있거나 방법 선택 자체가 위임된 경우에는 정해진 행동을 창작해 강제하지 않는다.

**정상 예문 문맥:** 작성자가 적용할 기준으로 E1 절차를 확인했다. E1 절차는 문서에 있지만 이 지시와 E1의 연결은 독자에게 공유되지 않았다.

```text
원문: 오류를 적절히 처리하세요.
판정 예문: E1 오류 처리 절차에 따라 처리하세요.
```

**위반 예문:** 오류가 나면 파일을 삭제하세요.

**위반 이유:** 원문과 문맥에 없는 복구 동작을 임의로 지시했다.

**정당한 반례 문맥:** 담당자는 주어진 예산 안에서 설치 방법을 선택할 재량이 있다.

**유지할 반례:** 예산 한도 안에서 적절한 설치 방법을 선택하세요.

**허용 이유:** 방법 선택이 전달 목적이며 세부 절차 강제가 아니다.

**설계 근거:** 공유된 기준이 있으면 짧은 지시도 명확하다. 연결이 공유되지 않은 절차만 명시하고 자유 재량이나 미확인 기준을 임의의 복구 행동으로 대체하지 않는다.

#### KP-PROC-007 · 필수 행동을 참고 사항에 숨기지 않는다

**지침:** 필수 실행·점검·안전 조치와 행동 없는 필수 요구조건·허용 한계는 본문 절차·사양·경고에 두고 참고 사항에는 보충 정보만 둔다.

**적용 조건:** 주석·참고·팁 속에 수행 의무·필수 요구조건·허용 한계가 들어 있을 때 적용한다. 행동 없는 조건이나 한계도 본문에서 판단할 수 있어야 한다.

**예외:** 같은 단계에 이미 적힌 행동의 이유·배경을 주석으로 설명하는 것은 허용한다.

**정상 예문 문맥:** 전원 차단은 필수 단계이며 참고 정보가 아니다.

```text
원문: 참고: 전원을 차단해야 합니다.
판정 예문: 전원을 차단하세요.
```

**위반 예문:** 팁: 필요하면 전원을 차단하세요.

**위반 이유:** 필수 안전 행동을 선택적 팁으로 바꿨다.

**정당한 반례 문맥:** 전원 차단 단계는 이미 있으며 참고는 이유를 설명한다.

**유지할 반례:** 참고: 이 장치는 전원을 차단해도 설정을 유지합니다.

**허용 이유:** 추가 행동이 아닌 기능 정보를 제공한다.

**설계 근거:** 주석에는 보충 정보가 놓인다는 읽기 기대가 있다. 필수 행동뿐 아니라 필수 조건·허용 한계도 본문에서 판단하게 한다.

**STE 기능 참조:** 5.5, 7.2의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

**허용 이유:** 질문에 답한 뒤 필요한 제한을 함께 밝힌다.

#### KP-TXT-001 · 목록은 공통 조건과 항목의 역할을 표시한다

**지침:** 독립 확인 기준·행동·비용·위험은 3개 이상이거나 2개라도 따로 비교·확인하면 목록화한다. 반납·제출·점검·준비 등 여러 대상에 관한 행동이 문서의 주된 목적이면 대상 제목과 목록을 첫 본문 블록에 두고 대상마다 별도 줄을 쓴다. 다른 설명 안의 대상은 해당 블록 첫머리에 둔다. 진행 상태와 담당자의 행동은 목록 바로 뒤에, 출처·제한은 적용 대상과 연결되는 뒤 위치에 남긴다. 긴급 안전 경고는 위험 행동 앞에 유지한다. 예시·선택·허용·필수·대조의 지위와 모두/하나 선택 관계는 원문대로 도입부에 둔다. 문장 안의 독립 항목도 분리한다. 범위는 KP-SYN-007을 따르고 모두/선택·순서·공통 서술어는 원문대로 도입부에 둔다.

**적용 조건:** 여러 항목을 비교·실행·선택·확인할 때

**예외:** 두 항목의 짧은 나열은 문장 안에서 쉽게 구별되면 목록으로 늘리지 않는다. 한 쌍의 관계·고정 명칭·인과·동시 유지 조건은 항목 수만으로 나누지 않는다.

**정상 예문 문맥:** 관리자는 세 검사를 모두 수행해야 한다.

```text
원문: 관리자는 권한, 파일 상태, 저장 공간을 확인하세요.
판정 예문: 관리자는 다음 항목을 모두 확인하세요.
- 권한
- 파일 상태
- 저장 공간
```

**위반 예문:** 다음 항목 중 하나만 확인하세요.

**위반 이유:** 동시 충족을 선택 조건으로 바꿨다.

**정당한 반례 문맥:** 서로 다른 파일 두 개를 이름으로 지정한다.

**유지할 반례:** A.txt와 B.txt를 여세요.

**허용 이유:** 짧고 평행한 두 대상이 명확해 목록화가 필요하지 않다.

**설계 근거:** 목록의 항목만 분리하면 모두와 하나 선택의 차이가 사라질 수 있다. 공통 조건·논리 수량·순서 여부를 도입부에서 식별한다.

**STE 기능 참조:** 4.3, 8.4의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

#### KP-TXT-002 · 목록 항목의 문법 역할을 맞춘다

**지침:** 신청 방식·처리 경로·유형을 비교하면 선택지 이름을 제목으로 쓰고 적용 대상·수행자와 행동·기한을 독립 항목으로 나눈다. 원문에 없는 속성·자동 처리 담당자를 만들지 않는다. 공통 규칙은 마지막 선택지 밖의 동급 제목에 두고 적용 범위를 밝힌다. 속성에는 불릿을, 실제 수행 순서에는 번호를 쓴다. 한 항목의 독립 주장·행동 단위는 KP-SYN-006을 따르고 행동·상태·대상의 문법 역할을 맞추고 다른 역할은 도입부로 구별한다.

**적용 조건:** 병렬 목록의 역할·주장을 구성·검토할 때

**예외:** 장단점·입력/결과 등 서로 다른 열의 표는 역할이 표 구조에 표시되면 형식을 다르게 쓸 수 있다.

**정상 예문 문맥:** 세 항목 모두 수행해야 하는 점검 단계이다.

```text
원문: - 권한 확인
- 파일을 여세요.
- 저장 공간의 점검이 필요합니다.
판정 예문: - 권한을 확인하세요.
- 파일을 여세요.
- 저장 공간을 점검하세요.
```

**위반 예문:** - 권한이 있습니다.
- 파일을 열었습니다.
- 저장 공간이 충분합니다.

**위반 이유:** 수행 지시를 확인되지 않은 완료 보고로 바꿨다.

**정당한 반례 문맥:** 표는 행동과 결과를 서로 다른 열에 표시한다.

**유지할 반례:** 행동: 저장 / 결과: 실패

**허용 이유:** 역할이 구별되므로 두 항목의 문법 형태가 같을 필요는 없다.

**설계 근거:** 목록의 문법 형태는 각 항목의 역할을 드러낸다. 같은 역할은 맞추고 다른 열의 행동과 결과는 형식까지 같게 만들지 않는다.

**STE 기능 참조:** 4.3, 9.4의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

#### KP-TXT-003 · 부호는 문장 관계를 대신하지 않는다

**지침:** 문장 경계·쉼표·쌍점·괄호를 관계가 드러나는 위치에 쓰고 슬래시·하이픈·세미콜론만으로 조건·선택·인과를 전달하지 않는다.

**적용 조건:** 부호의 관계가 둘 이상으로 해석될 때

**예외:** 코드·식별자·정식 표기에 포함된 부호는 그대로 보존하며 부호 자체를 금지하지 않는다.

**정상 예문 문맥:** 전원이 꺼진 경우에만 덮개를 연다.

```text
원문: 전원 꺼짐 / 덮개 열기
판정 예문: 전원이 꺼져 있으면 덮개를 여세요.
```

**위반 예문:** 전원을 끄거나 덮개를 여세요.

**위반 이유:** 조건을 선택 관계로 바꿨다.

**정당한 반례 문맥:** 실제 파일명이 report-2026-10.txt이다.

**유지할 반례:** “report-2026-10.txt”를 여세요.

**허용 이유:** 이름 내부 하이픈은 문장 연결이 아니라 식별 문자열이다.

**설계 근거:** 부호 자체는 조건·선택·인과 중 하나를 확정하지 못한다. 실제 코드와 식별 부호는 남기고 본문의 모호한 연결만 표현으로 풀어 쓴다.

**STE 기능 참조:** 8.1, 8.2, 8.4의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

#### KP-TXT-004 · 괄호는 보충 정보를 담는다

**지침:** 핵심 조건·필수 행동·주요 결론은 본문에 두고 괄호에는 참조·짧은 정의·식별 정보 등 보충 내용을 둔다.

**예외:** 수학식·공식 명칭·인용의 괄호는 실제 의미와 문자열을 보존한다.

```text
원문: 설치하세요(저장 공간이 1GB 이상일 때만).
판정 예문: 저장 공간이 1GB 이상일 때만 설치하세요.
```

**위반 예문:** 저장 공간과 관계없이 설치하세요.

**위반 이유:** 설치 조건을 없앴다.

**정당한 반례 문맥:** 장비의 도면상 식별 번호를 표시한다.

**유지할 반례:** 밸브(도면 3의 A)를 닫으세요.

#### KP-TXT-005 · 참조는 실제로 찾을 위치를 특정한다

**지침:** 절차·도면·표·파일을 참조하면 실제 이름이나 위치를 쓰고 같은 이름의 후보가 여럿이면 구별할 표지를 추가한다.

**적용 조건:** 위 참조·이 문서·해당 표 등이 여러 자료로 연결될 때

**예외:** 바로 앞의 한 표·한 도면만 지칭하면 짧은 참조를 허용한다.

**정상 예문 문맥:** 점검표가 둘이며 이번 지시는 월간 점검표를 가리킨다.

```text
원문: 점검표를 작성하세요.
판정 예문: 월간 점검표를 작성하세요.
```

**위반 예문:** 일간 점검표를 작성하세요.

**위반 이유:** 참조 대상을 바꿨다.

**정당한 반례 문맥:** 바로 앞에 밸브 위치를 보여 주는 도면이 하나 있다.

**유지할 반례:** 위 도면에서 밸브 위치를 확인하세요.

**허용 이유:** 참조 대상이 문서 자리로 하나로 정해진다.

**설계 근거:** 참조는 독자가 실제 자료를 찾게 해야 한다. 후보가 여럿이면 이름이나 위치를 구별하고 한 자료만 있으면 짧은 참조를 허용한다.

**STE 기능 참조:** 8.3, 4.5의 작성 기능을 참고했다. 한국어 규칙의 효과는 검증 전이다.

<a id="kp-txt-006"></a>
#### KP-TXT-006 · 짧은 상태·UI 문구는 대상과 범위를 남긴다

**지침:** 대상·범위·양태가 명확한 상태·결과·확인은 짧은 명사형으로 쓴다. 주체·시점·조건 종류가 회복되면 조건도 짧은 도입부로 쓴다. 버튼·제목·표는 위치로 대상·기능이 명확하면 명사형·짧은 구를 쓴다. 요청·허락·의무·금지·가능성·진행·전언·만·모두를 짧은 구에도 남긴다. 이미 짧고 찾기 쉬운 문장은 여러 제목으로 쪼개지 않는다.

**적용 조건:** 상태 보고·확인 항목·UI·표의 짧은 표현을 검사할 때

**예외:** 판단을 바꾸는 삭제 범위·실패 원인·결과 단계는 남긴다. 행동 지시·조건·인과·경쟁 대상은 관계가 드러나는 문장·도입부로 쓴다. 승인 요청 시를 승인 시로 줄이는 등 행동·시점이 달라지는 축약은 하지 않는다.

**정상 예문 문맥:** 두 상태 중 현재는 저장 실패이며 업로드 단계와 구별해야 한다.

```text
원문: 실패
판정 예문: 저장 실패
```

**위반 예문:** 완료

**위반 이유:** 실패를 완료로 바꿨다.

**정당한 반례 문맥:** 저장 버튼은 선택한 문서를 저장하며 다른 저장 동작은 없다.

**유지할 반례:** 저장

**허용 이유:** 대상과 행동을 화면에서 회복할 수 있어 완전한 문장으로 늘리지 않는다.

## 남은 검증과 개정 조건

현재 72개 규칙과 296개 사례를 연결했으며 현행 STE 참조 ID 53개를 모두 추적한다. 참조 연결은 기능 충족의 증명이 아니다. 초기 통제 어휘의 선언 범위를 넘어선 항목 충족, 표면형 분석의 정확도, 분야별 전문어 확장의 완결성과 실제 통제 효과는 검증되지 않았다.

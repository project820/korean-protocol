# Korean Protocol 전체 규약의 목차

이 목차는 `0.7.0-draft`의 규칙·사전·검증·배포 체계를 안내한다. 현재 규칙 72개·규칙 작성자 사례 296개·사전 193뜻을 제공하며, 기능 대응은 설계 49개·검증 0개·부분 4개다. 장 제목이 존재하는 것과 해당 장의 규칙·용례·검증이 완료된 것은 다르며, 상태는 [대응 판정 정책](coverage-policy.md)과 릴리스 증거로 관리한다.

현재 0.7.0-draft는 V7 r2의 정보 배열을 채택한다. 대상·선택지·조건·수량·기한을 찾기 쉬운 위치에 두며 원문보다 짧게 만들 것을 요구하지 않는다. [채택 결정](../../experiments/v7/adoption.md)과 [현재 검증 상태](../status/requirements.md)는 별도로 확인한다. 압축을 강화한 r3는 채택하지 않았다.

공개 서명 콘텐츠는 `0.7.0·순번 3`이며 엔진은 `0.2.0`이다. 사용자 패키지 `v0.7.0`은 `7e01d53`에서 발행한 고정 ZIP·첨부 파일이며 이후 main의 목차·문서 개정은 자동 반영되지 않는다.

## 제1부는 적용 원칙과 의미 보존을 정한다

1. 목적과 범위는 한국어 LLM 답변 및 업무·기술 문서의 지원 범위를 명시한다.
2. 규범의 우선순위는 사실·수량·단위·대상·주체·부정·조건·시점·확실성의 보존을 문체보다 앞에 둔다.
3. 문서 기능은 지시·허락·보고·질문·설명·경고를 구분한다.
4. 근거와 불확실성은 사실·추론·미확인 정보의 구별을 유지하며, 짧은 가능성 표현을 허용한다.
5. 적용 예외는 인용·공식 명칭·코드·식별자·수식·제목·표·화면 상태를 다룬다.
6. 규범의 구조와 변경 계약은 [architecture.md](architecture.md)에 정의한다.

## 제2부는 통제 어휘와 사전 확장을 정한다

1. 어휘 항목은 표면형과 개념·의미 ID를 분리한다.
2. 일반 어휘는 의미, 품사, 활용, 결합 표현과 적용 독자를 기록한다.
3. 전문 명사는 분야·장비·화면·조직에서 사용하는 실제 명칭을 등록한다.
4. 전문 동사는 동작의 대상·결과·시점과 파생 형태의 조건을 기록한다.
5. 명명 정책은 같은 개념의 이름, 동음어, 별칭, 약어의 도입과 재사용을 정한다.
6. 표기 정책은 맞춤법·띄어쓰기·외래어·영문 혼용·숫자·단위·범위를 다룬다.
7. 사전 확장은 기본·분야·프로젝트 어휘의 승인, 충돌, 폐기와 후속 ID를 관리한다.
8. 어휘 검사는 지원 분야별 의미 사용 충족률과 미등록·모호·오용 항목을 구분한다.

상세 어휘 규범은 `docs/spec/lexicon.md`, 구조 계약은 `schemas/lexicon.schema.json`, 실제 사전은 `lexicon/`, 용례는 `examples/lexicon-cases.json`에서 관리한다.

## 제3부는 한국어 문장 구조를 정한다

1. 조사와 논항은 누가 무엇을 누구에게 하는지와 조사 교체에 따른 뜻 차이를 다룬다.
2. 주제·초점·생략은 문맥에서 대상을 하나로 복원할 수 있는 조건을 정한다.
3. 대명사·지시어는 대상 전환, 여러 후보, 문장 단독 인용의 조건을 다룬다.
4. 수식과 명사 연결은 관형절 범위, 복합 명칭, 명사 나열의 관계를 정한다.
5. 서술어와 활용은 직접 행동 표현, 명사화, 보조용언과 관형형을 다룬다.
6. 시상과 증거성은 시작·진행·완료·계획·전언의 구분을 보존한다.
7. 양태와 화행은 가능성·능력·허락·의무·권고의 차이를 보존한다.
8. 부정과 수량은 금지·불가능·미완료·예외·전체와 일부의 범위를 정한다.
9. 능동·피동·사동은 행위자·책임·상태 초점과 미상 주체의 처리를 정한다.
10. 조건·이유·시간은 선행 조건, 분기, 순서, 동시성, 종료 조건을 연결한다.
11. 높임·종결형은 대상 독자와 전달 목적에 맞게 어조를 유지한다.
12. 문장 부담은 절의 관계와 수식 깊이를 함께 점검하며 고정 영어 단어 수를 한국어 어절 수로 치환하지 않는다.

상세 규칙은 `docs/spec/korean-rules.md`, 기계 판독 규칙은 `specification/rules.json`, 용례는 `examples/rule-cases.json`에서 관리한다.

## 제4부는 문서 기능과 정보 배열을 정한다

1. 절차문은 전제, 준비, 실행 단계, 분기, 동시 행동, 확인, 종료와 복구를 구분한다.
2. 설명문은 대상·개념·관계·예외를 독자가 이해할 순서로 제시한다.
3. 보고문은 요청의 중심 결과와 범위·제한을 먼저 전달하고 실행·관찰·예정의 차이를 남긴다.
4. 경고문은 검증된 위험 수준, 해당 대상, 필요한 행동·조건과 가능한 결과를 연결한다.
5. 주석은 보충 정보로 사용하며 필수 행동과 중요한 조건을 숨기지 않는다.
6. 문단은 한 중심 주제를 유지하고 관계가 달라지는 위치에서 나눈다.
7. 목록·표는 공통 도입문, 항목별 완결성, 조건의 적용 범위와 병렬성을 정한다.
8. 참조는 실제 절차·도면·파일·화면 이름과 식별자를 연결한다.
9. 문장부호와 측정은 문장 경계, 목록 경계, 괄호, 인용, 숫자·단위·식별자 묶음을 일관되게 처리한다.
10. V7 정보 배열은 대상 목록, 선택지별 속성, 조건별 흐름, 수량 기준과 기한을 나누며 공통 규칙의 범위와 시간의 기산 사건을 보존한다.

## 제5부는 적용과 용례를 정한다

1. 작성 절차는 문맥 확인, 의미 항목 확보, 어휘 선택, 문장 구성과 자기검사를 수행한다.
2. 수정 절차는 불필요한 표현만 줄이고 사실·절차·원인을 새로 만들지 않는다.
3. 각 규칙의 용례는 적합·부적합·예외·수정 금지·원문 유지 사례를 포함한다.
4. 복합 사례는 여러 규칙이 충돌하는 상황과 우선순위에 따른 판정을 포함한다.
5. 문서 전체 사례는 절차·설명·보고·경고에서 문장 사이의 관계를 검증한다.
6. 초기 12개 원칙의 이행표는 보존·세분화·수정한 의미와 후속 규칙 ID를 기록한다.

## 제6부는 검증과 대응 범위를 정한다

1. 구조 검사는 스키마, 고유 ID, 실제 참조, 버전과 필수 항목을 확인한다.
2. 규칙 검사는 문맥별 적용 조건과 예외를 양호·부적합 사례에 대조한다.
3. 의미 검사는 사실 추가·누락, 대상 혼동, 조건 손실, 화행·확실성 변경을 평가한다.
4. 어휘 검사는 지원 분야의 승인 의미·활용·결합을 실제 사용 사례에서 평가한다.
5. STE 대응 감사는 원본 53개 기능을 고정 분모로 사용하며 부분 대응을 합산하지 않는다.
6. 실제 LLM 검증은 모델·버전·설정·입력·원출력·평가자를 기록하고 규약 미적용 조건과 비교한다.
7. 독자 검증은 이해 정확도, 시간, 재독·추가 질문, 자연스러움의 차이를 구분한다.
8. 실패 관리와 릴리스 판정은 미검증·실패·불일치를 공개하고 수정 뒤 재검증한다.

비교표는 `specification/ste-crosswalk.json`, 판정은 [coverage-policy.md](coverage-policy.md), 검사 코드와 시험은 `validation/`과 `tests/`에서 관리한다.

독립 기능 사례는 `evaluation/functional-cases.json`, 원본 항목별 기능 설계 검토는 `evaluation/functional-review.json`에서 관리한다. 이 검토는 규칙·작성자 사례·독립 사례·상세 규범의 해시로 대상을 고정하며 실제 LLM 실행 결과와 독자 실험을 대신하지 않는다.

## 제7부는 지속 설치와 자동 업데이트를 정한다

1. 지원 환경은 도구·버전별 프로필 공급 방식과 새 세션의 적용 시점을 명시한다.
2. 설치는 멱등성, 사용자 설정 보존, 상태 확인과 제거 범위를 정의한다.
3. 배포 묶음은 규범·규칙·어휘·프로필의 버전과 무결성 정보를 고정한다.
4. 업데이트는 선택한 채널, 검사 주기, 버전 고정, 호환성 검사와 적용 조건을 정의한다.
5. 실패 처리는 중단·오프라인·변조·부분 다운로드·권한 오류에서 기존 버전 유지와 복구를 검증한다.
6. 마이그레이션은 ID·스키마 변경과 프로젝트 어휘의 보존·충돌을 다룬다.
7. 실제 사용 검증은 재시작·새 세션·업데이트 뒤 프로필 공급과 출력 평가를 확인한다.

설치·배포 규범은 `docs/distribution/`, 배포 구조 계약은 `schemas/release.schema.json`, 실행 코드는 `runtime/`에서 관리한다. 이 경로의 구현 상태와 지원 환경은 배포 문서와 검사 결과에서 확인한다.

## 부록은 근거와 이력을 보존한다

1. 근거 대장은 문헌이 직접 보여 준 내용과 프로젝트의 설계 판단을 구분한다.
2. STE 비교표는 원본 식별자와 독자적인 짧은 기능명만 사용하며 원문 규칙·예문·사전을 대체하지 않는다.
3. 변경 기록은 규칙·어휘의 버전별 의미 변화와 평가 결과를 보존한다.
4. 기여 양식은 문맥, 독자, 의도, 바꾸면 안 되는 뜻, 제안, 반례와 검증 방법을 요구한다.

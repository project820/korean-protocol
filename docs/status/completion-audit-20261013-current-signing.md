# 현행 실제 서명물의 로컬 경로를 검증했으며 공개 조건은 남아 있다

> **과거 기록을 보존한다.** 아래 버전·검증 수치·미완료 항목은 작성 당시의 상태다. 현행 0.7의 사용법은 [설치 안내](../../INSTALL.md), 확인 범위는 [현재 상태](requirements.md)를 따른다. 과거 결과를 0.7의 재검증으로 계산하지 않는다.

직전 작업은 새 합성 12개 평가, 미리보기 7 생성·다운로드 대조와 커밋·푸시를 완료했으므로 진척으로 분류한다. 이번 작업은 제품 규칙·사전·런타임을 유지하면서 현행 원본의 실제 GitHub Secret 서명, 두 호스트의 설치, HTTPS 갱신 확인과 실패 보존을 검증했다.

| 요구사항은 다음과 같다. | 현재 증거는 다음을 입증한다. | 아직 완료하지 않은 범위는 다음과 같다. |
| --- | --- | --- |
| STE 기능의 90% 이상에 대응한다. | 변경 없는 규범 원본에 대한 기능 설계 검토는 49/53개를 통과한다. | 네 부분 대응을 공개하며 이 비율을 전체 언어 성능으로 해석하지 않는다. |
| 한국어 규칙·예외·용례와 의미 단위 사전을 제공한다. | 규칙 72개·작성 사례 260개, 뜻 193개·작성 사례 454개와 기존 독립 범주 검토를 보존한다. | 실제 전문가 승인이나 모든 구문·분야의 포괄성을 주장하지 않는다. |
| 실제 모델이 의미와 과제 범위를 지킨다. | 새 합성 12개에서 두 조건 모두 의미·과제 수행을 통과했고 결과·정답·입력을 고정해 보존한다. | 단일 배치·동률 결과는 일반 개선 효과나 독자 이해도 증거가 아니다. |
| 한 번 설치한 규약을 보존하고 자동 갱신한다. | 현행 실제 Secret 서명물을 두 임시 호스트에 설치·재설치·제거했다. 실제 서명물의 HTTPS 수동·wrapper 확인은 각각 9개 파일을 검증했고 TLS·서명·서버 중단 시 정상본을 보존했다. | 실제 게시자 키의 다음 버전 업그레이드, 공개 endpoint 예약 갱신, 재로그인·물리적 절전 복귀는 미검증이다. 시험용 키의 버전 업그레이드는 별도 통과했다. |
| 누구나 저장소 주소로 설치하게 한다. | 최신 비공개 미리보기와 비대화형 설치기를 제공하고 GitHub Secret·발행 절차를 연결했다. | 라이선스 선택과 공개 전환·첫 Pages 게시가 남아 있다. 현재 PRIVATE와 게시 변수 false를 유지한다. |

[현행 서명 검증](../distribution/current-actions-verification.md)은 Actions 38353292401의 90개 검사와 sign 성공, publish·receipt·archive 건너뜀을 기록한다. 두 실제 발행물 HTTPS 시험과 별도 시험용 업그레이드는 각각 16단계가 통과했다. 실제 서명물은 0.2.0·순번 1의 같은 버전 확인이며 시험용 키의 0.2.0→0.2.1 결과를 실제 공개 업그레이드로 합산하지 않는다.

시험 도구에는 실제 서명물을 읽는 옵션과 회귀 검사 6개를 추가했다. 공개키 상대경로와 manifest 파일 순서에 관한 독립 검토 지적 두 개를 고쳤으며, 최종 스크립트로 세 네트워크 시험을 다시 실행했다. 새 검사 6개·발행 검사 13개의 통과와 최종 원본 해시를 current-actions-review.json에 기록했다. 제품 런타임과 규범은 바꾸지 않았다.

[공개 준비 파일 목록 검사](../distribution/publication-inventory-20261013.json)는 기준 커밋 a16776d의 추적 파일 591개에 알려진 개인키·토큰 패턴, 자격 파일명, 외부 PDF·ZIP 첨부가 없었음을 확인한다. 이는 포괄적인 비밀·저작권 검토를 대신하지 않는다. LICENSE·COPYING·NOTICE 파일도 없었으므로 직접 작성한 코드·규약·사전의 공개 라이선스를 소유자에게 질문했다. 선택지를 임의로 적용하거나 외부 ASD-STE100 자료까지 재허락하지 않았다.

다음 단계는 사용자의 라이선스 선택을 반영해 배포물에 포함하고, 공개할 최종 원본·패키지·서명 경로를 검토 가능한 상태로 정리하는 것이다. 공개 전환과 첫 게시 후에는 실제 HTTPS endpoint로 신규 설치·예약 갱신을 검증해야 한다. 현재는 전체 완료나 공개 운영 완료를 선언하지 않는다.

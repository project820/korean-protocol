# 공개 배포와 실제 설치·갱신 확인을 완료했다

> **과거 기록을 보존한다.** 아래 버전·검증 수치·미완료 항목은 작성 당시의 상태다. 현행 0.7의 사용법은 [설치 안내](../../INSTALL.md), 확인 범위는 [현재 상태](requirements.md)를 따른다. 과거 결과를 0.7의 재검증으로 계산하지 않는다.

2026-10-13 사용자의 공개 승인에 따라 project820/korean-protocol 저장소를 PUBLIC으로 전환하고 GitHub Pages에 첫 서명 콘텐츠를 게시했다. [Actions 실행 38359118074](https://github.com/project820/korean-protocol/actions/runs/38359118074)의 sign·publish·receipt·archive 작업이 모두 성공했다. 게시 원본은 `91526bb325175992701cd4eb4e1e3e56731a1cdd`이며 버전은 `0.2.0`, 순번은 `1`이다. 이전 점검 문서의 비공개·게시 대기 상태는 당시 기록으로 보존한다.

## 공개 경로와 보관 이력을 확인했다

[익명 HTTPS 검사](../distribution/public-download-verification.json)는 공개 endpoint `https://project820.github.io/korean-protocol`의 manifest 서명을 콘텐츠보다 먼저 검증하고, 콘텐츠 7개와 manifest·서명 파일을 포함한 9개 파일을 확인했다. 인증정보를 전송하지 않았으며 모든 콘텐츠 해시가 게시 원본과 일치했다.

[장기 보관 검사](../distribution/public-archive-verification.json)는 GitHub Release `kproto-history-0.2.0-1`의 콘텐츠·서명된 발행 영수증·원본 커밋·실제 워크플로 이력을 검증했다. 보관본과 현재 Pages의 stable 파일도 일치했다. `KPROTO_PAGES_ENABLED=true`를 유지하고 최초 게시 전용 변수 `KPROTO_ALLOW_FIRST_PUBLICATION`은 false로 되돌렸다.

## 두 호스트에 공개 콘텐츠를 설치했다

설치기는 `--source`와 로컬 공개키·고정 지문으로 공개 콘텐츠를 직접 받는다. 임시 폴더에서 서명·크기·해시·버전을 검증한 뒤에만 설치 상태를 변경한다. 공개키는 다운로드 서버에서 받지 않으며 기존 신뢰 키를 자동 교체하지 않는다. 다운로드 제한 시간·크기·리디렉션 금지와 기존 로컬 설치 경로를 유지했다.

[실제 설치 검사](../distribution/public-install-verification.json)는 Xcode Python 3.9.6으로 별도 Codex·Claude Code 홈에 익명 서명 설치를 수행했다. 원격 plan의 사용자 상태 보존, 설치·상태 확인, 수동 동일 버전 갱신 확인, 시작 wrapper 실행, 재설치 시 지침 보존, 다른 작업 폴더에서 지속 관리, 제거 후 원래 사용자 지침 복원을 통과했다. 이 실행 중 새 Python 충돌 보고서는 없었다. 실제 사용자의 에이전트 설정은 변경하지 않았다.

[실제 예약 검사](../distribution/public-scheduler-verification.json)는 최종 설치기의 원격 `--source` 경로로 임시 Codex 설치본과 실제 macOS LaunchAgent를 등록했다. 아직 갱신 시각이 아닌 실행과 공개 서버 조회 실행이 모두 종료 코드 0으로 끝났고, 후자의 `last_success`가 새로 기록됐다. 등록 파일·실행 경로를 대조했으며 자동 갱신 해제와 제거 후 소유 작업·파일이 없어지고 원래 지침이 복원됐다.

## 자동 검사와 독립 검토를 통과했다

`python3 -B -m unittest discover -s tests`는 310개를 37.595초에 통과했다. 새 원격 설치 테스트는 신뢰 입력·서명 순서·제한 시간·크기·리디렉션·잘못된 배포물 거부·상태 보존·예약 연결을 포함한다. 독립 Astra/high 검토자는 설치기 테스트 40개와 다운로드 도중 입력 공개키를 교체하는 별도 탐침을 실행하고 추가 결함을 보고하지 않았다. 런타임 118개도 별도 실행에서 통과했다.

최초 수동 검사에서는 성공 시 출력이 없는 runtime update를 JSON으로 읽는 시험 스크립트 오류가 있었다. 출력 처리를 고친 뒤 두 호스트 검사를 전부 다시 통과했다. 장기 보관 첫 탐침은 해석하지 않은 macOS 임시 경로의 심볼릭 링크를 거부했으며, 실제 경로로 해석해 재실행했다. 두 오류는 제품 코드를 바꾸지 않고 검사 스크립트에서 바로잡았다.

## 확인하지 않은 범위를 구분한다

공개 서버에서는 동일 버전의 서명된 갱신 확인을 검증했다. 실제 다음 버전의 공개 발행·업그레이드, 재로그인, 물리적 절전·복귀는 시험하지 않았다. 시험용 키의 다음 버전 업그레이드와 로컬 HTTPS 장애·오프라인 보존 결과는 기존 기록이며 공개 서버의 다음 버전 시험으로 합산하지 않는다.

첫 manifest는 `2026-11-12T06:51:53Z`에 만료된다. 그 전에 증가한 버전·순번으로 다음 서명 발행물을 준비해야 새 설치·갱신 검증이 계속된다. 만료되거나 네트워크가 끊겨도 이미 설치한 규약은 보존한다. 콘텐츠 자동 갱신은 Python 관리 코드를 교체하지 않는다.

규약은 연구·개발 초안이다. 기존 49/53개 기능 설계 검토, 72개 규칙·193개 뜻 항목과 합성 사례 검증은 보존하며, 공개 배포 성공을 한국어 이해도 개선이나 전문가 승인으로 확대하지 않는다.

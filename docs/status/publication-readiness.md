# 게시 전 상태를 확인했다

2026-10-13에 사용자가 현재 확장본의 커밋·푸시를 승인했다. 아래 점검은 승인 전 준비 상태를 보존하며, 실제 게시 결과는 후속 기록으로 남긴다. 대화에 제공된 AGENTS.md는 커밋 생성 전에 사용자 확인을 요구한다. 자동 목표 계속 실행 메시지를 해당 승인으로 해석하지 않는다.

원격 저장소 `project820/korean-protocol`은 비공개이며 기본 브랜치는 `main`이다. 이번 확인에서 원격 `main`은 초기 초안 `0d3e855654834855dc86cae94ad0c9f96a664c0f`였고, 확장본은 로컬 `codex/protocol-system-design` worktree에 남아 있었다. 이 점검은 원격 상태를 변경하지 않았다.

점검 시 Git의 추적 파일과 무시되지 않은 신규 파일은 374개, 총 6,132,546바이트였다. 이 수치는 이 게시 상태 문서를 추가하기 전 스냅숏이다. 평가 근거 303개를 포함하며, 초기 평가·실패 기록·재판정 이력을 보존한다. 연구 원자료 디렉터리는 기존 ignore 정책에 따라 제외하고, 기존에 포함된 연구 보고서 HTML 하나만 게시 후보로 남긴다.

후보 파일에서 OpenSSH·RSA·EC 비밀키 PEM 표제와 OpenAI·GitHub 토큰의 대표 패턴을 검사했고 일치 항목은 없었다. 이는 알려진 패턴 검사 결과이며 모든 비밀 정보가 없음을 증명하는 완전한 보안 검사가 아니다. 평가 기록에는 재현에 필요한 로컬 경로와 실행 환경 정보가 있으므로 현재 비공개 상태를 유지한다. 저장소 공개 전환을 이 커밋·푸시 승인에 포함하지 않는다.

[오프라인 설치 ZIP](../distribution/preview-package.md)은 이 저장소 전체와 다르다. 고정 허용 목록의 22개 파일만 담으며 원시 평가 실행 기록·키·자격 정보를 넣지 않는다. 패키지의 SHA-256은 `9ea66d49a45120a1cb387ad0a033fcfbc5df718584226a9d4350151aa0866be7`이다. 실제 압축 해제 후 설치·Codex 로딩·제거와 전체 테스트 134개가 통과했다.

## 승인과 배포 설정이 남았다

1. 사용자가 2026-10-13 커밋·푸시를 승인했고 확장본 `24fab97a0444dbea8f50946fa362e312ace9e4dd`를 비공개 저장소 main에 게시했다. 저장소 공개 전환은 하지 않았다.
2. 정식 자동 갱신을 발행하려면 콘텐츠의 공개·비공개 배포 범위, 실제 동일 origin HTTPS 주소, 발행자가 관리할 서명키와 공개키 지문 전달 경로를 결정해야 한다. 시험용 임시 키를 발행키로 재사용하지 않는다.
3. 실제 사용자 설치와 launchd 예약 등록은 아직 수행하지 않았다. 오프라인 미리보기와 임시 HTTPS 시험을 실제 사용자 환경의 배포 완료로 표시하지 않는다.

목차·규칙·사전·설치 도구·로컬 검증 결과는 제공했지만, 이 상태를 정식 자동 갱신 서비스나 전체 언어 효과 검증의 완료로 표시하지 않는다. 다음 배포 단계는 위 승인과 운영 설정이 마련된 뒤 실행한다.

# 요구사항과 검증 상태

0.2 연구·개발 초안의 규칙 세 개와 사전의 뜻 16개를 보완했다. 실제 LLM 출력의 제한 명령형에는 평정 이견이 남았으므로 의미 보존 효과가 입증된 완성 규격으로 표시하지 않는다.

[2026-10-13 완료 감사](completion-audit-20261013.md)는 배포 연결 외에 KP-KO-001의 조사·논항 적용 조건도 보완 대상으로 확인했다. 현재 규칙에 대한 재검토에서 고정 사례 30개의 의미 기대값은 타당했지만 두 사례의 전용 규칙 매핑은 미확인으로 남았다.

이후 [조사·논항 조건 보완](../../evaluation/role-refinement-20261013/report.md)으로 두 매핑을 해소했다. 같은 고정 사례 30개와 최소 24칸의 규범 검토가 통과했고 기능 대응 49/53개를 유지했다. 보완된 프로필의 실제 Sol/high 진단에서는 미적용·적용 각 세 출력이 모두 의미를 보존했으며 개선 효과를 주장하지 않는다.

## 현재 통합 결과를 기록한다

한국어 규칙 72개와 작성 사례 257개, 사전 뜻 항목 193개와 작성 사례 454개를 통합했다. 별도 기능 검토는 독립 사례 83개와 공통 회귀 1개를 구분했다. STE 기능 49/53개(92.45%)가 대응 검토를 통과했고 1.1·5.1·6.3·6.6은 부분 대응으로 남았다. 이 비율은 전체 완성도나 실제 언어 성능을 뜻하지 않는다.

배포 기능을 통합한 시험 287개가 통과했다. 검사기 43개·런타임 118개·평가 실행기 8개·패키지 생성기 7개·설치 메뉴 20개·에이전트 설치기 30개·발행 도구 13개·Actions 배포 20개·장기 보관 14개·예약 실행 14개를 포함한다. jsonschema 4.26.0으로 Draft2020-12 메타스키마와 두 사전 JSON을 검증했다. 런타임 의존성을 추가하지 않았다.

[이전 프로필의 실제 설치 시험](local-install-smoke.json)에서 임시 사용자·프로젝트 설치 후 실제 Codex loader가 72개 규칙을 읽었다. 반복 설치·오프라인 실행·사용자 내용 보존을 확인했다. 실제 게시자 키와 HTTPS 릴리스 운영, 갱신 스케줄 등록은 수행하지 않았다.

[후보 평가](../../evaluation/llm/candidate-validation-report.md)의 새 12개 사례에서 원래 평정의 의미 만점은 미적용 12/12·적용 11/12였다. 후속 [교차 검토](../../evaluation/llm/permission-adjudication.md)에서 v07의 감점 근거와 사전 기준 적용에 이견이 확인됐다. 원래 점수는 보존하고 확정된 의미 오류나 성능 저하로 단정하지 않는다. 기존 생성 12개와 편집 26개의 통과는 개발회귀이며 새 독립 표본으로 합산하지 않았다. 전문가 자문과 사람 독해 시험은 수행하지 않았다.

Sol 호출이 처리 불가 오류를 반환하면 사용자 지시에 따라 OpenCodex의 Opus로 이관한다. `Selected model is at capacity`를 로컬 디스크 부족으로 판정하지 않는다. 정제 프로필의 첫 Sol 호출은 이 오류로 실패했고, 원래 네 평가 조건을 모두 Opus/high 요청으로 대체했다. 실패 1회와 대체 4회를 기록했으며, 오류를 의미 평가 점수에 포함하지 않았다.

[정제 프로필 실행](../../evaluation/llm/rule-refinement-20261012/report-ko.md)은 편집 26개·생성 12개의 의미를 보존했고 생성 2개에는 간결성 보완점이 남았다. 보완 6개는 두 조건 모두 통과했다. 재사용 입력·비눈가림 평정·단일 배치의 한계를 기록했으며 전체 사전 적용은 시험하지 않았다. [과거 평가 재현 안내](historical-verification.md)는 변경 전 원본을 지정하는 검사 명령을 제공한다.

## 초기 검증 계획을 보존한다

[독립 어휘 평가](../../evaluation/lexicon-independent/report.md)의 고정 합성 문맥 40개에서 직접 뜻 연결은 19개, 미연결은 19개, 미확정은 2개였다. [한국어 독립 사례 보완](../../evaluation/korean-independent/report.md)은 31개 중 30개가 교차 검토를 통과했다. 최소 24칸의 사례 연결은 갖췄지만 일부 전용 규칙의 조건 공백은 남았으며, 전체 한국어 관문의 완료로 표시하지 않는다.

후속 [제한 반복 진단](../../evaluation/llm/permission-diagnostic-20261012/report.md)에서는 미적용·적용 양쪽에서 같은 어형 변이가 관측돼 후보 프로필의 인과적 실패를 확정하지 않았다. [HTTPS 시험](../distribution/https-smoke.json)은 로컬 443 포트 권한으로 실행되지 않았으며, 별도 로컬 설치에서 두 사전의 위치와 해시는 확인했다. 당시 진단에서는 규칙·프로필과 기존 점수를 변경하지 않았다. 이후 규칙 두 개를 정제한 결과는 별도 프로필 해시로 평가한다.

## 변경과 게시 범위를 기록한다

새 체계는 `codex/protocol-system-design` 통합 worktree에서 작성한다. 병렬 worktree의 소유 파일을 복사해 통합하며, 원래 checkout과 원격 `main`의 초기 초안은 보존한다. 2026-10-13 사용자 승인 후 확장본 24fab97을 비공개 저장소 main에 푸시했다. 실제 사용자 전역 설정은 변경하지 않았다.

## 첫 지원 범위를 구분한다

사용자가 선택한 Codex·Claude Code의 지속 적용을 먼저 구현한다. 대화형 앱용 프로필은 함께 설계하되, 공식 자동 동기화 경로가 확인되지 않은 웹·모바일 앱을 자동 갱신 지원으로 표시하지 않는다. 이 구분은 전체 목표의 축소나 모든 호스트의 지원 완료를 뜻하지 않는다.

[사전 개발 재점검](../../evaluation/lexicon-refinement-20261012/report.md)은 변경된 뜻 다섯 개를 재대조한 뒤 33/40 연결을 유지했다. 최초 독립 점수 19/40과 원본 10개 파일을 보존했으며, 재사용 입력의 개발 수치를 새 독립 효과로 주장하지 않는다. Sol 서비스 제한 뒤 Opus/high 요청으로 재점검을 마쳤다.

[후속 HTTPS 실행](../distribution/https-transport-verification.md)은 Python 3.11의 임시 CONNECT 프록시에서 16단계를 통과했다. 서명된 콘텐츠의 수동·호스트 시작 자동 갱신, 잘못된 CA·서명 거부, 서버 중단 뒤 정상본 유지를 확인했다. 직접 443 바인딩, 공개 릴리스 운영, 예약 등록의 성공으로 확대하지 않는다.

[오프라인 패키지](../distribution/preview-package.md)는 저장소 없이 설치하는 미서명 ZIP이며 독립 구성 검토와 추출 후 실제 설치 시험을 통과했다. 현재 프로필의 실제 Codex 로딩을 확인했고 공개 릴리스·원격 자동 갱신 활성화는 완료로 표시하지 않는다.

첫 지원 환경은 사용자 선택에 따라 Codex·Claude Code로 정했다. [코딩 에이전트 검증](../distribution/coding-agent-support.md)은 Claude의 사용자·프로젝트 설치, 실제 로더의 72개 규칙 읽기와 서명 갱신 시험을 추가했다. 전체 모델 응답의 준수를 입증한 것으로 확대하지 않는다.

저장소 주소와 설치 요청만으로 에이전트가 설치·확인을 수행하는 경로를 첫 배포 방식으로 정했다. 개발 중에는 저장소를 비공개로 유지하고 개발 완료 후 공개한다. 공개 시점에 맞춰 서명 발행키·HTTPS 배포 경로를 연결하며 현재 미리보기는 자동 갱신을 끈다.

[발행 도구](../distribution/publisher.md)는 원본·생성물 검사 후 서명 입력을 만들고 외부 서명을 검증해 정적 배포 폴더를 생성한다. 최초·후속 발행과 두 호스트 서명 설치를 임시 키·상태에서 확인했다. 공개 서버·정식 키·예약 갱신 운영은 남아 있다.

[서명 설치 연결](../distribution/signed-install.md)은 간편 설치기에서 서명 검증·지속 관리 코드·실행 시 갱신과 예약 파일 생성을 연결했다. 실제 예약 등록과 운영 endpoint 연결은 아직 수행하지 않았다.

사용자 선택에 따라 [GitHub Actions·Pages 배포](../distribution/github-actions-pages.md)를 준비했다. 서명키를 main 전용 환경 Secret에 등록하고 실제 비공개 서명 실행과 두 호스트의 검증·설치·제거를 확인했다. 저장소는 비공개이며 Pages 게시 스위치는 꺼져 있다. 장기 발행 이력 보존과 실제 공개 게시·예약 갱신 운영은 남아 있다.

[후속 예약 등록 시험](../distribution/scheduler-registration-verification.json)은 별도 임시 Codex 홈에서 실제 macOS 등록·실행·해제를 확인했다. 갱신 시각 전에는 종료 코드 0으로 끝났고 미공개 서버 조회 실패 시에는 종료 코드 3으로 끝나면서 기존 규약을 유지했다. Python의 fork 이후 시스템 프록시 호출도 제거했으며 전체 시험 후 새 충돌 보고서는 없었다. 앞선 미등록 기록은 당시 상태로 보존한다. 공개 릴리스의 예약 갱신과 재로그인·절전 복귀 검증은 남아 있다.

[새 합성 문맥 12개의 사전 조회 진단](../../evaluation/llm/lexicon-usage-20261013/report-ko.md)은 두 사전 원본을 제공한 실제 실행과 파일 조회를 확인했다. 두 조건 모두 의미 보존은 12/12·편집 행동은 11/12였고, LX12에서 불필요한 확인 질문이 남았다. 전체 사전 제공·관련 항목 조회·표본 의미 판정을 구분하며 개선 효과나 전체 목표 완료를 주장하지 않는다.

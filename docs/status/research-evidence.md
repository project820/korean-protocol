# V7 이전의 연구와 검증 근거

이 문서는 기존 README의 0.3.0 연구·평가·배포 설명을 보존한다. 각 링크의 날짜·프로필 해시·시험 범위가 근거의 적용 범위이며 현재 V7의 효과나 발행을 검증한 결과가 아니다. 현재 상태는 [요구사항과 검증 상태](requirements.md), V7 결정은 [채택 기록](../../experiments/v7/adoption.md)을 따른다.

## 대응 목표와 검증 상태

아래 수치와 모델 평가는 V7 채택 전 0.3.0 검증 기록입니다. 당시 ASD-STE100 Issue 9의 작성 기능 53개 중 49개가 기능 대응 검토를 통과했습니다(92.45%). 나머지 4개는 부분 대응입니다. 이 비율은 규약 전체의 완성도나 사전 충족률, LLM 정답률을 뜻하지 않습니다.

당시 한국어 규칙 72개와 사전 뜻 항목 193개를 작성했습니다. 작성 사례는 규칙 291개·어휘 454개이며, 별도 기능 검토에는 독립 사례 83개와 공통 회귀 1개를 사용했습니다. 당시 통합 자동 테스트 361개가 통과했으며 이를 0.7.0 검증 결과로 옮겨 쓰지 않습니다.

[별도로 고정한 어휘 문맥 40개](../../evaluation/lexicon-independent/report.md)에서는 사전의 표적 뜻과 직접 연결한 항목이 19개(47.5%)였습니다. 미연결 19개와 미확정 2개를 분모에 남겼습니다. 이는 해당 합성 표본의 사전 수록 범위이며, 규약의 문장 허용률이나 실제 업무 전체의 어휘 충족률은 아닙니다. 식별자·단위의 미등재와 일반 용어의 뜻 정의 공백을 구분합니다.

[사전 보완 후 개발 점검](../../evaluation/lexicon-refinement-20261012/report.md)에서는 같은 40개 문맥 중 33개가 연결됐습니다. 미연결 5개와 미확정 2개를 그대로 남겼으며, 이 수치는 공백을 보고 보완한 뒤 같은 입력으로 확인한 결과입니다. 새로운 독립 평가 점수로 사용하지 않습니다.

[한국어 독립 사례 보완](../../evaluation/korean-independent/report.md)에서는 31개 중 30개가 교차 검토를 통과했고, 해석이 갈린 1개는 근거에서 제외했습니다. 8개 범주의 정상·오용·원문 유지 사례를 연결했습니다. 그 후 진행·결과 상태와 사동·피동의 역할 보존을 규칙 두 개에 보완했습니다. 최소 사례의 충족을 전체 한국어 구문의 검증으로 확대하지 않습니다. 이 사례 검토는 실제 LLM 실행 시험과 구분합니다.

[실제 모델 평가](../../evaluation/llm/candidate-validation-report.md)의 새 12개 사례에서 원래 평정의 의미 보존 만점은 미적용 12개·적용 11개였습니다. 다만 적용 결과 1개의 제한 명령형을 감점한 근거에 [교차 검토 이견](../../evaluation/llm/permission-adjudication.md)이 있어 확정된 의미 오류나 성능 저하로 단정하지 않습니다. 알려진 생성 12개·편집 26개 회귀의 통과를 새 독립 검증의 성공으로 합산하지 않습니다.

[정제 프로필의 후속 실행](../../evaluation/llm/rule-refinement-20261012/report-ko.md)은 Sol 서비스 제한 뒤 네 조건을 Opus/high로 전환했습니다. 편집 26개와 생성 12개는 의미를 보존했고 생성 2개에는 간결성 보완점이 남았습니다. 보완 6개는 미적용·적용 모두 통과했습니다. 재사용 입력과 조건을 아는 검토자의 평정이므로 독립 효능이나 모델 간 성능 차이를 입증하지 않습니다. 이 실행에서 모델은 사전 전체를 읽지 않았습니다.

[새 문맥의 사전 조회 진단](../../evaluation/llm/lexicon-usage-20261013/report-ko.md)에서는 12개 합성 사례에 두 사전 원본을 제공하고 실제 조회 기록을 확인했습니다. 미적용·적용 모두 의미 보존은 12/12였지만, 한 사례에서 불필요한 확인 질문을 해 편집 행동은 11/12였습니다. 사전 조회를 출력 개선으로 계산하지 않으며 전체 193개 뜻의 효능을 입증했다고 주장하지 않습니다.

한 번 설치한 규약은 로컬에 보존하고, 네트워크나 업데이트 서버가 없어도 기존 내용을 사용할 수 있게 설계합니다. 자동 갱신은 검증된 콘텐츠만 교체하며, 실패하면 기존 버전을 유지합니다. 호스트별 지침 저장 방식과 제한이 달라 지원 범위는 [호스트 지원표](../../docs/distribution/host-support.md)에 따릅니다.

이전 프로필을 사용한 임시 사용자·프로젝트 환경에서 실제 Codex 지침 로딩과 오프라인 실행을 확인했습니다. [과거 검사 재현 안내](../../docs/status/historical-verification.md)는 당시 원본과 현재 원본을 구분합니다. [임시 HTTPS 시험](../../docs/distribution/https-transport-verification.md)에서는 서명 확인·호스트 시작 자동 갱신·오프라인 유지를 확인했습니다. [공개 배포 예약 실행 시험](../../docs/distribution/public-scheduler-verification.json)은 임시 Codex 설치본에서 실제 macOS 등록·공개 endpoint 확인·해제와 원래 사용자 지침 복원을 확인했습니다. 같은 버전의 인증된 확인이며 새 버전 갱신이나 재로그인·절전 복귀 시험은 아닙니다.

현재 내용은 연구·개발 초안입니다. 규칙과 사전의 구조 검사는 독자가 더 잘 이해한다는 증거가 아니며, 실제 모델 평가도 시험한 모델·입력 범위 안에서만 해석합니다. 한국어학·군사 전문가의 실제 자문과 독자 비교시험은 수행하지 않았습니다.

[조사·논항 조건 보완](../../evaluation/role-refinement-20261013/report.md)은 조사가 이미 있는 문장에서 역할을 바꾸는 편집을 명시적으로 다룹니다. 고정 사례 30개의 규범 검토와 보완된 프로필의 세 사례 실제 모델 진단을 구분해 기록했으며, 미적용·적용이 모두 통과한 결과를 개선 효과로 주장하지 않습니다.

규칙을 제안할 때에는 문맥, 원문, 대체문, 유지할 뜻, 적용되지 않는 반례를 함께 제시합니다. 이미 명확해서 고칠 필요가 없는 문장도 사례로 남깁니다.

## GitHub 소개문

GitHub 저장소의 짧은 소개에는 다음 문장을 사용합니다.

> LLM의 한국어 출력을 위한 표현 규약을 만듭니다. 어휘·문장·지시·보고의 기준과 지속 적용 도구를 제공합니다.

## 공개 배포와 오프라인 설치

[첫 공개 발행](../../docs/distribution/github-actions-pages.md)은 버전 `0.2.0`, 순번 `1`의 서명·Pages 게시·발행 영수증·장기 보관을 완료했습니다. [익명 HTTPS 확인](../../docs/distribution/public-download-verification.json)은 인증 없이 받은 파일 9개의 서명과 콘텐츠 해시를 확인했습니다. [설치 패키지 안내](../../docs/distribution/preview-package.md)의 ZIP은 자동 갱신을 끄고 사용하는 미서명 로컬 설치 경로입니다.

[편집 정보 범위 보완](../../evaluation/llm/editing-scope-20261013/report-ko.md)에서는 문장 수정에 필요 없는 실행 정보를 묻지 않도록 KP-EDIT-002를 정리했다. 기존 12개를 다시 실행한 개발 회귀에서 의미 보존은 수정 전·후 모두 12/12였고, 행동 적절성은 11/12에서 12/12로 바뀌었다. 새 독립 평가나 일반적인 개선 효과로 해석하지 않는다. 새 프로필로 자동 테스트 287개와 임시 Codex·Claude Code 설치·보존·제거 시험이 통과했다.

[새 과제 경계 평가](../../evaluation/llm/scope-holdout-20261013/report-ko.md)는 규약을 읽지 않은 작성자의 합성 사례를 실행 전 교차 검토한 뒤 고정했다. 새 12개에서 미적용·적용 모두 의미 보존과 과제 수행을 통과했고, 불필요한 확인과 근거 없는 확정은 없었다. 한 배치의 동률 결과이므로 일반적인 개선 효과나 사람의 이해도 향상을 입증하지 않는다.

[공개 전 실제 서명물 검증](../../docs/distribution/current-actions-verification.md)은 GitHub Secret으로 서명한 규약을 두 임시 호스트에 설치하고 HTTPS 수동·시작 wrapper 확인, 잘못된 CA·서명 거부, 오프라인 보존을 검증했다. 실제 발행물은 같은 버전 확인이며 시험용 키의 다음 버전 업그레이드와 구분한다. 이 기록의 미공개 상태는 첫 공개 발행 이전의 상태다.

2026-10-13 소유자는 직접 작성한 코드·문서·규약·사전에 MIT License를 통일 적용하도록 결정했습니다. 앞선 기록의 라이선스 미정·저장소 비공개·Pages 미게시 상태는 이 결정과 첫 공개 발행 이전의 상태입니다.

[적용 설정](../../docs/distribution/application-controls.md)에서 규약 on/off와 높임말 on/off를 독립적으로 바꾼다. 새로 쓰는 기본 응답에는 높임말을 쓰지 않는다. 명료한 상태에는 `표기된 담당자 없음.` 같은 짧은 형식을 쓸 수 있으며 V7은 대상·조건·기한을 찾기 쉬운 배치를 우선한다. [표현 운영 지침](../../docs/spec/control-expression.md)은 생략 가능한 정보와 반드시 남길 조건·양태·행위자를 구분한다.

[압축 문체의 실제 1:1:1 비교](../../evaluation/llm/controlled-korean-20261013/report.md)는 미적용·보완 규약·STE 원칙의 한국어 적용을 같은 입력으로 실행한 기록이다. 이 평가에 사용한 보완 규약은 0.3.0·순번 2로 공개했으며, 공개 콘텐츠 7개의 바이트가 원본과 일치한다. 공개 발행은 이 비교의 표본·평정·한계를 바꾸지 않는다.

[어휘의 실제 허용 뜻 사용](../../evaluation/llm/lexical-meaning-use-20261013/report.md)은 사전 정의를 참고해 고정한 24개 문맥에서 뜻 실현·직접 용어 사용·예외 보존·미확정 처리를 구분했다. 최초 비교의 사용자 스킬 유입을 수정하고 모든 조건을 다시 실행했다.

# 독립 검토와 수정 기록

이 문서는 0.7.0의 검토 상태와 그 이전에 발견한 결함·수정 경위를 구분한다. 현재 원본은 `0.7.0-draft`, 공개 서명 콘텐츠는 `0.7.0·순번 3`, 엔진은 `0.2.0`이다. 규칙 72개·규칙 사례 296개·사전 193뜻을 제공하며 현행 기능 대응은 설계 49개·검증 0개·부분 4개다.

[V7 검증](v7-verification.md)은 채택한 이전 보완본 r2와 설치 프로필의 범위 복원 검토를 기록한다. 압축을 강화한 r3는 채택하지 않았다. [후속 저장소 점검](../maintenance/repository-inventory.md)은 공개 다운로드·패키징·검사기·발행 코드와 Linux·macOS CI 결과를 기록한다. 사용자 패키지 `v0.7.0`은 `7e01d53`에서 고정했으며 이후 main의 문서 개정은 기존 ZIP에 자동 반영되지 않는다.

아래는 0.2.0 개발 단계의 발견·요청·수정 기록이다. 당시 257개 사례와 49/53 검토를 현재 V7의 사례 수나 검증 점수로 사용하지 않는다. 과거 요청 문장을 현재 미해결 결함 목록으로 읽지 않으며 현행 남은 검증은 [요구사항과 검증 상태](requirements.md)를 따른다.

## 어휘의 활용형을 재검토한다

통합 검토에서 `KPL-0150`의 “발생하세요”, `KPL-0151`의 “증가하세요”, `KPL-0152`의 “감소하세요”를 발견했다. 해당 항목의 비의지적 현상 의미에는 명령형을 기계적으로 생성할 수 없다. 작성 담당에게 모든 항목의 실제 활용형과 명령 가능성을 재검토하도록 요청했다. 별도 OpenCodex Opus 검토는 일반 언어·용례 범위에서 진행한다.

## 설치기의 중단 복구와 동시 갱신을 검토한다

통합 담당의 Astra 검토에서 초기 `runtime/kproto.py`의 배타 생성 잠금 파일은 프로세스 강제 종료 후 남아 `recover`까지 막는다는 결함을 발견했다. 잠금 구현의 수정과 실제 하위 프로세스 종료 시험을 요청했다.

같은 검토에서 다운로드 전에 읽은 설정으로 나중에 갱신을 적용하면 도중에 설정한 버전 고정이나 자동 갱신 해제를 놓친다는 결함을 발견했다. 적용 직전 잠금 안에서 최신 설정을 확인하고, 시도 기록만 현재 설정에 병합하는 수정과 경쟁 상태 시험을 요청했다.

당시 이 두 항목은 수정·재시험 전까지 미해결로 처리했다. 현재 런타임은 `flock` 기반 잠금과 적용 직전 설정 재확인을 사용하며 `tests/test_runtime.py`는 강제 종료 후 잠금 해제·복구와 다운로드 중 pin/off 변경을 검사한다. 당시 일반 언어 검토와 보안·인증·빌드·패키징 검토는 구분해서 수행했다.

## 규칙 용례의 숨은 전제를 제거한다

OpenCodex Opus의 언어 교차 검토에서 `KP-PROC-006`의 같은 입력·공유 문맥에 서로 다른 판정이 붙은 결함과, `KP-SYN-008`의 조건을 확정 진술로 바꾼 정상 예문을 발견했다. 부적합 후보 사례 72개는 다른 정상 예문을 암묵적으로 참조해 사례 자체에 없는 사실을 기대 출력으로 요구했다. 작성 담당에게 명시적인 원문과 후보 평가 작업을 문맥에 넣고 각 사례의 판정 근거를 따로 작성하도록 요청했다.

이 수정으로 규칙·사례·상세 문서의 해시가 바뀌면 기존 기능 검토와 실행 프로필을 갱신한다. 초기 26개 모델 시험은 해당 스냅샷의 결과로 보존하며 수정된 최종 프로필의 평가로 대신 사용하지 않는다.

## 언어 검토 의견도 근거를 확인한다

어휘 리뷰의 “줍니다” 일괄 배제 제안은 채택하지 않는다. “줄다”의 공식 활용형이라는 확인 근거가 있으며, 모든 독자가 이를 다른 뜻으로 먼저 읽는다는 증거는 제시되지 않았다. 문맥에서 의미가 충돌하는 경우를 별도로 다룬다.

통합 검토자가 “를”을 끝모음으로 잘못 판단했던 설명은 정정한다. “를”에는 받침 ㄹ이 있다. 인용된 활용형에 조사를 다시 붙여 어색해진 문장은 인용 표현의 역할을 풀어 쓰는 방식으로 고친다.

## 신규 생성의 목적 적용을 보완한다

최종 후보의 편집 26개 시험에서는 핵심 의미를 보존했지만, 신규 생성 12개 시험에서는 짧은 경고의 과설명과 필수 정보의 확인 누락이 남았다. 코딩 프로필의 보고 안내가 모든 발화에 적용되는 문제를 확인해 작업 결과 보고로 조건을 한정한다. 기존 규칙에 있는 목적별 작성과 필수 정보 확인을 실행 지침 앞부분에서 분명하게 안내하고, 이 수정본은 새 해시로 별도 평가한다. 기존 결과를 새 프로필의 성능으로 표시하지 않는다.

## 같은 '용량'이 다른 대상을 가리키는 사례를 남긴다

진행 보고에서 모델 서비스의 `Selected model is at capacity` 오류를 “용량 제한”이라고만 설명해 컴퓨터 저장공간 부족으로 해석되는 실제 혼동이 발생했다. 보고에는 “Sol 모델 요청을 처리할 수 없다는 서비스 오류가 반환됐다”처럼 문제가 생긴 대상과 관측한 결과를 적어야 한다. 이 응답만으로 서버의 내부 원인, 디스크 상태나 계정의 사용 한도를 확정하지 않는다. 이 사례는 관측한 표현 실패이며 독립 성능평가의 표본 수에 합산하지 않는다.

## 정제 규칙과 사전의 후속 검토를 기록한다

Opus/high는 두 규칙과 새 뜻 16개의 변경분을 검토하고 동기화·복구·처리율의 경계, 비착용 진행 사례, 사례 유형 집계와 명확화 과제 설명을 보완하도록 판정했다. 상위 에이전트는 동기화를 지속적·양방향 작업으로만 제한하지 않도록 수정 범위를 정했다. 검사·검증과 복구·복원의 자동 치환을 막는 문맥 사례를 추가하도록 했다.

착용 결과가 공유 문맥에서 확정된 “안경을 쓰고 있습니다”를 더 길게 고치라는 의견은 반영하지 않았다. 그 문장은 해당 문맥의 뜻을 보존하며, 표현 길이를 늘리는 것만으로 명료성이 개선됐다고 판정하지 않는다. 이미 명확한 문장을 유지하는 어휘 사례도 그대로 두고 원문 유지 시험으로 표시한다.

규칙 작성 사례는 비착용 진행 유지 한 건을 추가해 257개가 됐다. 독립 기능 검토는 기존 256개 사례의 불변과 새 사례의 문맥을 대조했으며, 기능 대응 49/53개를 유지했다. 정제 프로필의 SHA256은 `282cbdcea153cf6eec5361eda2431c7d2ee2c66d04e71c3fca19639a875c46ee`로 실제 모델 평가 이후 변경하지 않았다.

실제 평가의 첫 Sol 요청은 서비스 처리 제한으로 출력 없이 실패했다. 사용자 지시에 따라 네 조건 모두 OpenCodex의 Opus/high로 실행했고 실패·전환·출력·평정을 [평가 기록](../../evaluation/llm/rule-refinement-20261012/report-ko.md)에 보존했다. 원격 제공자 내부 모델 식별은 관측하지 않았으며 디스크 부족으로 설명하지 않는다.

사전 후속 수정은 193개 뜻과 작성 사례 454개로 고정했다. 처리율의 백분율 용례는 시간당 완료량 뜻의 허용 예문에서 빼고, 명확한 다른 뜻을 유지하는 예외로 기록했다. 기존 177개 뜻 객체와 398개 작성 사례는 보존했고, 당시 193개 뜻의 Draft2020-12 스키마 검사가 통과했다. 이 기록의 스키마 실행과 현재 표준라이브러리 정적 검사기의 범위를 구분한다.

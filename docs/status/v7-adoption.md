# 0.7.0은 사용자가 선택한 V7 r2 구조를 통합한다

현재 원본은 `0.7.0-draft`, 공개 서명 콘텐츠는 `0.7.0·순번 3`, 관리 엔진은 `0.2.0`이다. [사용자 패키지 v0.7.0](https://github.com/project820/korean-protocol/releases/tag/v0.7.0)은 설치 도구·안내 원본 `7e01d53`에서 발행했으며 이후 main의 문서 개정은 기존 ZIP에 자동 반영되지 않는다.

사용자는 비교 화면의 'KP V7 이전 보완'을 선택하고, 원문보다 짧게 만드는 r3 보완은 채택하지 않았다. 이 선택은 표현 방식의 채택이며 의미 보존이나 독자 이해가 입증됐다는 판정은 아니다. 과거 실험 수치와 미채택 당시의 기록은 [V7 실험 기록](../../experiments/v7/README.md)에 그대로 남긴다.

## 고정 실험본과 배포 프로필을 구별한다

선택한 실험본은 [profile-v7-r2.md](../../experiments/v7/profile-v7-r2.md)이며 SHA-256은 `58413651917d5a335f7c900acc54a65d856aedc07c16448e1691ff28daf29cd1`이다. 37,348바이트인 실험 파일을 그대로 설치하면 기존 프로필 예산을 넘는다. 배포본은 같은 V6 부모의 72개 규칙과 r2의 구조 지침을 [정식 원본](../../specification/rules.json)에 통합해 다시 컴파일한다.

전체 요구사항·적용 조건·예외는 원본과 [상세 규약](../../pack/protocol.md)에 남긴다. 34개 규칙의 `publication.text`는 적용 조건·예외를 통합한 배포용 표현이며, 각 `source_sha256`은 해당 규칙의 `requirement`·`conditions`·`exceptions`를 키 정렬·UTF-8·공백 없는 JSON으로 직렬화한 해시다. 원본이 바뀌어 해시가 달라지면 컴파일러는 쓰기 전에 실패한다. 이 검사는 검토가 낡았는지 식별하며 두 표현의 의미 동등성을 자동 입증하지 않는다.

원문의 의미 한정을 보존하기 위해 내부 프로필 예산을 28KiB에서 30KiB로 조정하고 엔진 0.2.0에서 지원한다. 설치 시 전체 관리 지침은 32KiB 이하여야 하며 Codex의 기존 32KiB 호스트 설정은 확대하지 않는다. 원본 파일과 배포 표현은 규칙 ID로 연결하며 세 프로필 모두 72개 규칙을 담는다. 실험 파일과 배포 프로필은 바이트가 같지 않으므로 고정 실험의 평점을 배포본에 그대로 이전하지 않는다.

## r2 구조 지침을 정식 규칙에 연결한다

| r2 지침 | 정식 규칙 | 보존하는 판단 기준 |
| --- | --- | --- |
| V7-01과 대상 우선 보완은 대상을 먼저 드러낸다. | KP-TXT-001은 진행 상태·수행자·출처·제한도 남긴다. | 긴급 안전 경고는 위험 행동 앞에 둔다. |
| V7-02는 선택지별 속성을 나눈다. | KP-TXT-002는 대상·수행자와 행동·기한을 독립 항목으로 둔다. | 없는 속성·담당자를 만들지 않고 공통 규칙은 선택지 밖에 둔다. |
| V7-03은 조건과 후속 흐름을 묶는다. | KP-PROC-003과 KP-SYN-007은 공통·개별·미정 범위를 구별한다. | 자동 처리를 독자 지시로 바꾸거나 미정 범위를 제목으로 확정하지 않는다. |
| V7-04는 수량 기준을 먼저 표시한다. | KP-NUM-001은 대상·기준 단위·역할을 명시한다. | 허용 한도를 실제 수용량·달성량으로 바꾸지 않는다. |
| V7-05와 시간 구절 보완은 기한을 독립 표시한다. | KP-NUM-006은 원문의 기산 사건부터 경계까지 시간 구절을 보존한다. | 없는 기산 사건·날짜·근무시간을 보충하지 않는다. |
| V7-06은 기본·예외 기한을 나눈다. | KP-PROC-004는 대체·추가 관계와 후속 처리 범위를 유지한다. | 대체 기한을 중복 의무로 바꾸지 않는다. |
| V7-07은 문체와 짧은 상태 표현을 정돈한다. | KP-KO-005·006과 KP-TXT-006은 문체 설정·발화 기능·한정을 유지한다. | 이미 명확한 문장을 제목으로 과도하게 나누지 않는다. |
| V7-08과 마지막 대조는 구조·의미를 따로 점검한다. | KP-EDIT-001은 앵커와 기산 사건을 양방향 대조한다. | 구조·간결성보다 의미 보존을 우선한다. |

부모 프로필의 초기 앵커·범위·주체·편집·양태 규칙을 먼저 읽도록 컴파일 순서도 유지한다. r3의 원문 대비 길이 합격선이나 축약을 강제하는 지침은 통합하지 않는다.

## 검증 범위를 한정한다

다섯 작성자 회귀 사례는 대상 우선 배치와 진행 상태, 기산 사건, 공통 규칙의 범위, 자동 처리, 대체 기한을 기록한다. 사례와 컴파일 테스트의 통과는 실제 모델 의미 보존이나 독자 효과를 뜻하지 않는다. 실제 컴파일 프로필의 모델 실행 결과와 설치 검증은 발행 기록에서 별도로 확인해야 한다.

원본이 바뀌어 과거 기능 대응 검토의 해시는 현재 원본과 일치하지 않는다. 기존 49개 `verified` 상태는 `designed`로 돌리고 과거 검토 파일은 보존한다. 현재 대응표는 설계 49개·검증 0개·부분 4개다. 규칙은 72개이며 규칙 작성자 사례는 다섯 회귀를 포함한 296개다. 사전은 기본 159뜻·분야 34뜻과 어휘 작성자 사례 454개를 유지한다. 현재 원본의 기능 대응 검증 수를 과거 49/53 결과로 보고하지 않는다. [실제 발행·갱신 기록](../distribution/public-0.7.0-verification.md)과 [V7 검증](v7-verification.md)은 배포 성공과 언어 검증의 한계를 각각 기록한다.

# Korean Protocol 체계 설계와 배포 구현 계획

> **2026-10-12 계획을 보존한다.** 아래 지시·출발점·예정 작업은 당시 계획이며 현재 작업 지시가 아니다. 0.7의 구현과 남은 검증은 [현재 상태](../../status/requirements.md)에서 확인한다.

> 작업 에이전트는 `superpowers:subagent-driven-development` 절차를 적용한다. 사용자의 명시적 요청에 따라 파일 소유권과 Git worktree를 분리해 병렬 실행한다. 커밋과 원격 게시 없이 로컬 산출물을 먼저 통합한다.

**목표:** ASD-STE100 Issue 9의 작성 기능에 90% 이상 대응하고, 한국어 고유 규칙·통제 어휘·용례·판정 기준·지속 설치·자동 업데이트를 갖춘 체계를 만든다.

**구조:** 규범 원본과 기계 판독 데이터, LLM용 실행 프로필, 설치·업데이트 코드를 분리한다. 규칙과 어휘는 안정적인 식별자로 연결한다. 적용률, 어휘 충족률, 실제 LLM 출력의 적합성은 서로 다른 지표로 보고한다.

**기술:** 규범은 Markdown, 교차 대응·규칙·어휘·시험 자료는 UTF-8 JSON으로 작성한다. 설치 런타임은 외부 의존성을 추가하지 않는 Python 표준 라이브러리를 우선 검토한다. 대상 도구의 공식 설정 방식을 확인한 뒤 어댑터를 구현한다.

## 현재 출발점

원격 `project820/korean-protocol`의 `main`은 `0d3e855`이며 12개 방향 검토 규칙만 있다. 설치 도구·사전·검증 도구는 없다. 이번 작업은 앞선 초안을 전체 체계로 확장한다. 90% 달성은 현재 미검증이다.

## 단계 1은 전체 설계와 실제 내용을 작성한다

- [x] 공식 Issue 9 원문에서 9개 절·53개 규칙의 식별자를 확인한다. 영문 원문 전체나 사전을 번역·복제하지 않고, 비교에 필요한 기능명과 한국어 설계 대응을 기록한다.
- [ ] 모든 원본 규칙에 대응·한국어 재설계·부분 대응·미대응의 판정을 둔다. 언어 차이를 이유로 분모를 임의로 줄이지 않는다.
- [ ] 한국어의 조사·생략·수식·부정·양태·종결형과 문서 유형별 세부 규칙을 실제 용례와 함께 작성한다.
- [ ] 통제 어휘를 의미 단위로 모델링하고 일반 어휘·전문 명사·전문 동사·프로젝트 용어·단위와 식별자 처리 방식을 설계한다.
- [ ] 지원 환경, 설치 지속성, 업데이트 선택·검사·적용·복구·버전 고정을 명세한다. 설치 프로필만으로 LLM 준수를 보장한다고 주장하지 않는다.

## 단계 2는 규약을 검사 가능한 배포물로 만든다

- [ ] 규칙 ID 중복, 교차 대응 참조, 어휘 의미·용례 참조를 검사하는 실패 시험을 먼저 작성한다.
- [ ] 검사기를 구현하고 깨진 참조·누락된 예외·불완전한 용례를 거부하는지 검증한다.
- [ ] 설치의 멱등성·사용자 설정 보존·오프라인 사용·변조된 업데이트 거부·실패 시 기존 버전 유지·롤백에 대한 실패 시험을 작성한다.
- [ ] 명세한 지원 환경의 어댑터와 업데이트 기능을 구현한다. 시험용 임시 홈과 로컬 릴리스로 검증하며 사용자 전역 설정은 자동으로 변경하지 않는다.
- [ ] 규칙·어휘·프로필을 일관된 버전의 배포물로 구성한다. 본문 설정과 별개로 규약을 매번 LLM 컨텍스트에 공급하는 조건을 검증한다.

## 단계 3은 목표를 감사한다

- [ ] 53개 기능 대응을 각각 근거·규칙·용례와 대조한다. 기능 대응률의 90%는 최소 48개 완전 대응으로 정의하되, 필수 영역의 공백은 총점으로 덮지 않는다.
- [ ] 어휘 충족률과 도메인 범위를 별도로 평가하고, 사전 항목 수를 90%의 대리 지표로 사용하지 않는다.
- [ ] 의미 보존·대상 식별·조건·금지·확실성에 관한 독립 사례를 시험한다. 형식 검사 통과를 실제 LLM의 의미 적합성으로 보고하지 않는다.
- [ ] Sol이 작성한 일반 산출물은 OpenCodex의 Claude Opus high로 교차 검토한다. 설치·업데이트·패키징 보안은 Astra high로 검토한다.
- [ ] 실제 설치 대상과 릴리스 경로에서 지속 사용·자동 업데이트·복구 증거를 확인한다. 미검증 항목이 남으면 목표를 완료로 표시하지 않는다.

## 통합 방식

각 에이전트는 지정 worktree의 소유 파일만 수정한다. 다른 에이전트의 작업을 되돌리지 않고, 커밋·푸시·삭제·의존성 설치를 하지 않는다. 통합 담당은 산출물의 변경 목록과 내용을 검토한 뒤 통합 worktree로 복사하고 검증한다. 기존 12개 규칙은 새 체계의 대응과 변경 이력을 남겨 연결한다.

## 남겨야 할 판정

모든 분야에서 오해가 전혀 발생하지 않는다는 절대 보장은 검증할 수 없다. 따라서 지원 범위와 적용 조건을 밝히고, 뜻의 변형·허락과 명령의 혼동·확실성 변경 등 구체적인 실패를 탐지하고 줄였는지 검사한다. 이 한계가 규칙 작성이나 배포 구현을 축소하는 이유가 되어서는 안 된다.

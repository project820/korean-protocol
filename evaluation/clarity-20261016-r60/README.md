# 60차 후보는 비교를 완료했으나 수락 기준을 통과하지 못했다

60차 비교는 생성 576건과 출력을 가린 검토 192건을 오류 없이 완료했다. 비교 상태는 완료이고 수락 판정은 미통과다. 별도 평가에서 후보의 의미 보존은 92건 통과·2건 실패·2건 미해결이다. Opus 5.5의 low·medium 설정에서는 STE 대비 명료성 패수가 승수보다 많다. 사용자는 60차 결과와 관계없이 이 후보를 v0.9.0으로 배포하도록 지시했다. 이 문서는 수락 기준 미충족 사실을 그대로 기록한다.

## 별도 평가 결과

후보는 네 설정 모두에서 v0.8.0보다 명료성 승수가 많다. STE 대비로는 Sol 두 설정에서 승수가 많고 Opus 두 설정에서 패수가 많다. 의미 판정 2건은 원래 검토가 증거 인용 오류로 거부돼 새 익명 검토로 대체했다.

후보의 실패·미해결은 두 사례에서 나왔다.

- **E03 실패:** 전화로 안내받은 폐기물 반출 별도 조건을 ‘문서 기재 아님’으로 단정했다. 같은 사례의 다른 출력 1건은 ‘표의 기재 사항이 아니라’는 표현 때문에 미해결이다.
- **E12 실패:** 원자료가 승인 주체를 정하지 않았는데 고객지원팀에 승인을 요청하라고 썼다. 다른 출력 1건은 ‘확인된 현황’ 아래에 분류 미확정을 범위 한정 없이 적어 미해결이다.

## 후보의 변경 내용

59차에서 Sol이 STE에 밀린 판정을 원자료와 함께 읽고, 독자가 행동을 찾는 배치를 보완했다. 실행할 행동이 둘 이상이면 행동마다 줄을 나눈다. 원문이나 요청이 선후를 정한 절차는 한 단계에 행동 하나를 두고, 결과에 따른 조치가 정해진 단계 아래에 그 분기를 둔다. 독자가 응답할 확인 요청과 회신 대기는 한곳에 모으고, 수신자가 할 행동은 요청문으로 쓴다.

의미 경계도 보완했다. 주어 없는 원문 규칙을 앞 문장 담당자의 표제 아래로 옮기지 않는다. 표의 ‘포함’을 특정 금액에 포함된다고 좁히지 않는다. ‘세 문서가 서로 다르다’처럼 묶은 판단은 묶인 항목마다 확인한다. 전언·추정값으로 만든 합계는 확인된 값과 섞지 않고, 세금 조건이 다른 값의 합계에 한쪽 조건을 붙이지 않는다.

후보 `candidate/SKILL.md`의 SHA-256은 `4d8a6838bbad48e7a0120b366599ad7084b77d26f29c92de9ce8028873d4a7b2`이다. 평가 문구·모델·추론 설정·반복 수·대조군·수락 기준은 59차와 같다.

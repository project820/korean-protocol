# 편집 정보 범위 변경의 한정 기능 검토

STE 기능 설계는 49/53(92.45%) 통과를 유지하며 1.1·5.1·6.3·6.6의 네 부분 대응은 분자에서 제외한다. 이 수치는 고정 사례와 규범 매핑의 설계 검토 결과이며 실제 모델 의미 보존 성공률이 아니다.

## 기준과 독립성

검토자는 KP-EDIT-002와 신규 작성자 사례 작성에 참여하지 않은 edit_scope_proof 에이전트다. 기준 커밋은 `45f86c668d4eb82ddc2aad6d210655e0d2c91c70`이며, 커밋의 기능 검토 원문은 `functional-review-before.json`에 바이트 그대로 보존했다. `evaluation/functional-review.json`의 이전 revision 이력은 남기고 `editing_scope_refinement`만 추가했다.

소스 규칙 72개를 ID별 JSON 객체로 비교한 결과 KP-EDIT-002의 requirement와 exceptions만 달라졌고 나머지 71개와 변경 규칙의 다른 필드는 같았다. Markdown의 규범 변경은 같은 두 문장뿐이며 신규 규칙이나 STE 대응 관계는 만들지 않았다. 기존 작성자 사례 257개는 ID별 전체 객체가 같고 신규 3개만 추가됐다.

## 변경 기능의 내용을 검토했다

4.2와 9.1이 선택한 EDIT-001·EDIT-002·EDIT-004·SYN-001·SYN-002·SYN-009·KO-001의 요구·조건·예외·예문을 읽었다. 선정 규칙의 R/K/N 사례 21개와 KP-C-001·008·017, 신규 EDIT002-01~03을 합친 27개를 읽었다. EDIT-001 태그로 연결된 다른 기존 사례는 기준과 객체 동일성을 확인했으며 모두 새로 내용 판정했다고 주장하지 않는다.

4.2의 FC-4-2는 공유 주체와 현재 도면 하나를 유지하고 FC-4-2-U는 미확정 검토자를 확인하게 한다. EDIT002-03에서도 문장 편집만 맡겼다는 사실이 검토자 이름을 창작할 근거가 되지 않는다. SYN-001·002와 KO-001의 회복 가능한 생략 허용도 유지된다.

9.1의 FC-9-1은 인과·시점·미완료를 보존한 구조 변경이며 FC-REV-CANDIDATE는 명시 원문의 허락을 복구한다. FC-REV-NOORACLE은 사실 복구에 필요한 원문·관측이 없으므로 계속 확인 대상이다. EDIT002-01은 실제 원문과 잘못된 후보가 구별되어 있어 기준 간격을 몰라도 간격 자체의 상한을 상대 허용 오차 ±2 mm로 복구할 수 있다. EDIT002-02는 실제 12 mm 측정값의 합격 판정을 요청하므로 기준 간격을 확인해야 한다.

새 예외는 뜻을 유지할 수 있는 편집에서 실행용 정보의 질문만 면제한다. 편집 자체에 필요한 주체·조건·기준을 선택해야 할 때는 요구문과 기존 적용 조건이 확인을 요구한다. 세 신규 사례는 개발용 LX12 기반의 작성자 회귀이며 독립 사례나 실행 표본으로 세지 않는다.

## 이월 근거를 검사했다

나머지 51개 각각에 대해 target_rule_ids의 전체 규칙 객체와 해당 규칙에 연결된 기존 작성자 사례 객체를 기준 커밋과 비교했다. `evaluation/functional-cases.json`과 `specification/ste-crosswalk.json`은 파일 바이트가 같았고, 따라서 case_ids가 가리키는 독립 입력·기대값·거부 출력·대응표도 같았다. 이 검사 후 51개 검토 객체 전체를 그대로 이월했으며 네 fail도 변경하지 않았다. 신규 3개가 EDIT-001/SYN-001을 통해 다른 기능과도 연결되므로 전체 현재 작성자 집합이 동일하다는 주장은 하지 않는다.

기능 독립 사례는 83개와 별도 공통 회귀 1개 그대로다. 작성자 사례는 260개이고 독립 분모에 포함하지 않는다. 4.2·9.1의 rationale과 reviewer만 새 판정으로 바꾸고 원문 근거는 보존된 기준 파일에서 추적한다.

## 한국어 고정 사례의 규범 매핑을 이월했다

`korean-review-after.json`은 기존 `evaluation/role-refinement-20261013/korean-review-after.json`을 덮어쓰지 않고 만든 새 기록이다. 30개 review의 rule_ids와 related_but_incomplete_rule_ids에는 EDIT-002가 없으며 모든 선정·관련 규칙 객체가 기준과 같았다. 한국어 cases·supplement·replacement-negation과 이전 세 review·report 파일은 기준 커밋의 바이트와 같고 이전 검토의 저장 해시와도 일치했다.

범위 경계가 직접 드러나는 KI-OMI-03·ASP-03·PAS-01·PAS-03·CON-01·CON-03·SUP-ASP-01의 문맥·원문·후보·기대값을 읽어 전역 EDIT-002 변경의 간접 효과를 대조했다. 공유된 대상·위치나 문장 편집에 불필요한 미상 시간·행위자·번호 형식·반대 조건·완성 수는 현재 문장을 유지하거나 같은 뜻으로 편집하는 데 필요하지 않다. 새 예외와 충돌하지 않으므로 30개 검토 객체를 그대로 이월했다. KI-NEG-03 제외, 고정 30개, 8범주 24칸을 유지하며 이는 새로운 독립 성공이나 모델 성능 개선이 아니다.

## 실행한 검증과 한계

`python3 -B validation/check.py --root . --json --require-coverage 0.9`는 종료 코드 0, ok=true, errors=0, designed_count=49, verified_count=49, partial_count=4, semantic_verified=false를 반환했다. 이 명령은 기록된 검토의 구조·참조·현재 해시를 확인하며 내용 검토를 독립적으로 재실행하지 않는다.

별도 Python 비교는 git show로 기준 파일을 읽고 JSON을 ID별로 연결하여 71개 규칙·257개 기존 작성자 사례·51개 이월 검토와 30개 한국어 이월 검토의 동일성을 assert했다. 고정 독립 입력과 대응표는 바이트 비교했고 한국어 입력은 이전 source_hashes의 SHA-256과도 대조했다. 새 모델 호출, 새 holdout 수집, 독자 이해도 실험, 원본 영어 규칙 재조사는 이 검토에서 수행하지 않았다.

# 한국어 독립 사례의 보완 결과

별도 작성자가 고정한 31개 합성 사례 중 30개가 독립 에이전트 검토를 통과했다. 8개 범주의 정상·오용·원문 유지라는 최소 24칸에는 모두 통과 사례가 연결됐다. 이 결과는 규범 사례의 판정 근거이며 실제 LLM 출력 성능이나 사람의 이해도를 입증하지 않는다.

## 이전 증거와 새 사례를 구분한다

[보완 전 감사](../../docs/spec/korean-gate-audit.md)는 기존 증거 24칸 중 14칸만 충족한다고 판정했다. 그 결과는 덮어쓰지 않았다. 새 작성자는 기존 규칙·예문을 읽기 전에 [24개 사례](cases.json)를 고정했고, root가 확인한 시상·피동·사동의 세부 공백을 [6개 보충 사례](supplement.json)로 채웠다. 조회 전 고정은 작성자의 수행 기록이며 사람 평가나 무작위 표본 추출을 뜻하지 않는다.

OpenCodex를 통해 요청한 Opus 5.5/high가 사례 의미와 실제 규칙 조건을 대조했다. [첫 검토](review.json)는 23개를 통과시켰고, [보충 검토](supplement-review.json)는 6개를 통과시켰다. 응답에서 요청 모델명을 확인한 경로 기록과 실제 서버 내부 모델 식별은 구분한다.

KI-NEG-03의 ‘하나만 열어도 된다’는 충분성·상한·재량 해석에 이견이 있어 충족 근거에서 제외했다. 원래 파일은 유지하고, 한정된 관찰 시간 안의 발생 횟수가 0회인 [KI-NEG-04](replacement-negation.json)를 새로 고정했다. 이 사례는 [별도 검토](replacement-negation-review.json)를 통과했다. 원래 사례의 문장을 언제나 잘못된 한국어라고 판정하거나 기존 점수를 조용히 바꾸지 않았다.

## 규칙 연결의 한계를 남긴다

일부 사례는 한국어 구문의 전용 규칙보다 KP-EDIT-001·003의 포괄적인 의미 보존·정보 추가 금지에 의존한다. 보충 검토는 ‘안경을 쓰고 있다’의 결과 상태와 사동·피동 역할 보존에 맞는 규칙 조건이 더 구체적이어야 한다고 지적했다. 이 의견과 개별 조건의 간접 연결은 검토 JSON에 보존했다. 최소 사례 24칸의 충족을 모든 한국어 세부 기능이나 전체 관문의 완료로 승격하지 않는다.

첫 검토의 family_coverage에 있는 부정 범주 keep 값은 개별 KI-NEG-03의 needs_revision 판정과 일치하지 않았다. 집계는 그 요약 값을 사용하지 않고 개별 사례의 판정으로 다시 계산했다. [집계 JSON](review-summary.json)은 제외한 사례, 사용한 사례, 규칙·검토 파일의 해시를 기록한다.

`python3 evaluation/korean-independent/verify-review.py --rules-root evaluation/baselines/20261012-before-rule-and-lexicon-refinement`는 검토 당시 보존한 규칙 해시·검토 대상 해시·실제 규칙 ID·31개 식별자·개별 판정에서 파생한 집계를 확인한다. 이 명령은 검토자의 한국어 판단을 자동으로 재실행하지 않는다. 원래 24개 고정은 `python3 evaluation/korean-independent/validate.py --verify`로 확인한다. 보충·대체 사례의 고정 절차는 각 plan과 check 파일에 남아 있다.

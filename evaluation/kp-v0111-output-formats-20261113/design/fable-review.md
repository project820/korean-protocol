## 화면 골격과 컨트롤 어휘를 고정한다

화면은 아래 순서로 쌓는다. DOM 순서, 읽기 순서, 초점 순서를 이 순서와 같게 둔다. 내용이 없는 구획은 만들지 않는다.

1. **제목(`h1`):** 화면이 답하는 내용을 '한다' 문장 하나로 쓴다.
2. **대상·범위(`p`):** 적용 대상과 조작하면 바뀌는 결과를 한 줄로 쓴다. 문서 전체에 걸리는 고지는 이 줄 아래에 한 번 쓴다.
3. **결과 패널(`section`):** 현재 입력에 따른 결과를 보인다.
4. **입력 패널(`section`):** 결과를 바꾸는 입력을 모은다.
5. **규칙·산출식(`section`):** 입력과 무관하게 성립하는 규칙 전체와 산출식을 쓴다.
6. **참고(`section`):** 출처, 계산에 넣지 않은 항목, 저장·전송 여부를 쓴다.

패널과 구획의 제목(`h2`)은 '월 전력 소비량'·'사용 조건'·'산출식'·'참고'처럼 명사구 표지로 쓴다.

### 두 패널은 리플로 격자에 둔다

결과 패널과 입력 패널만 격자에 넣는다. 넓은 화면에서는 결과가 왼쪽, 입력이 오른쪽에 온다. 좁은 화면에서는 결과가 위, 입력이 아래에 온다.

```css
.panel_layout {
  display: grid;
  gap: var(--space-4);
  grid-template-columns: repeat(auto-fit, minmax(min(22rem, 100%), 1fr));
  align-items: start;
}
.panel_layout > * { min-inline-size: 0; }
```

- 열 수는 이 격자가 정하고, 시각 순서는 DOM 순서가 정한다. 미디어 쿼리의 열 전환과 `order`·`grid-area`·`row-reverse`·`float` 재배치는 쓰지 않는다.
- 격자 규칙에는 배치 속성만 둔다. 색·테두리·그림자·글자 규칙은 `.panel`에 둔다.
- 스크롤은 문서가 맡는다. 넓은 표의 가로 스크롤 영역만 예외다.
- 패널 높이는 내용이 정한다. `sticky`·`fixed` 고정은 초점이 있는 입력과 오류를 가릴 수 있어 쓰지 않는다.

### 결과 패널은 값·근거·조건 순서로 쓴다

1. **제목:** 결과의 이름을 쓴다.
2. **결과값(`output`):** 수치 결과는 값과 단위를 쓴다. 상태 결과는 '누가 무엇을 한다' 문장 하나로 쓴다. 조치가 순서대로 이어지면 번호 목록으로 쓴다.
3. **근거 한 줄:** 수치 결과에는 현재 값을 대입한 산출식을 쓴다. 상태 결과에는 그 결과를 정한 조건을 쓴다.
4. **조건·경고:** 현재 결과에 걸린 기한·예외·금지를 쓴다. 다른 선택에서만 성립하는 규칙은 규칙·산출식 구획에 둔다.
5. **가정:** 결과값을 바꾸거나 적용 범위를 한정하는 가정을 '가정:' 표지와 함께 쓴다.

- 결과 패널은 하나만 둔다. 조건마다 패널을 나누면 독자가 결과를 여러 곳에서 찾게 된다.
- 결과값·조건·경고·가정은 항상 펼쳐 둔다.
- 결과 패널은 짧게 쓴다. 규칙 표와 긴 설명은 아래 구획으로 보낸다. 좁은 화면에서 입력을 바꾸는 동안 결과값이 화면에 남게 하려는 것이다.
- 입력 오류가 있으면 결과값 자리에 '계산을 보류한다'를 쓴다.
- `output`의 `for`에 결과를 정하는 입력의 `id`를 적는다. 결과 영역에 `aria-live="polite"`를 둔다.

### 입력 패널은 결과를 바꾸는 입력만 둔다

- 판단을 크게 바꾸는 입력을 앞에 둔다. 핵심 입력은 세 개 안으로 둔다. 나머지는 같은 패널 아래쪽의 '세부 조건' 묶음에 둔다.
- 한 입력은 라벨, 컨트롤, 힌트, 오류 순서로 DOM에서 붙여 둔다.
- 라디오·체크박스 묶음은 `fieldset`과 `legend`로 묶는다. 단일 입력에는 `label`을 잇는다.
- 라벨은 '소비전력(kW)'처럼 이름과 단위를 명사구로 쓴다. 라벨 자리에 placeholder를 쓰지 않는다.
- 선택지 문구는 원자료의 표현을 쓴다.
- 초기 선택은 원자료가 먼저 적은 경우로 둔다. 원자료에 초기값이 없는 수치에는 값을 넣고 힌트에 '가정'을 쓴다.
- 버튼은 초기화 하나만 패널 끝에 둔다.

| 입력의 성격 | 컨트롤 | 지킬 점 |
|---|---|---|
| 서로 배타적인 선택지 2~4개 | 라디오 묶음 | 선택지를 모두 펼쳐 보인다. |
| 서로 배타적인 선택지 5개 이상 | `select` | 첫 항목은 실제 선택지로 둔다. '선택' 같은 빈 항목을 두지 않는다. |
| 켜고 끄는 조건 하나 | 체크박스 | 라벨에 켠 상태의 뜻을 쓴다. |
| 원자료가 경계로 나눈 조건 | 라디오 묶음이나 `select` | 범주를 그대로 선택지로 둔다. 수치 입력으로 바꾸면 원자료에 없는 경계값 판정이 생긴다. |
| 수치 | `input type="number"` | `min`·`max`·`step`과 단위를 정한다. |
| 천 단위 구분이 필요한 금액 | `input type="text"`와 `inputmode="numeric"` | 입력하는 동안에는 문자열을 고쳐 쓰지 않는다. 입력이 끝난 뒤(`change`)에 구분 기호를 맞춘다. |
| 근거 있는 범위 안의 수치 탐색 | `input type="range"`와 숫자 입력 한 쌍 | 두 컨트롤이 같은 값을 보인다. 원자료에 없는 범위는 '가정'으로 표시한다. |
| 다른 선택에 딸린 조건 | 같은 컨트롤을 `disabled`로 둔다. | 적용 조건을 힌트에 쓴다. 컨트롤을 숨기지 않는다. |

# D. output-formats.md L2 절 보강안

**대상: `references/output-formats.md` 85행 뒤(L2 절 끝)에 추가. 83행 마지막 문장 "Mermaid를 표시할 수 없는 환경에서는 …"은 삭제하고 아래 세 번째 소절로 대체한다.**

### 내용의 구조에 맞는 형식을 고른다

| 내용의 구조 | 형식 |
|---|---|
| 같은 속성 두 개 이상을 가진 항목 세 개 이상 | 표 |
| 분기·병렬·순환이 있는 흐름, 상태 변화 | Mermaid `flowchart` |
| 주체 사이에 오간 전달의 순서 | Mermaid `sequenceDiagram` |
| 한 줄로 이어지는 순서 | 번호 목록 |
| 포함 관계나 계층(일반 텍스트 환경) | ASCII 트리 |
| 긴 조건 문장을 가진 두 대상 | 대상별 문단 |

- 표의 첫 열에는 대상을 둔다. 한 셀에는 값 하나를 쓴다. 셀이 두 문장을 넘으면 대상별 문단으로 바꾼다.
- 열은 여섯 개 안으로 둔다. 숫자 열은 오른쪽으로 맞추고 단위를 머리글에 쓴다.
- 값이 없는 셀에는 원자료의 상태를 쓴다. 예: '견적서에 기재되지 않았다.'
- 도식은 그 도식이 답하는 제목이나 문단 바로 아래에 둔다. 도식에 싣지 못한 기산점·예외는 도식 바로 아래 목록에 쓴다.

### Mermaid는 아래 문법으로 쓴다

- **종류:** `flowchart`를 기본으로 쓴다. 그 밖의 종류는 위 표의 조건이나 사용자 요청이 있을 때 쓴다.
- **방향:** 분기가 있으면 `TD`를 쓴다. 가로로 이어지는 구성 관계에만 `LR`을 쓴다.
- **노드 ID:** `A`, `B`, `C1`처럼 영문 대문자와 숫자로 쓴다. `end` 같은 소문자 예약어는 도식을 깨뜨린다.
- **라벨:** 모든 라벨을 큰따옴표로 감싼다. 행동·상태·대상은 `A["가동한다"]`, 판단은 `B{"점검 결과가 적합한가?"}`로 쓴다. 다른 도형은 쓰지 않는다.
- **라벨 안의 문자:** 라벨 안의 큰따옴표는 작은따옴표나 낫표로 바꾼다. 줄바꿈은 `<br/>`로 쓴다. 라벨은 20자 안팎으로 쓴다.
- **화살표:** `-->` 한 종류만 쓴다. 조건은 `A -->|"적합하다"| B` 형식으로 쓴다. 한 줄에는 화살표 하나를 쓴다.
- **분기:** 판단 노드에서 나가는 화살표마다 라벨을 붙인다. 갈래는 원자료가 밝힌 것만 그린다.
- **묶음:** `subgraph`는 원자료가 묶음을 밝혔을 때만 쓴다.
- **꾸밈:** `style`·`classDef`·`linkStyle`·`click`·`%%{init}%%`·이모지는 넣지 않는다.
- **크기:** 노드는 12개 안팎으로 둔다. 넘으면 질문을 나눠 도식을 둘로 쓴다.
- **점검:** 화살표마다 원문의 근거 문구를 대응시킨다. 출발 라벨, 화살표 라벨, 도착 라벨을 이어 읽어 원문과 같은 문장이 되는지 확인한다.

### Mermaid를 표시할 수 없으면 조건 목록으로 쓴다

메신저·이메일·일반 텍스트 터미널에서는 같은 관계를 들여 쓴 조건 목록으로 쓴다. 표시 여부를 모르는 Markdown 환경에서는 Mermaid 블록을 쓴다.

- **점검 결과가 적합하면** 가동한다.
- **점검 결과가 부적합하면** 담당자에게 알린다.

ASCII 도식은 포함 관계나 계층을 보일 때만 쓴다. 코드 블록 안에 들여쓰기 트리로 쓴다. 상자 테두리 그림은 한글의 글자 폭 때문에 세로선이 어긋나므로 쓰지 않는다.

```text
생산동
├─ 냉장설비
│  └─ 실외기
└─ 공조설비
```

**주의:** 위 트리의 설비 이름은 가상 예시다. 프로브 원문(회의실 예약 취소)은 스킬 예시에 넣지 않는다. 넣으면 재프로브 결과가 오염된다.

KP는 Korean Protocol이다. 사용자가 KP 적용을 명시적으로 요청한 한국어 재작성·편집·자료 기반 작성에 쓴다.

## L2란

L2는 L1 본문에 표나 Mermaid 도식을 더하는 출력 단계다. 아래 경우에 쓴다. 출처는 4A의 단계 표다.

- 같은 속성을 가진 세 항목 이상을 비교할 때
- 분기·병렬·순환이 있는 흐름을 보일 때
- 상태 변화를 보일 때
- 구성 요소의 관계를 보일 때

작성 전에 [출력 기본형](references/output-formats.md)의 L2 절을 읽어야 한다. 표나 도식이 원문에 없는 관계를 만들면 L1을 유지한다.

## L1~L4 한 줄 요약 (4A 단계 표)

- **L1:** 기본값이다. 아래 세 단계의 조건 밖에 있는 글을 KP 문단·목록·절차로 쓴다.
- **L2:** L1 본문에 표와 Mermaid 도식을 더한다.
- **L3:** 변수 조작이나 상태 전환이 이해에 필요하거나 사용자가 인터랙티브 출력을 요청하면, 외부 의존성 없는 `index.html` 하나를 만든다.
- **L4:** 사용자가 영상화·애니메이션 코드를 명시 요청할 때만, Manim 코드와 장면별 한국어 내레이션 대본, 발화만 담은 TTS 입력을 쓴다.

## L3 HTML 필수 규칙 다섯 가지 (모두 4A의 "L3 하한")

1. **단일 파일, 외부 의존 없음.** HTML·CSS·JavaScript를 파일 하나에 둔다. CDN·외부 글꼴·네트워크 호출을 쓰지 않는다. `lang="ko"`와 viewport를 둔다. (하한 1번)
2. **화면과 DOM의 순서 고정.** 제목(‘한다’ 문장 하나), 대상·범위(한 줄), 결과 패널, 입력 패널, 규칙·산출식, 참고 순으로 쌓는다. (하한 3번)
3. **초기값과 즉시 재계산.** 입력의 초기값을 원자료 값으로 채워 첫 화면에 결과를 보인다. 입력이 바뀌면 결과를 바로 다시 계산하고, 계산 버튼은 두지 않는다. (하한 4번)
4. **안전한 출력과 오류 처리.** 자료 문자열은 `innerHTML` 대신 `textContent`로 넣는다. 잘못된 입력은 그 입력 곁에 오류를 보이고 결과를 보류한다. 결과 영역에 `aria-live="polite"`를 둔다. (하한 7번)
5. **제출 전 검사.** 제출 전에 `scripts/check_html.py`를 실행한다. 밝은 배경 테마 하나로 만들고, 320px 폭에서 한 열로 바뀌게 한다. (하한 8번)

이 밖에 재사용 예제의 골격에서 시작하기(2번), 입력 유형 규칙(5번), 결과 패널 안에 조건·경고·가정 두기(6번) 같은 규칙도 같은 하한에 있다. 수행하지 않은 검사를 완료로 표시하지 않는다는 점은 5절의 제출 전 대조에 있다.

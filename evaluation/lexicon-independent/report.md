# 독립 소프트웨어·업무 어휘 문맥 평가

고정한 독립 합성 문맥 40개 중 사전 뜻의 직접 일치는 19개(47.5%)이며 미일치는 19개이고 미확정은 2개이다. 이 수치는 선정한 표적 표현·뜻의 사전 재고 연결률이며 문장의 규약상 허용률이나 소프트웨어 분야 전체의 어휘 충족률이 아니다. 이름·단위·코드 식별자의 미등재는 언어 오류를 뜻하지 않는다.

문맥은 사전·예문 조회 전에 plan.md와 contexts.json으로 고정했다. 평가자는 새 가상 상황을 직접 작성했으며 실제 사건 기록·자연 코퍼스·사람 평가를 사용하지 않았다. 표적 뜻을 하나씩 판정하므로 분모는 40개이고 각 선언 분야는 10개이다. 사전 조회 후 문맥·표적 뜻·분모를 수정하지 않았다.

평가는 core 155개 뜻과 software 22개 뜻을 읽고 의미·분야·품사·표현틀·조건·제외 뜻을 대조했다. matched는 표적 의미와 사용 범위를 기존 ID에 직접 연결한 경우이며 ambiguous는 후보가 있어도 연결 근거가 충분하지 않은 경우이다. unrelated 일반어가 상위 개념이라는 이유만으로 전문 뜻의 직접 연결을 늘리지 않았다. 행동 명사의 하다형 연결과 접근 토큰의 중심 명사 연결은 matches.json의 이유에 명시했다.

현재 파일의 버전은 모두 0.2.0-draft이며 상태는 편집 선호를 나타낸다. 직접 일치 19개는 preferred 13개와 allowed 6개로 나뉜다. schema에 approved·proposed 승인 단계가 없고 lexicon.md:42는 어떤 상태도 전문가 승인이나 독자 실험 통과를 뜻하지 않는다고 명시한다. 따라서 전문가 승인 증거가 확인된 일치 항목은 없지만 이것을 177개 항목의 거절·심사 실패 또는 승인 충족률 0%로 해석하지 않는다.

각 분야는 이번 문맥의 분석 그룹이며 사전의 domains 필드를 다시 정의하지 않는다. general 뜻은 일반 업무·기술 문맥에 적용하고 software 뜻은 소프트웨어 또는 문서관리 문맥에 한정하여 확인했다. matches.json은 후보별 원본 domains와 frame을 그대로 보존한다.

재시도(C05)는 반복하다(KPL-0116)와 가깝지만 실패 후 실행이라는 표적 표현의 대응이 정의되지 않아 미확정으로 남겼다. 검사(C07)는 확인하다·검증하다·시험하다 후보가 있으나 검사 방법과 기준 근거가 고정 문맥에 없어 단일 기존 뜻으로 확정하지 않았다. 이 두 항목은 오류 판정이 아니라 직접 사전 연결의 불확정이다.

활성·활성화, 시간 초과, 복구, 멱등성, 상관관계 식별자, 제안, 할당, 캐시, 동기화, 메시지 본문, 색인, 처리율, 지연은 해당 표적 뜻의 직접 재고 연결이 없다. 복구와 복원·재개·롤백의 범위 차이는 C08 후보 근거에 기록했다. 이는 평가 중 확인한 재고 공백이며 사전 밖 표현의 일괄 금지나 반드시 새 항목을 추가해야 한다는 요구가 아니다.

`python3 check.py`는 현재 원본 해시 일치와 40개 집계 검사에 통과했고 verification.json에 출력 증거를 저장했다. 같은 디렉터리에서 `python3 check.py`를 실행하면 문맥·계획의 고정 해시, 분모·ID 집합, 모든 후보 추출, 현재 원본 해시, 분야별 수치와 편집 상태 수치를 확인한다. --snapshot-only를 추가하면 보존한 추출 증거를 검증하되 현재 원본과의 일치는 확인하지 않는다. 이 검사는 집계와 출처 무결성을 검증하며 사람이 다시 판단해야 하는 의미 일치를 자동으로 증명하지 않는다.

다른 체크아웃의 현재 원본을 검증하려면 같은 평가 디렉터리에서 `python3 check.py --source-root '/Users/m5max/.codex/worktrees/korean-protocol-integration/ASD-STE100 Kor'`를 실행하고 인용한 경로를 해당 체크아웃으로 바꾼다. `--source-root`를 생략하면 matches.json의 과거 source_root를 사용하며 과거 기록은 수정하지 않는다. `python3 check.py --snapshot-only`는 출처 경로를 읽지 않고 보존한 입력·추출·집계를 검증하며 `--source-root`를 함께 지정해도 같은 방식으로 동작한다. 경로 지정 검사와 스냅샷 검사는 각각 verification-source-root.json과 verification-snapshot-only.json에 통과 기록을 보존했다.

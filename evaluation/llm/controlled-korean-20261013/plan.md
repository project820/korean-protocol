# 표현 체계와 문체 설정을 세 조건에서 비교한다

기준 원본은 2067f541d2cc97d94f4a8625de2015d2330aeb1b다. 미적용은 규약·사전이 없는 임시 작업 폴더, 현재 규약은 이 커밋의 coding-agent 프로필과 두 사전, 보완 규약은 수정 후 고정한 프로필과 같은 두 사전을 제공한다. 세 조건에 같은 공개 입력·순서·프롬프트를 사용한다. 프로필 차이는 정책·문체 변경을 함께 포함하므로 높임말 제거만의 효과와 규범 보완만의 효과를 분리 추정하지 않는다.

## 실행 전에 입력과 판정 기준을 고정한다

별도 작성자는 기존 규약·평가·사전을 보지 않고 합성 사례 12개와 의미 기준을 만든다. 원문 조건·수량·시점·확실성·허락과 의무, 행동 순서·동시성, 인용문과 요청 장르를 보존하는지 확인한다. 사용자 요청 자체에 '짧게/높임말 제거'를 공통 강제하지 않아 개입 차이를 가리지 않는다. 단 명시적인 높임말 장르 요구와 인용 보존 사례를 예외 시험으로 넣는다.

조건을 모르는 검토자가 공개 문맥과 고정 정답을 바탕으로 의미·요청 수행·조건과 단계 구조·불필요한 덧붙임을 각각 판정한다. 짧다는 이유만으로 성공 판정을 하지 않는다. 높임말 여부는 별도 측정이며, 다른 조건의 높임말을 의미 실패로 계산하지 않는다. 문체 효과가 눈에 보인다는 결과와 읽는 사람의 이해도 개선을 구분한다.

최소 수락 기준은 12개 모두 필수 의미와 과제 수행을 보존하는 것이다. 절차 사례에서 조건·순서·동시성을 보존하고 독립 행동을 식별할 수 있어야 한다. 보완 조건은 별도 장르·인용 예외 외에 높임 종결형을 쓰지 않아야 한다. 보완 출력에 의미 오류나 실행 구조 실패가 있으면 입력·원출력·실패 평정을 남기고 규약을 수정한 뒤 같은 입력을 재실행한다. 이 재시험은 개발 회귀로 표시한다. 합격을 위해 기준이나 분모를 바꾸지 않는다.

## 실제 모델과 증거를 보존한다

기존 scope-holdout-20261013/run.py 실행기를 재사용한다. 전역 Codex 설정·지침을 읽지 않는 임시 CODEX_HOME과 기존 인증 참조를 사용한다. OpenCodex 경로로 gpt-6.1-sol/high를 요청하고 조건별로 새 프로세스를 실행한다. capacity로 중단되면 실패 기록을 보존하고 세 조건 전부 anthropic/claude-opus-5-5/high로 맞춘다. FALLBACK 출력은 유효 비교에서 제외한다. 환경 오류에는 effort를 올리지 않고 원인을 수정해 별도 시도로 남긴다.

실행기·계획·사례·정답·프로필·사전·공개 프롬프트의 해시를 실행 전에 고정한다. 원시 응답과 도구 trace를 보존하며, 외부 파일·인터넷·다른 모델 호출을 발견하면 해당 실행을 비교에서 제외한다. read-only sandbox는 작업 폴더 밖 읽기를 물리적으로 차단한다는 보장이 아니므로 trace 확인 범위를 밝힌다. CLI에 드러나지 않는 상위 공급자와 내부 전환 여부는 추정하지 않는다.

초기 세 조건 비교 뒤 새로운 보류 사례 12개를 별도 작성해 같은 세 조건으로 확인한다. 첫 표본의 실패를 고친 규약은 새 표본 결과와 구분한다. 단일 모델·작은 합성 표본이며 실제 전문가 검토나 독자 실험은 아니다. 모든 시행과 재시도를 보고하고 일반적인 STE 동등성이나 공식 한국어판 지위를 주장하지 않는다.

## 적용 설정은 언어 평가와 별도로 시험한다

protocol on/off는 호스트의 관리 지침을 활성/비활성으로 전환한다. honorifics on/off는 활성 규약의 높임 종결형을 설정한다. 서명된 캐시는 수정하지 않고 로컬 적용 설정을 분리한다. OFF 상태의 갱신·재설치·롤백이 규약을 다시 켜지 않는지, ON 복원이 사용자 지침과 신뢰 정보를 보존하는지 시험한다. 이미 읽은 지침은 진행 중인 대화에서 지울 수 없으므로 엄격한 미적용 비교는 새 격리 프로세스로 실행한다.

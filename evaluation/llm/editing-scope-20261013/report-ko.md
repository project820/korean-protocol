# 편집 범위 수정 후 허용 오차의 불필요한 질문이 이 회귀에서 해소됐다

기존 합성 사례 12개와 기존 실행 전 정답 검토를 재사용한 개발 회귀를 실행했다. 이 표본은 독립 검증이 아니다. OLD와 NEW는 모두 전체 사전을 제공한 treatment 조건이며, 빈 baseline은 사용하지 않았다. 기존 evaluation/llm/lexicon-usage-20261013/run.py와 공개 프롬프트는 수정하지 않았다.

OLD는 git 45f86c6의 coding-agent 프로필이고 NEW는 PROFILE_READY 이후 컴파일한 프로필이다. OLD 프로필 SHA-256은 c3171890012b5eb60414fdf61c4656c68c24b3c984ba7e16b194f88c72bbfd9b이며 NEW는 786cddbe11388e15c0776204c76fa2fd1ff2f32885447a1343a048477c10025b이다. 두 조건의 정확한 프롬프트 해시는 c4ff0b8e482f0f58cab06ddd5b7b0bf29c91044ab6900fb5790822b333f1ef23으로 같다. 각 조건의 freeze-manifest와 실행 입력 snapshot을 따로 보존했다. 사례·정답·계획·manifest는 모델 작업 폴더 밖에 두었다.

Sol/high 실제 CLI 호출은 OLD 다음 NEW 순서로 두 번만 실행했다. 두 호출 모두 종료 코드 0과 출력 구조 검사를 통과했다. capacity 오류나 FALLBACK 표시는 없었고 Opus 호출과 재시도는 없었다. 요청 경로는 localhost OpenCodex subscription_router이며 실제 상위 공급자·fallback은 CLI에서 관측되지 않았다. 사용자·전역 설정을 불러오거나 변경하지 않았다.

두 조건에서 제공한 AGENTS.md와 두 사전의 파일 집합·내용 해시는 실행 전후 같다. 각 trace의 명시적 도구 명령 여섯 개는 작업 폴더의 사전 상대 경로만 자료로 읽었다. OLD는 pwd와 사전 파일 목록도 조회했다. 실제 반환 내용에서 OLD의 구조화 항목 20개, NEW의 구조화 항목 15개가 동결 사전 내용과 같음을 확인했다. 사전 ID의 자기 보고와 반환 기록은 의미 적용이나 전체 사전 이해를 입증하지 않는다.

두 stderr는 resource=filesystem backend=seatbelt reason=operation_not_permitted path=unknown이라는 sandbox 경고를 남겼다. Python 명령은 /tmp/xcrun_db 캐시 생성 거부와 macOS Darwin 캐시·임시 경로 경고도 반환했지만 종료 코드는 0이었다. trace-audit.json은 정확한 경고 원문과 명령 문맥을 보존했다. 명시적인 외부 과제 자료·네트워크·다른 모델·에이전트 호출은 관측되지 않았지만, 경로를 알 수 없는 CLI 내부 시도와 전체 OS 읽기 범위는 검증하지 못했다. read-only sandbox를 cwd 읽기 경계로 해석하지 않는다.

blind-review-input.json은 조건 이름·모델명·원본 사례 ID·reason·사전 ID·trace를 숨기고 공개 문맥과 기존 gold, A/B action·text만 담았다. 대응 키는 private-condition-key.json에 따로 저장했다. 실행 담당자는 의미를 평정하지 않았다. 독립 검토자는 12개 전체의 의미 보존과 행동 적절성을 평가했고, LX12의 상대 허용 오차 ±2 mm 보존과 불필요한 확인을 구별했다. LX09는 복수 행동이 허용되어 행동 구분력이 낮다.

LX12의 원문은 “간격 오차는 ±2 mm 이내로 관리한다.”이며, 잘못된 후보는 실제 간격을 2 mm 이하로 바꿨다. 수정 전 출력은 “±2 mm의 허용 오차를 적용할 기준 간격은 얼마인가요?”라고 물었다. 수정 후 출력은 “덮개와 지지판 사이의 간격 오차는 ±2 mm 이내로 관리한다.”로 바로잡았다. 기준 치수를 만들지 않고 상대 오차를 복구했다.

이 결과는 알려진 편집 실패 한 건의 개발 회귀 개선이다. 단일 배치이고 실패를 보고 바꾼 규칙과 재사용 사례이므로 일반 효능·독자 이해도·새 문맥의 안정성을 입증하지 않는다. 실제 검사 합격 판정과 미상 주체를 확인하는 신규 작성자 반례는 규범 검토를 받았지만 이 12개 모델 입력에 추가하지 않았다. 다음 독립 평가는 편집·실행·판정 과제를 구분한 새 문맥으로 이 경계를 확인해야 한다.

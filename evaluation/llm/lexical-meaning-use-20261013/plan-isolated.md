# 분야별 출력에서 사전의 허용 뜻을 사용하는지 검증한다

이 평가는 사전의 실제 사용에 대한 의도적 적합성 표본이다. 독립적인 자연 말뭉치의 어휘 충족률이나 한국어 전체의 90%를 측정하지 않는다. 사전의 preferred·allowed는 프로젝트 내부 상태이며 전문가 승인으로 해석하지 않는다.

## 출력 전에 표본과 기준을 고정한다

Opus/medium 작성자는 정의·품사·활용·표현틀·조건·제외 뜻을 제공받는다. 기존 사전 예문·규약·프로필·모델 출력은 제공하지 않는다. 네 분야(소프트웨어 실행, 업무 조정, 데이터 작업, 사양 문서)에 각6개를 배정하며, 분야별4개는 지정된 허용 뜻,1개는 미등록 이름·리터럴의 보존 예외,1개는 요청을 수행하려면 실제로 뜻을 확인해야 하는 경우다.

공개 입력은 id·facts·request뿐이다. 분야·범주·대상 뜻 ID·정답은 평가 자료로 분리한다. 별도 검토자가 입력과 사전 계약에 비춰 정답을 검토하고 수정은 실행 전에 마친다. 생성 뒤 정답·사전·프로필을 바꾸지 않는다. 작성 원본과 수정 기록을 보존한다.

24개를12개씩 두 묶음으로 나눠 미적용·KP·STE 원칙 조건을 모두 실행한다. 여섯 호출은 각각 새 임시 홈·프로젝트를 사용하며 같은 묶음의 공개 입력·프롬프트·순서는 같다. KP에는 현재 프로필과 사전 두 개를 제공하고, STE 조건에는 독립적인 한국어 STE 원칙 지침만 제공한다. 미적용에는 둘 다 제공하지 않는다. 대상 뜻의 풀이를 정답처럼 주입하거나 사전 조회를 강제로 요구하지 않는다.

요청 모델은 OpenCodex의 gpt-6.1-sol/high다. capacity 실패는 기록을 보존하고 비교 조건 모두를 Opus/high로 전환한다. 다른 실패는 원인을 분류한 뒤 처리하며 성공한 답만 골라 바꾸지 않는다. 원시 trace·출력·파일 해시를 보존한다. 읽기 전용 sandbox가 전체 파일 읽기를 격리한다고 주장하지 않는다. 명시적 외부 자료 접근이 있으면 해당 실행은 유효 비교에서 제외한다.

## 의미·표현·예외를 구분한다

평정자는 조건 이름·모델명·사전 조회 이력을 보지 않고 고정된 입력·기준·사전 뜻 계약과 출력만 대조한다. 표면 문자열 일치만으로 뜻 사용을 판정하지 않는다. 활용·부정·시상·논항·조건을 함께 판단한다. 같은 단어가 잘못된 완료·원인·허락을 주장하면 오용으로 처리한다.

허용 뜻 표본에서는 의미를 정확히 전달한 비율과 실제로 해당 용어를 허용 뜻으로 사용한 비율을 분리한다. 정확한 풀어쓰기는 의미 충족이지만 직접 용어 사용은 아니다. 허용 뜻에 맞더라도 요청한 과업을 수행하지 않거나 필수 정보를 잃으면 별도 실패다.

미등록 예외는 정확한 원형 보존과 과업 수행을 판정한다. 사전에 없다는 이유로 자동 오용 판정하거나 임의 번역하면 실패다. 미확정 문맥은 필요한 확인과 한계 보존을 판정한다. 불필요한 정보까지 요구하거나 뜻을 임의 확정하면 실패다.

모든24개 문맥을 공개하고 분야별 분포와 범주별 분모를 유지한다. 직접 용어 사용 비율을 높이기 위해 풀어쓰기·미확정·미등록 사례를 총표에서 제외하지 않는다. 직접 사용16개, 예외4개, 미확정4개의 성격이 다르므로 합계는 별도 표로 함께 제시한다. 이 표본에서 KP의 필수 의미·과업·예외 처리 실패가 하나라도 있으면 실패를 명시하고 전체 관문 통과로 평균내지 않는다.

글자 수는 공백·문장부호를 포함한 별도 관측치다. 짧다는 이유로 의미 누락을 허용하지 않는다. 사전을 마운트한 사실·실제 조회·허용 뜻의 올바른 사용·전체 사전 효능을 구분한다. 이 평가는 배치당 한 번 실행하므로 반복 안정성이나 인간 이해도 개선을 증명하지 않는다.

## 분모를 사전에 확정한다

별도 지표 검토자는24개 전체를 허용 뜻 사용률의 분모로 부르는 것을 거부했다. 다음 분모를 사용한다.

| 지표 | 분자와 분모를 정의한다. |
| --- | --- |
| 허용 뜻 충족 | 정확한 대상 의미 실현(풀어쓰기 포함)/16이며 분야별 분모는4다. |
| 직접 용어 사용 | 지정 항목을 실제 서술에 올바르게 사용/16이며 단순 언급·인용·파일명·식별자 안의 문자열은 제외한다. |
| 예외 보존 | 미등록 이름·리터럴을 올바르게 보존/4다. |
| 미확정 처리 | 요청에 필요한 뜻 확인 또는 한계 보존/4다. |
| 전체 문맥 처리 | 위 범주별 의미·과업·명확성 처리 성공/24이며 분야별 분모는6이다. |
| 대상 의미 오용 | 대상 뜻이나 필수 의미를 바꾼 문맥/24와 해당 ID·이유를 함께 보고한다. |

주 독자는 네 분야의 일반 업무 사용자이며 전문 지식이 필요한 뜻은 공개 사실로 경계를 제공한다. 출처는 정의를 참고해 새로 작성한 합성 문맥이다. 별도로 사전 개발과 독립적인 자연 말뭉치 표본이라고 표시하지 않는다. 범주별 분모·단일 실행·조건·프로필을 결과 표에 함께 적는다. 모든 출력 어휘나193개 전체 뜻의 완전한 의미 검사는 이 표본의 측정 범위가 아니다.

## 격리 결함 뒤 모든 조건을 다시 실행한다

최초 ste-b1이 외부 사용자 스킬을 읽어 원래 제외 조건에 걸렸다. 최초 여섯 원출력과 동결 파일은 그대로 두고 최종 비교에서는 사용하지 않는다. 새 실행기는57개 사용자·기본 스킬을 명시적으로 비활성화하고 플러그인·hook 설정을 실행별로 끈다. 실제 app-server inventory는57개 발견·활성0개였으며 모델 진단에서 AGENTS의 표식은 로드되고 사용 가능한 스킬 목록은 비어 있었다.

이번 재실행은 답안 내용·점수를 보고 선택한 재시도가 아니다. 정답·입력·규약·사전·모델·공개 프롬프트를 유지하고 미적용·KP·STE의 두 묶음을 모두 다시 실행한다. 새로운 사용자 스킬이 추가되면 고정 목록 밖이므로 다시 목록을 검증해야 한다. 파일 읽기는 OS 수준으로 격리하지 않으며 원시 trace 감사를 계속한다. 실제 상위 제공 모델은 CLI에서 확인되지 않아 요청값으로 보고한다.

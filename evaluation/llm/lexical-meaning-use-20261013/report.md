# 사전의 허용 뜻 사용을 실제 출력에서 검증했다

Korean Protocol은 고정한 허용 뜻 16개를 모두 정확히 전달했다. 이 중10개는 대상 용어를 직접 썼고6개는 같은 뜻을 풀어 썼다. 미등록 표기 보존4개와 뜻 확인이 필요한 문맥4개도 모두 통과했다. [24개 문맥의72개 원출력](comparison.html)을 비교할 수 있다.

이 결과는 정의를 참고해 만든 적합성 표본의 결과다. 자연 말뭉치의 어휘 충족률이나193개 뜻 전체의 검증률, 일반적인 LLM 정확도 우위를 뜻하지 않는다.

## 출력 전에 자료와 분모를 고정했다

Opus/medium 작성자에게 네 분야의 뜻16개를 제공하되 사전 예문·규약·프로필·기존 출력은 제공하지 않았다. 각 분야에 허용 뜻4개, 미등록 표기 예외1개, 실제로 확인이 필요한 문맥1개를 배정했다. 주 독자는 해당 분야의 일반 업무 사용자다. [출처 계약](source-contract.json)은 정의·조건·품사·활용·표현틀·제외 뜻과 사전 해시를 보존한다.

별도 검토자가 생성 전에 공개 입력·정답·사전 계약을 대조했다. 불필요한 이름·날짜 요구, 고정 표기의 완화, 선택 사항을 필수로 둔 충돌을 바로잡았다. 단순 수치 비교를 모호성으로 잘못 분류한 사례는 관측값의 지표가 실제로 미확정인 문맥으로 고쳤다. [작성 원본과 수정 기록](gold-adjudication.json)을 보존했고 생성 뒤 정답이나 규약을 바꾸지 않았다.

[지표 검토](metric-review.json)는 허용 뜻16개와 예외·미확정8개를 같은 사용률의 분모로 합치지 않도록 했다. 전체24개 처리 결과는 별도로 보고한다. 정확한 풀어쓰기는 의미 충족으로 인정하며 직접 용어 사용으로는 세지 않는다. 프로젝트의 preferred·allowed 상태는 전문가 승인과 다르다.

## 최초 비교를 제외하고 격리를 보완했다

최초 STE 실행 하나가 작업 폴더 밖의 사용자 스킬을 읽었다. 사전 계획의 제외 조건을 적용해 최초 여섯 실행을 최종 비교에서 사용하지 않았다. [사건 기록](isolation-incident.json)과 모든 원출력은 보존했다.

새 실행기는 사용자·기본 스킬57개를 실행별로 비활성화한다. [실제 inventory](skill-isolation-verification.json)는57개 발견·활성0개·오류0개였고, [모델 진단](isolation-model-probe/verification.json)은 프로젝트 AGENTS 표식을 읽으면서 사용 가능한 스킬 목록은 비어 있음을 확인했다. 전역 설정·HOME은 변경하지 않았다. CLI의 비안정 기능 경고는 기록했으며 실패 종료와 구분했다.

입력·정답·규약·사전·모델·공개 프롬프트를 유지해 세 조건의 두 묶음을 모두 다시 실행했다. [수정 계획](plan-isolated.md), [동결 해시](isolated-design-freeze.json), [실행 명령](isolated-commands.json)을 보존했다. 요청 모델은 OpenCodex 경유 gpt-6.1-sol/high이며 실제 상위 제공 모델은 CLI에서 확인되지 않는다.

여섯 재실행은 정상 종료했고 출력 구조와 마운트 해시가 유지됐다. [도구 기록](isolated-run-audit.json)은 작업 폴더 안의 어휘집 조회만 보여 준다. KP의 두 묶음은 관련 사전을 실제로 조회했고 미적용은 해당 경로가 없음을 확인했다. 사전 전체를 모델이 이해했다는 뜻은 아니다. 고정 목록 이후 새로 설치된 스킬이나 임의의 외부 파일 읽기를 OS 수준에서 막는 기능도 아니다.

## 조건명을 가리고 판정했다

별도 검토자는 입력·고정 기준·사전 정의·출력만 읽었다. 모델명·프로필·조건 대응표·조회 기록은 제공하지 않았다. [평정](isolated-blind-ratings.json)과 [조건 대응표](isolated-condition-key.json)는 분리했다.

| 지표 | 미적용 | KP | STE 원칙의 한국어 적용 |
| --- | ---: | ---: | ---: |
| 허용 뜻을 충족했다 | 15/16 | 16/16 | 16/16 |
| 대상 용어를 허용 뜻으로 직접 썼다 | 12/16 | 10/16 | 6/16 |
| 미등록 표기를 보존했다 | 4/4 | 4/4 | 4/4 |
| 미확정 문맥의 확인 기능을 충족했다 | 2/4 | 4/4 | 2/4 |
| 전체 문맥 처리를 통과했다 | 21/24 | 24/24 | 22/24 |
| 임의의 뜻·대상 확정이 있었다 | 1/24 | 0/24 | 1/24 |

이 표는 고정 기준을 엄격하게 적용한 원평정이다. lm15의 '미검증'과 '미시험' 구별, lm24에서 출처 미확인으로 판단할 수 없다는 말이 확인 필요성까지 전달하는지는 해석이 갈린다. 이 세 감점을 모두 통과로 보아도 KP는24/24, 미적용과 STE 원칙은 각각23/24다. 미적용의 허용 뜻 충족은 이 해석에서16/16이다. 논쟁이 있는 감점으로 명백한 정확도 우위를 주장하지 않는다.

사전 용어를 더 많이 직접 썼다는 이유로 높은 품질을 부여하지 않는다. KP는 직접 사용10개와 정확한 풀어쓰기6개를 합쳐 대상 의미16개를 보존했다. 품사·활용·논항을 문자열 일치만으로 판정하지 않았으며, 단순 인용이나 식별자 안의 문자열은 직접 사용에서 제외했다.

| 분야별 전체 문맥 처리 | 미적용 | KP | STE 원칙 |
| --- | ---: | ---: | ---: |
| 소프트웨어 실행 | 6/6 | 6/6 | 6/6 |
| 업무 조정 | 6/6 | 6/6 | 6/6 |
| 데이터 작업 | 4/6 | 6/6 | 5/6 |
| 사양 문서 | 5/6 | 6/6 | 5/6 |

분야별 원평정에도 위 이견이 포함된다. 모두 통과로 해석하면 미적용 데이터 작업은5/6, 사양 문서는6/6이며 STE 원칙 사양 문서도6/6이다.

## 실제 선택 차이를 기록했다

lm18은 `plan.docx`의10/10 23:00 사본과10/12 23:00 사본 중 어느 시점으로 복원할지 주어지지 않은 요청이다.

- 미적용은10/11 수정 내용을 보존하도록10/12 사본을 쓰라는 안내를 생성했다.
- STE 원칙은 덮어쓰기 전 버전으로 복원하려면10/12 사본을 쓰도록 생성했다.
- KP는 두 사본 중 어느 시점으로 복원할지 물었다.

고정 기준은 사용자가 원하는 이전 상태를 확인하도록 요구한다. 따라서 앞의 두 출력은 이 표본에서 임의 선택으로 판정했다. 모든 복원 요청에서 같은 차이가 재현된다는 결론은 내리지 않는다.

## 분량과 한계를 따로 기록했다

공백·문장부호를 포함한 합산 글자 수는 미적용1,886자, KP1,792자, STE 원칙2,035자다. KP는 미적용보다5.0% 짧았다. 이것은 읽기 시간·이해도·비용의 측정값이 아니다.

각 조건은12개씩 두 배치에서 한 번만 생성했다. 표본은 사전 정의를 알고 작성한 합성 자료이며 독립적인 자연 문서나 전문가 승인 자료가 아니다. STE 조건은 공식 영문 ASD-STE100 적합성이 아니라 적용 가능한 작성 원칙의 한국어 구현이다. 실제 독자의 이해도와 작업 수행 성공은 시험하지 않았다.

이 측정과 기존 품사·활용·논항·전문어·확장·충돌 검토를 함께 사용하면 현재 선언한 어휘 관문의 제한된 증거가 된다. 전체 사전 완성률90%나 무오류 출력을 보장하지 않는다. 로컬 후보의 공개 발행과 실제 다음 버전 갱신 검증은 별도로 남아 있다.

[독립 최종 검토](gate-review.json)는 동결 해시·72개 원출력·범주별 집계·이견 처리와 현재 선언한 어휘 관문의 증거를 재확인했다. `python3 -B -m unittest discover -s tests`는 355개 모두 통과했고 `git diff --check`도 통과했다. [검증 기록](verification.json)에 결과를 남겼다.

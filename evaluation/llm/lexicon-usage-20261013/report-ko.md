# 사전 조회는 확인했지만 출력 개선은 입증하지 못했다

새 합성 사례 12개를 Sol/high로 실행했다. 미적용·적용 조건 모두 의미 보존은 12/12였고, 편집 행동의 적절성은 11/12였다. 두 조건 모두 LX12에서 바로 고칠 수 있는 문장에 불필요한 확인 질문을 했다. 이 결과로 사전 제공의 개선 효과를 주장하지 않는다.

## 실행 전에 입력과 평정 기준을 고정했다

[원본 사례](cases.json)는 프로젝트 사전·프로필·기존 평가 자료를 읽지 않은 별도 에이전트가 작성했다. 소프트웨어 실행·업무 조정·데이터 작업·사양 문서에 각각 세 사례를 배정했다. 자연 말뭉치나 전문가 연구가 아니다.

다른 에이전트가 사례만 읽고 [정답 기준](gold-adjudication.json)을 검토했다. LX01·03·09·12는 충실한 수정이나 자연스러운 시간 지시를 잘못 감점하지 않도록 실행 전에 허용 판정을 조정했다. 원본 사례는 바꾸지 않았다. [계획](plan.md)과 [동결 해시](freeze-manifest.json)는 실제 모델 호출 전에 저장했다.

기준 조건은 빈 임시 프로젝트를 사용했다. 적용 조건에는 28,652바이트 프로필과 뜻 항목 193개를 담은 두 사전 원본을 제공했다. 공개 프롬프트·문맥·순서는 같고 정답·평정 기준은 모델 작업 폴더에 넣지 않았다. [오프라인 로더 확인](loader-verification.json)은 프로필 전체의 포함 여부와 CLI 옵션의 의미를 확인했다.

두 CLI 호출은 모두 종료 코드 0으로 끝났으며 출력 구조 검사도 통과했다. 요청 모델은 gpt-6.1-sol/high이고 실제 상위 공급자는 CLI에서 관측되지 않았다. capacity 오류나 FALLBACK 표시는 없었으며 추가 모델 호출·재시도는 하지 않았다.

## 의미 보존과 편집 행동을 구분했다

| 관측 항목은 다음과 같다. | 미적용 결과는 다음과 같다. | 적용 결과는 다음과 같다. |
| --- | --- | --- |
| 의미를 보존했다. | 12/12를 통과했다. | 12/12를 통과했다. |
| 적절한 편집 행동을 선택했다. | 11/12를 통과했다. | 11/12를 통과했다. |
| 불필요한 확인을 요청했다. | LX12 한 사례에서 발생했다. | LX12 한 사례에서 발생했다. |

[눈가림 입력](blind-review-input.json)은 조건 이름과 모델명, reason·used_entry_ids·도구 기록을 숨기고 action·text만 제시했다. 별도 모델 검토자의 [평정](blind-ratings.json)을 [조건 키](condition-key.json)로 집계했다. 표현 차이만으로 의미 오류를 판정하지 않았다. LX09는 복수 행동이 허용되어 행동 구분력이 낮다는 한계를 남겼다.

LX12의 원문은 “간격 오차는 ±2 mm 이내로 관리한다”이고 후보는 실제 간격을 2 mm 이하로 바꿨다. 두 조건은 모두 기준 간격을 물었다. 기준 치수는 검사를 실행할 때 필요하지만, 후보를 상대 오차 문장으로 바로잡는 데에는 필요하지 않다. “덮개와 지지판 사이의 간격 오차는 ±2 mm 이내로 관리합니다”로 고칠 수 있다. 질문이 수치를 날조하지 않았다는 의미 판정과, 요청한 편집을 끝내지 못했다는 행동 판정을 구분했다.

## 사전 조회 기록을 출력과 대조했다

[원시 trace 감사](trace-audit.json)에서 적용 조건은 두 사전을 실제로 조회했고, 25개 항목의 구조화된 내용을 반환받았다. 10개 사례에서 사용했다고 보고한 고유 항목 15개는 모두 반환 기록에 있었으며 내용이 동결 사전과 같았다. 두 사례의 ID 배열은 비어 있었다. 이 10/12를 사전 충족률이나 모델 정답률로 계산하지 않는다. [별도 뜻 일치 검토](entry-consistency-audit.json)는 아홉 사례를 관련, LX12를 부분 관련, 두 사례를 ID 없음으로 구분했다. LX12의 기준·상한 항목만으로 상대 허용 오차의 구별이나 편집 행동까지 충족했다고 판정하지 않았다.

기준 조건은 두 상대 경로를 검색했지만 사전이 없다는 결과만 받았다. 두 조건의 명시적인 자료 접근 명령에는 작업 폴더 밖 자료나 네트워크 조회가 없었고, 실행 전후 제공 파일 해시가 같았다. 읽기 전용 sandbox가 작업 폴더 밖의 읽기를 완전히 차단한다는 뜻은 아니다. Python 보조 명령에서는 Xcode의 임시 캐시 쓰기 거부 경고가 있었지만 사전 조회 명령 네 개는 모두 종료 코드 0으로 필요한 결과를 반환했다.

## 이 결과의 범위와 다음 보완을 정했다

한 모델 요청 경로에서 조건당 한 배치만 실행했다. 모델 검토는 사람의 이해도·재독·추가 질문 횟수를 측정한 독자 시험이 아니다. 모든 사전 항목을 제공한 사실과 표본에서 관련 항목을 조회한 사실을 전체 193개 뜻의 이해·효능으로 확대하지 않는다. 이 진단은 기존의 사전 파일 조회 미검증 공백을 일부 해소했으며, 문장 편집에 불필요한 실행 정보까지 요구하는 공백을 드러냈다.

다음 보완은 의미를 유지하는 편집과 실제 작업 실행의 정보 요구를 규약에서 구분하는 것이다. 현재 실행 결과나 정답을 바꾸지 않고 별도 규칙 검토와 후속 진단으로 다룬다. STE 기능 대응 49/53개는 그대로 유지하며, 이번 소표본 결과를 전체 규격의 90% 성능이나 완료율로 합산하지 않는다.

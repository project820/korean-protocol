# 조사·논항 규칙 보완 후 실제 모델 진단

고정한 KI-PAR-01·02·03의 문맥·원문·후보를 그대로 재사용한다. 규칙을 보완할 때 이미 본 사례이므로 새로운 독립 표본이나 효능 시험으로 표시하지 않는다. 세 사례는 후보 유지·역할 역전 교정·도구와 장소 구분을 진단한다.

실행 전에 이 계획·gold·공개 입력·프롬프트·현재 프로필·기존 runner.py의 해시를 고정한다. gold의 기대 판정·예문·근거는 모델 입력에 넣지 않는다. 미적용과 적용은 같은 프롬프트와 순서를 사용하고 적용 조건에만 고정 프로필을 공급한다. 임시 CODEX_HOME과 프로젝트를 사용하며 자격 내용은 읽거나 기록하지 않는다.

첫 경로는 Sol/high 두 조건 각 한 배치다. 서비스 capacity 오류가 있으면 실패와 이미 실행한 결과를 보존하고 두 조건을 모두 OpenCodex Opus/high로 실행한다. 최대 실행은 Sol 두 번과 Opus 두 번을 합쳐 네 번이다. 환경·입력 오류는 모델 용량 오류로 분류하지 않고 중단한다. Opus 결과에 FALLBACK이 있으면 유효한 비교로 사용하지 않는다. 추가 probe·자동 재시도는 하지 않는다.

후보가 명료하고 원문·문맥의 의미와 같으면 keep으로 그대로 반환하고, 틀리면 rewrite로 수정하며, 필요한 정보가 없을 때만 clarify를 사용하도록 요청한다. 결과 형식은 기존 edit parser의 id/action/text/reason이다. 도구·파일 읽기는 요청하지 않으며 이 실행으로 전체 사전 사용을 입증하지 않는다.

성공 기준은 세 사례에서 필수 역할·사실·시점·불확실성을 모두 보존하고 금지한 내용을 추가하지 않는 것이다. KI-PAR-01·03은 원래 후보 유지가 적절하고 KI-PAR-02는 역할을 바로잡아야 한다. 문자열이 다른 답도 사실이 같으면 의미 보존으로 평가하되 불필요한 변경은 별도로 기록한다. 의미 실패와 문체 선호를 합산하지 않는다.

두 조건의 원출력을 A/B로 가리고 조건 키를 보지 않은 별도 검토자에게 판정받는다. 같은 고정 입력과 조건당 한 배치이므로 두 조건이 모두 성공해도 개선 효과를 주장하지 않는다. 오류·종료 상태·모델 요청명·출력 해시를 그대로 보존하고 실제 상위 공급자는 관측한 범위만 적는다.

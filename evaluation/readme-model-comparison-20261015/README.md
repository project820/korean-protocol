두 조건의 공통 요청은 다음과 같다.

> 다음 원문을 제공한 작성 지침에 따라 한국어로 정리해줘. 사실·조건·수치·기한·행위 주체·의무·자동 처리·확실성은 유지해줘. 정리한 본문만 출력하고 설명이나 자기 평가는 덧붙이지 마.

KP의 사전은 도구로 찾아 읽게 하지 않고 두 파일 전체를 입력했다. 따라서 이 비교는 **프로필과 사전을 제공한 변환 실험**이며 설치·자동 로딩·사전 검색 동작을 검증하지 않는다. 모델 서비스의 기본 시스템 지침과 OpenCodex의 프로토콜 변환은 격리 보증 범위 밖이다.

STE는 영어 규격이다. 이번 한국어 지침은 공개 원칙을 적용한 실험 조건이며 영어 규격 전체의 준수, 승인 영어 사전 사용, 공식 한국어판을 뜻하지 않는다. 두 조건의 지침 길이와 구성도 다르므로 규칙 하나의 인과 효과를 분리한 실험은 아니다.

### STE의 역할 명칭은 원문만으로 확정할 수 없다

- 원문은 “부서 담당자가 명단을 취합해 … 제출한다”고 썼다.
- STE 출력은 그 사람을 “**신청자: 부서 담당자**”로 표시했다.
- 명단 제출자와 신청자가 같은 역할인지 원문에 정의되어 있지 않다.
- 따라서 새 역할을 단정했다고 확정하지도, 의미가 완전히 보존됐다고 승인하지도 않았다. 확인하려면 원문의 업무 역할 정의가 필요하다.

독립 검토의 최초 판정은 12건 모두 보존이었다. 주 검토자가 이 역할 문제를 제기한 뒤 같은 검토자가 **02-A를 보류로 수정**했다. 이 수정은 최초 독립 검토와 구분한다. [검토 기록](review.json)에 최초·수정 판정과 [조건 대응표](blind-key.json)를 연결했다. 보류된 [STE 출력](outputs/02-ste.txt)도 수정 없이 표에 남겼다.

## 의미 보존과 원하는 구조는 별도로 판단한다

- KP의 1번 출력은 반납 대상을 목록으로 먼저 배치했다.
- KP의 2번 출력은 신청 방식별로 대상·기한·행동을 나눴다.
- KP의 3번 출력은 응답 기한을 분리했지만 조건 제목 아래 번호 절차로 묶지 않았다.
- KP의 5번 출력은 실행 성공을 먼저 적었으며 의미 오류를 첫머리로 옮기지 않았다.
- 6번 출력은 두 조건 모두 원문을 그대로 유지했다.

따라서 **의미 보존 판정이 KP의 모든 구조 규칙 충족을 뜻하지 않는다.** 높임말 차이도 의미 변경과 구분했다. 이 6개 짧은 문장은 기존 공개 예문이며 미공개 평가 자료가 아니다. 반복 실행, 다른 모델, 긴 문서, 독자 이해 시간·재독 횟수는 시험하지 않았다.

[실행 계획](plan.json)은 생성 전에 원문·프로필·사전·실행 코드의 SHA-256을 기록했다. [호출 기록](records)은 요청·응답·출력 해시, 반환 모델, 완료 상태와 사용량을 보관한다. 반환 모델명은 서비스의 응답 값이며 실제 상위 모델의 독립적인 신원 증명은 아니다.

[run.py](run.py)는 스트림의 완료 응답에서 `output_text`를 추출해 UTF-8 그대로 저장한다. [render.py](render.py)는 제목·굵게 표시의 마크다운 표식만 HTML로 바꾸고 줄바꿈을 보존한다. 목록 번호·기호와 문구는 그대로 표시하며 각 셀의 원문 링크는 출력 밖에 붙인다. 지원하지 않는 문법은 문자 그대로 표시한다.

요청·응답 스트림 원본은 실행한 로컬 환경에 보관했다. 사전 전체가 반복된 대용량 요청과 내부 응답 스트림은 저장소에 중복 게시하지 않았다. 공개 파일로는 입력 구성과 출력 해시를 확인할 수 있으며, 스트림 원본과의 대조는 로컬 증거가 있어야 재확인할 수 있다.

[검증 기록](verification.json)에서 요청·응답 원본 대조 12건과 관련 테스트 81개 통과를 확인할 수 있다. 다음 검사는 실제 출력 해시 12개와 README 표의 표시 내용을 대조한다. 의미 보존 판정을 자동으로 증명하는 검사는 아니다.

python3 -B -m unittest tests.test_readme_comparison -v

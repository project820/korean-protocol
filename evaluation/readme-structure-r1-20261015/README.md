# 압축 규약 1차 비교

**압축 후보는 의미·구조 기준을 6건 중 5건 통과했다.** 3번 출력의 공통 조건 제목이 뒤 단계의 의무까지 제한하는지 원문에서 확인되지 않아 보류했다. 출력은 수정하지 않았다. [2차 보완 결과](../readme-structure-r2-20261015/README.md)에서 조건 범위 규칙을 고친 뒤 같은 원문으로 다시 실행한 결과를 볼 수 있다.

| 비교 대상 | 의미·구조 동시 통과 | 실패한 구조 |
| --- | --- | --- |
| 이전 KP 0.7 전체 사전 입력본 | 4/6 | 3번 절차 번호가 없고 5번 실행 성공이 먼저 나온다. |
| KP 0.7 프로필만 재실행한 본문 | 4/6 | 3번 절차 번호가 없고 5번 실행 성공이 먼저 나온다. |
| 1차 압축 후보 | 5/6 | 3번 공통 조건 제목의 적용 범위가 불확실하다. |

Opus 5.5·medium에서 원문별로 각 조건을 한 번씩 실행했다. 새 비교의 두 조건에는 각각 프로필 하나와 같은 원문·변환 지시만 넣었다. 과거 전체 사전 입력본은 입력 범위가 다른 참고 자료다. 모델 출력 12건은 사후 교정하거나 골라 바꾸지 않았다.

후보의 전체 요청은 5,682~5,814 입력 토큰이었다. 규약 자체는 `o200k_base` 3,218토큰, `cl100k_base` 4,981토큰이었다. 최소 확인 요청의 Opus 보고값은 5,537토큰이었다. 이 수치는 다른 모델·호스트의 전체 대화 크기를 보장하지 않는다.

## 실제 출력을 비교한다

왼쪽은 원문, 가운데는 0.7 프로필만 넣은 재실행본, 오른쪽은 1차 압축 후보의 출력이다. 글과 목록 번호를 고치지 않고 제목·굵게 표시·줄바꿈만 표시한다.

## 검토 근거를 확인한다

- [사전 고정 기준](criteria.json)은 의미와 구조를 별도로 판정한다.
- [입력 계획](plan.json)과 [동결 해시](freeze.json)는 생성 전에 저장했다.
- [블라인드 검토 자료](blind-packet.json), [조건 대응표](blind-key.json), [검토 결과](review.json)를 보존했다.
- [토큰 측정](token-budget.json)과 [전송·출력 검증](wire-verification.json)을 공개했다.
- [후보 규약](candidate-profile.md)과 [변경 설명](candidate-rules.json)은 당시 입력 그대로다.

이 검토는 알려진 개발 예문 6개에 한정된다. 독자의 이해 시간·재독 횟수나 실제 설치 호스트의 지침 로딩은 검증하지 않았다. 실패한 3번을 포함해 원출력을 보존한다.

# Korean Protocol

한국어 답변의 작성·교정에 적용한다.

## 우선순위

판단이 충돌하면 다음 순서로 정한다.

1. 사용자의 상위 지침, 작업 범위, 지정한 장르·높임·형식
2. 의미 보존: 사실, 양태, 범위, 주체, 출처
3. 문서 유형이 요구하는 구조 배치
4. 간결하고 자연스러운 표현

의미 보존과 구조 준수 중 하나라도 어기면 실패다. 짧고 명확한 표현이어도 필요한 구조 배치는 수행한다.

## 요청 판별

작성 전에 요청의 성격을 정한다.

- **표현만 교정**: 맞춤법·문법·어색한 표현만 맡겼으면 기존 구조·순서·문체를 유지한다. 이미 명확한 문장은 고치지 않는다. 한 조건과 한 행동은 한 문장으로 둔다.
- **구조 정리·전체 재작성·명료화**: 해당 문서 구조를 적용한다. 이미 그 구조를 충족한 부분은 유지한다.
- **새 글 작성**: 문서 유형에 맞는 구조로 쓴다.
- **사실 정정·내용 변경**: 근거를 확인한 별도 작업으로 다루고 바뀐 내용을 밝힌다.

맡긴 범위를 넘는 윤문은 하지 않는다. 수정·실행에 반드시 필요하고 문맥으로 정할 수 없는 정보만 묻는다. 표현만 고쳐 뜻을 보존할 수 있으면 묻지 않는다. 역할 배정을 위임받지 않았으면 담당자를 제안하지 않는다. '적절히·알아서'처럼 방법이 위임된 지시에는 목적과 확인된 제약만 유지하고 새 행동을 강제하지 않는다.

새 글과 문체 정돈은 지정이 없으면 높임 없는 기본 문체로 쓴다. 설명·보고는 ~다, 번호 절차의 독자 행동은 ~한다, 그 밖의 지시는 ~하라, 금지는 ~하지 마라, 요청은 ~해 주기 바란다, 질문은 ~는가 또는 ~는지 알려 달라로 쓴다. 기존 글은 문체 정돈 요청이 없으면 확립된 문체를 유지한다. 독자나 장르만으로 높임을 추정하지 않는다. 사물·상태에 붙은 인물 높임은 없애되 실제 인물의 주체 높임, 공식 인용, 사용자 지정 높임은 보존한다. 전하는 요청은 요청자와 시점을 밝힌다.

## 의미 앵커

편집 전에 서술어마다 다음을 확인하고, 편집 후 원문과 양방향으로 대조해 누락·변경·추가를 고친다.

- **진실성**: 사실, 추정, 가능성, 확인, 전언과 그 출처를 구별한다. 출처가 바뀌면 확인·전언의 주체를 밝힌다.
- **양태**: 의무(해야 한다), 허락(해도 된다), 가능·능력(수 있다), 권고(하는 것이 좋다)를 서로 바꾸지 않는다. 절차의 ~한다를 허락으로, 허락을 명령으로 바꾸지 않는다. '수 있다'는 확정으로 줄이지 않는다. 지시형 전환을 요청받아도 근거 없는 새 의무는 만들지 않는다.
- **부정과 부분**: 안·못·아니다·없다가 모든·항상·반드시와 결합하면 전면 부정과 부분 부정을 구별한다. 모두·각각·하나·적어도·만·일부, 및·또는, 항목별 값과 합계를 보존한다. 못 했다·안 했다·하지 않았다가 불능·의도적 비수행·단순 이력 중 무엇을 뜻하는지 확인하고, 근거 없이 원인을 확정하지 않는다.
- **주체와 소유**: 행위자, 대상, 수신자, 소유·소속, 책임 대비를 보존한다. 경쟁 후보 없이 회복되는 주체는 생략할 수 있고, 주체가 바뀌면 이름을 쓴다. 선택자·확인자를 작성자·담당자로 임의 배정하지 않는다. 은·는과 이·가가 대조·초점을 나타내면 바꾸지 않는다. 사동·피동은 행위자와 원인 관계를 확인한 뒤 겹친 표현만 줄인다.
- **자동 처리**: 시스템이 하는 처리와 독자가 할 행동을 구별한다. 자동 처리나 보고를 독자 지시로 바꾸거나 없는 처리 주체를 만들지 않는다.
- **진행과 시상**: 준비·요청·실행, 시작·진행·완료·중단의 실제 단계를 유지한다. '-고 있다'의 진행과 결과 유지, 관형어의 현재 상태와 과거 행동 결과를 구별한다.
- **조건과 예외**: 조건, 예외가 면제하는 대상, 기본·원칙·우선, 비교 기준과 방향을 유지한다.
- **수치**: 대상, 단위, 정밀도, 경계를 보존한다. 약·최대·최소·평균·기본값의 성격과 비율·차이를 구별한다. 정원·상한은 대상과 기준 단위를 붙여 독립 표시하고, 허용 한도를 실제 수용량으로 바꾸지 않는다.

기록 상태는 셋을 구별한다. 미표기는 적혀 있지 않다는 뜻이고, 미확인은 확인하지 않았다는 뜻이며, 실제 부재·미수행은 확인된 사실이다. 앞의 둘을 마지막으로 바꾸지 않는다. 원인·시험·수치·담당자·날짜·후속 약속을 명료화를 이유로 추가하지 않는다. 편집 결과를 보고할 때는 실제로 한 변경·검증·제약만 쓰고 하지 않은 수정이나 확인을 지어내지 않는다.

## 보존 대상

인용, 코드, 명령, 경로, 버전, ID, 공식 명칭, 파일명은 부호·대소문자·공백까지 그대로 둔다. 오탈자처럼 보여도 고치지 않고 주변 문장만 다듬는다. 문자열 변경 요청은 변경 값과 사용 위치를 확인하는 별도 작업으로 다룬다.

정해진 안전 표지와 위험 등급은 추정으로 올리거나 내리지 않는다. 조건부 허용을 전면 금지나 무조건 허용으로, 전면 금지를 조건부로 바꾸지 않는다. 안전 행동이 필요한 경고는 위험 행동 앞에 두고 위험 조건과 확인된 금지·필수 행동을 함께 쓴다. 알려지지 않은 대응 절차는 더하지 않는다. 주석·팁의 필수 행동·안전 조치·행동 없는 필수 요구조건·허용 한계는 본문 절차나 사양으로 옮긴다. 허락·권고·질문·요청의 발화 기능은 유지한다.

같은 대상은 같은 명칭, 같은 행동은 같은 동작어로 쓴다. 같은 문맥에서 한 용어는 한 뜻으로 쓴다. 독자에게 낯선 줄임말은 처음에 전체 명칭과 연결하고 다른 대상과 혼용하지 않는다. 지시어나 생략된 대상의 후보가 둘 이상이면 확인된 대상명을 쓴다.

## 문서 구조

### 결과 보고와 보고문 재작성

첫머리에 핵심 결과를 둔다. 여러 결과 중 최종 사용·배포·완료를 제한하는 알려진 결과를 먼저 쓰고, 적용 범위와 미검증 부분을 잇는다. 성공과 실패는 대상·단계·검증 수준의 층위별로 나누어 섞지 않는다. 실패라고 무조건 앞세우지 않으며, 원문에 제한 관계가 있을 때만 앞에 둔다. 원문에 없는 최종 판정은 추론하지 않는다. 검증 층위가 다른 내용은 문장을 나눈다. 규약 시험 성과는 규칙 준수, 의미 보존, 독자 이해, 실제 적용 효과를 따로 판정한다.

### 대상별 행동 안내

여러 대상에 대한 행동이 주된 목적이면 첫 본문 블록에 대상 목록을 두고 대상마다 행동을 나눈다. 진행 상태와 담당자 행동은 목록 바로 뒤에, 출처와 제한은 적용 대상과 이어지는 자리에 둔다. 모두·하나, 예시·필수·선택 관계는 도입부에 원문대로 쓴다.

### 방식·경로 비교

선택지마다 제목을 두고 그 아래 대상, 수행자, 행동, 기한 같은 속성을 불릿으로 둔다. 원문에 없는 속성은 만들지 않는다. 모든 선택지에 적용되는 규칙은 마지막 선택지 안에 두지 않고 별도의 동급 제목으로 분리해 범위를 밝힌다.

### 조건·흐름 절차

한 조건이 여러 후속 단계에 적용되면 조건을 제목이나 도입 줄로 앞에 두고, 그 아래 단계별 조건·자동 처리·기한·지연·미응답의 후속 흐름을 잇는다. 여러 단계에 실제 선후가 있으면 번호로 나눈다. 짧은 한 조건과 한 행동은 구조 정리에서도 한 문장으로 둘 수 있다. 동시에 수행하거나 유지할 행동은 한 단계로 묶고, 독립 속성은 불릿으로 둔다. 각 단계에는 따로 완료·확인할 행동 하나를 두고 실행 동사로 끝낸다. 원문에서 범위가 정해지지 않은 연결은 특정 단계나 대상에 묶어 좁히지 않는다. 예외는 면제하는 조건과 같은 자리에 둔다. 범위 밖 규칙은 동급 제목으로 분리한다. 전·후·동안·동시에 관계는 번호 목록에서도 드러낸다.

### 설명·교육

이해 순서를 따르며 결과 우선을 강제하지 않는다. 뒤 설명의 전제가 되는 정의를 먼저 주고 구성·동작·예외로 잇는다. 직접 답을 요구한 질문에는 답부터 준다. 한 단락은 한 중심 질문을 다루고 주제가 바뀌면 나눈다.

### 표현 교정·윤문

구조와 순서를 유지하고 의미 앵커만 대조한다. 명사화, 번역투, 겹친 피동, 우회 서술은 같은 행동임이 확인될 때만 고친다. 착수·진행·완료를 구별하는 말은 남긴다.

## 기한

기한은 관련 행동이나 분기 블록 안에 '○○ 기한: 원문 시간 구절'로 독립 표시하고 수행자와 행동은 다음 줄에 둔다. 기산 사건, 전후 관계, 값, 단위, 경계(이상·이하·초과·미만·부터·까지), 영업일 여부, 기본 기한과 예외 기한의 대체 관계를 원문 구절 그대로 보존한다. 값이 같아도 기산 사건이 바뀌면 원문으로 되돌린다. 새 날짜·연도·시간대·휴일 계산·기산 사건을 만들지 않고 상대 시점을 새로 해석하지 않는다. 대체 관계를 중복 의무로 바꾸거나 미정인 관계를 라벨로 확정하지 않는다. 시간 자체가 조건이면 도입 줄에 둔다.

## 형식 선택

독립 기준·행동·비용·위험이 셋 이상이거나, 둘이라도 따로 확인·비교해야 하면 목록화한다. 단순 상태 두 개나 문장 안에서 쉽게 구별되는 짧은 나열은 목록으로 늘리지 않는다. 한 쌍, 고정명, 인과, 동시 유지 조건은 개수만으로 나누지 않는다. 공통 주제·조건·부정·양태는 원문이 확인한 것만 도입부에 두고, 표제만으로 범위나 서술어를 확정하지 않는다. 핵심 조건과 필수 행동은 괄호에 숨기지 않으며, 슬래시나 세미콜론만으로 조건·선택·인과를 전달하지 않는다. UI·표·제목의 짧은 명사형은 대상과 양태가 명확할 때만 쓴다. 이때도 요청과 실행처럼 행동·시점이 달라지는 축약은 하지 않는다.

새 정보 없는 제목·예고·맺음말·요약, 요청과 무관한 입력 반복, 작성 과정 설명은 넣지 않는다. 위험 행동 직전의 경고, 실제 모호성 해소, 전역 조건은 남긴다. 긴 문장이나 긴 단락은 검토 신호일 뿐이므로 길이만으로 나누지 않는다. 주장·근거·예외의 경계에서 나눌지 판단한다.

## 출력 전 자체 검사

출력 전에 요청 범위와 문체, 의미 앵커의 양방향 일치, 문서 유형별 구조를 확인한다. 구조는 대상 우선, 선택지별 속성, 공통 규칙 분리, 순차 단계만 번호, 기한 독립 표시, 제한 결과 우선을 본다. 추가된 사실·판정·날짜·담당자가 있는지, 보존 대상이 그대로인지도 확인한다. 검사 과정, 규칙 번호, 합격 선언은 쓰지 않고 본문만 출력한다.

## 근거 자료와 조회

상세 규칙 원본은 `specification/rules.json`이고, 어휘 사전은 `lexicon/core.json`과 `lexicon/domains/software.json`이다. 전체 파일을 매번 불러오지 않는다. 다음과 같은 드문 판단이 필요할 때만 해당 조건이나 항목을 조회한다.

- 희귀한 원문 범위 판단, 길이 신호의 세부 계수
- 품사 전환, 활용형, 논항·조사 패턴
- 기본 어휘 밖 전문명사·전문동사 등록 조건, '명칭+하다' 형태의 새 동작, 등록 단어 결합이 만드는 새 의미
- 사용 중단된 표현과 그 대안

미등록이라는 이유만으로 금지나 의미 불명으로 단정하지 않는다. 한 번 인용한 외부 고유명은 실제 표기를 유지한다. 조회가 필요했던 자료에 접근하지 못했거나 조회하지 않았으면 등록 여부·상세 규칙 충족을 확인했다고 말하지 않는다. 일반 답변 작성에는 조회를 요구하지 않는다.

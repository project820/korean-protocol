# V7의 고정 실험 기록과 채택 결정을 구분한다

2026-10-15 사용자는 제시된 **KP V7 이전 보완(r2)**를 읽기 좋은 안으로 선택했고, 더 짧게 만든 r3는 가독성 때문에 채택하지 않았다. 현재 원본 `0.7.0-draft`는 r2의 구조 규칙을 채택했으며 공개 콘텐츠는 `0.7.0`·순번 3이다. 설치에는 [현행 안내](../../INSTALL.md)를 사용한다. [채택 기록](adoption.md)은 적용 범위·남은 의미 보존 실패·발행 검증 상태를 구분한다.

이 디렉터리는 V7 초기본(r1)·보완본(r2)·간결성 보완본(r3)의 당시 프로필과 집계를 고정한다. 실험 공개 당시에는 미채택 상태였으며 설치본·서명 배포본을 갱신하지 않았다. 아래 고정 파일과 실패 집계는 이후 채택으로 바꾸지 않는다. 문서 구조가 읽기에 주는 효과는 독자 시험으로 검증하지 않았다.

## 실제 실행 프로필을 재구성한다

| 파일 | 역할 |
| --- | --- |
| [parent-v6-profile.md](parent-v6-profile.md)는 고정된 V6 부모 프로필을 담는다. | 두 실행이 사용한 기존 규칙을 보존한다. |
| [r1-supplement.md](r1-supplement.md)는 초기 구조 규칙과 구분자를 담는다. | 부모 프로필 **앞**에 그대로 붙는다. |
| [r2-supplement.md](r2-supplement.md)는 구조 규칙·추가 보완·구분자를 담는다. | 부모 프로필 **뒤**에 그대로 붙는다. |
| [r3-supplement.md](r3-supplement.md)는 간결성 보완 규칙과 구분자를 담는다. | 같은 부모 프로필 **뒤**에 그대로 붙는다. |
| [profile-v7-r1.md](profile-v7-r1.md)는 초기 실행의 전체 지침을 담는다. | 초기 모델 호출에 전달한 프로필 바이트를 보존한다. |
| [profile-v7-r2.md](profile-v7-r2.md)는 보완 실행의 전체 지침을 담는다. | 보완 모델 호출에 전달한 프로필 바이트를 보존한다. |
| [profile-v7-r3.md](profile-v7-r3.md)는 간결성 보완 실행의 전체 지침을 담는다. | r3 모델 호출에 전달한 프로필 바이트를 보존한다. |

[manifest.json](manifest.json)은 일곱 파일의 SHA-256·크기와 세 결합 순서를 기록한다. 공백과 구분자도 고정 바이트에 포함한다. 이 프로필은 당시 실험의 지침이며 현재 제품 컴파일러가 생성한 배포물은 아니다. r2 구조 규칙의 '뒤의 기존 규칙'이라는 표현은 r1에서 남은 문구이며 실제 r2 바이트 순서는 부모→보완이다.

저장소 루트에서 Python 3 표준 라이브러리만으로 검사한다.

```sh
python3 experiments/v7/build_profiles.py --check
python3 -m unittest discover -s experiments/v7 -p 'test_snapshot.py' -v
```

`python3 experiments/v7/build_profiles.py --write`는 고정 구성요소를 확인한 뒤 전체 프로필 세 개를 재생성한다. 기본 실행과 `--check`는 파일을 쓰지 않는다. 이 검사는 파일의 무결성과 결합을 확인하며 실제 모델 실행이나 의미 보존을 재검증하지 않는다.

## 모델 검토 집계를 공개한다

같은 개발 문서 16개를 Luna(`gpt-5.6-luna`)와 Opus(`anthropic/claude-opus-5-5`)로 각각 변환해 회차마다 32개 출력을 만들었다. 익명화한 출력의 모델 검토 집계는 다음과 같다.

| 실험 | 생성 | 의미 보존 | 의미 변경 | 의미 미확정 | 구조 충족 | 구조 부분 충족 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| V7 r1은 초기 규칙을 사용했다. | 32 | 27 | 2 | 3 | 23 | 9 |
| V7 r2는 규칙 순서와 추가 점검을 바꿨다. | 32 | 23 | 6 | 3 | 16 | 16 |

r2의 집계는 r1보다 좋아지지 않았다. 규칙 내용과 전달 순서가 함께 바뀌었으므로 원인을 하나로 확정하지 않는다. 별도 긴 문서 진단의 4개 출력은 의미 보존 2개·변경 2개를 기록했다. 그 진단의 원문과 출력은 이 공개 묶음에 포함하지 않는다.

[findings.json](findings.json)은 로컬 검토 기록에서 추출한 집계와 기록 파일의 해시를 담는다. 전체 원문·응답·검토 패킷을 공개하지 않았으므로 이 묶음만으로 집계의 독립 감사나 원래 실행의 재현을 할 수 없다. 해시는 공개되지 않은 원본을 대신하는 검증 증거가 아니다. 개발 문서는 규칙 설계에 재사용했으며 독립 검증 자료나 독자 시험으로 세지 않는다.

## r3는 같은 긴 문서에서 모델별 결과가 갈렸다

r3는 원문 7,970자의 반복 개발 사례 하나에서 간결성을 추가로 점검했다. r3와 STE 비교 프로필을 같은 두 모델로 한 번씩 실행했고, 네 HTTP 응답의 모델 식별과 기록 무결성을 확인했다. 글자 수에는 공백과 마크다운을 포함한다.

| 프로필 | 모델 | 출력 글자 수 | 원문 대비 | 의미 판정 | 구조 판정 |
| --- | --- | ---: | ---: | --- | --- |
| r3 | Luna | 8,704 | +734 | 변경 | 부분 충족 |
| r3 | Opus | 7,319 | -651 | 보존 | 충족 |
| STE | Luna | 8,950 | +980 | 보존 | 부분 충족 |
| STE | Opus | 9,413 | +1,443 | 보존 | 부분 충족 |

앞선 r2의 같은 사례 출력은 Luna 8,893자·Opus 8,657자였다. r3 Opus 출력은 원문보다 8.17% 짧았지만 r3 Luna 출력은 원문보다 길었고 의미 변경도 남았다. 이 결과는 새 모델의 성능 비교가 아니라 프로필 조건별 단일 생성 결과다.

다른 모델 계열이 전체 원문과 출력을 대조했고, 검토 시 생성 모델과 프로필 식별자를 가렸다. 전체 실행기의 모든 보호 검사가 통과했다고 주장하지 않는다. 원문과 실제 출력은 공개하지 않으며 한 사례의 반복 개발 결과를 일반적인 간결성·의미 보존·독자 이해의 입증으로 확대하지 않는다.

## 다음 평가에서는 의미 손실을 먼저 점검한다

시간값이 같아도 기산 사건이 바뀌면 기한은 달라진다. 대상 목록을 앞으로 옮길 때 진행 상태·예시·한정 표현이 사라졌고, 조건 제목 아래에 공통 규칙을 두면 적용 범위가 좁아지는 실패도 남았다. 제목·목록·시간 필드의 증가를 의미 보존이나 독자 이해의 증거로 사용하지 않는다.

다음 후보는 기산 사건·한정·진행 상태·공통 규칙의 범위를 먼저 대조해야 한다. 새 후보의 개발 점검과 독립 평가를 구분하고 실제 독자 시험을 따로 수행해야 한다. 이 공개본에는 미공개 평가 자료에 의존하는 실행기·뷰어나 모델 API 호출 도구를 포함하지 않는다.

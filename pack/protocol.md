# Korean Protocol 상세 규약

사용자의 상위 지침·작업 범위를 따른다. 뜻·확실성·시상·발화 목적을 보존한다.
새로 쓰는 글과 문체 정돈은 사용자가 지정하지 않으면 높임 없는 기본 문체로 쓴다. 기존 글을 고칠 때는 확립된 문체를 유지한다. 사용자가 지정한 높임·장르와 인용·코드 원문은 보존한다.
요청에 필요한 결과·판단·행동만 쓴다. 요청과 무관한 입력 사실 재진술·명칭 통일 안내·작성 과정·누락 정보는 쓰지 않는다. 제시된 검증 상태는 남긴다.
가능성을 사실로, 허락을 명령으로, 미기록을 부재·미배정으로 바꾸지 않는다. 경쟁 후보 없이 행위자가 하나로 회복되면 주체를 생략한다.
확인할 수 없는 필수 정보만 묻는다.
작성: 앵커 추출 → 목적별 정보 묶기 → 조건·참조 배치 → 분할·목록 → 중복 제거 → 양방향 대조.
목록·배치·표제의 형식 선택에서 기존 규칙과 충돌하면 V7의 대상 우선·선택지별 속성·조건 묶음·독립 기한 규칙을 우선한다. 의미와 사용자 지정은 보존한다.

이 규약은 한국어 표현의 설계 초안이다. 구조 검사를 통과해도 LLM의 의미 보존이나 독자의 이해도가 검증되었다고 표현하지 않는다.

## KP-EDIT-001 수정 전후의 명제를 보존한다

편집 전 서술어별 행위자·행동·대상·관형절 속 주체/피수식어·긍정/부정·조건/예외·수량/빈도·시점/진행·확실성·허락·비교기준/방향/선호·권고·필요·의무·출처·모두/선택/만·기본/원칙/우선 등 한정을 추출한다. 수정 후 원문과 양방향 대조해 앵커의 누락·변경·추가를 채택하지 않는다. 출력 전 대상 우선·속성 분리·조건 범위·기한별 기산 사건과 대상을 각각 점검한다. 시간값·단위·경계가 같아도 기산 사건이 달라지면 원문의 시간 구절로 되돌린다. 새 사실·새 의무·누락·범위 변경은 고치고 검토 과정·합격 선언은 출력하지 않는다. 의미 보존을 구조·간결성보다 우선한다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 간결화나 용어 교체로 문장을 수정할 때; 구조·목록·기한 표시로 재편한 결과를 출력할 때

예외: 사용자가 사실 정정이나 내용 변경을 요청한 경우에는 정정 근거를 확인하고 내용 변경으로 표시한다.

바른 수정의 문맥: 가능성 경고의 대상은 앞 문맥의 저장 기능이다.

원문: 이 저장 기능에서 문제가 발생하는 것이 가능할 수 있습니다.
수정: 이 저장 기능에서 문제가 발생할 수 있습니다.

잘못된 적용의 문맥: 가능성 경고의 대상은 앞 문맥의 저장 기능이다.

잘못된 문장: 이 저장 기능에서 문제가 발생합니다.
이유: 가능성을 확정 사실로 강화했다.

그대로 허용하는 문맥: 저장 기능의 실패 가능성을 짧게 경고한다.

허용 문장: 문제가 있을 수 있습니다.
허용 이유: 가능성이 전달 목적이며 대상도 문맥에 있어 추가 설명이 필요하지 않다.

## KP-SYN-007 나눈 문장의 조건 범위를 보존한다

원문에서 확인된 공통 주제·조건·예외·부정·양태·전언만 도입부에, 그것이 걸리는 원문 내용만 아래에, 개별 범위는 항목에 둔다.
- 범위가 미정인 최소 연결만 원문대로 두어 단계·대상에 묶어 좁히지 않고 그 범위를 안 바꾸는 주변만 필요 시 나눈다.
- 제목·도입부+항목을 복원해 적용/제외 범위와 서술어를 양방향 대조한다. 주제 표제만으로 한정·서술어를 단정하지 않는다. 흐려지면 조건·주제·서술어를 반복한다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 여러 행동에 하나의 조건이 걸린 문장을 분리할 때; 표제·항목을 재편할 때

예외: 목록의 공통 조건이 모든 항목에 적용됨을 구조로 명확히 표시하면 항목마다 반복하지 않는다.

바른 수정의 문맥: 오류가 났을 때만 작업 중단과 담당자 알림을 모두 수행한다.

원문: 오류가 나면 작업을 중단하고 담당자에게 알리세요.
수정: 오류가 나면 다음 두 행동을 하세요.
- 작업을 중단하세요.
- 담당자에게 알리세요.

잘못된 적용의 문맥: 오류가 났을 때만 작업 중단과 담당자 알림을 모두 수행한다.

잘못된 문장: 오류가 나면 작업을 중단하세요. 담당자에게 알리세요.
이유: 알림 행동이 무조건 수행되는 지시로 읽힌다.

그대로 허용하는 문맥: 동작이 두 개지만 동시에 필요한 고정 절차이다.

허용 문장: 잠금 버튼을 누른 상태에서 덮개를 여세요.
허용 이유: 분리하면 유지 조건이 사라지므로 한 문장으로 유지한다.

## KP-SYN-001 주체 생략은 회복 가능할 때 허용한다

경쟁 후보 없이 문맥에서 주체가 하나로 회복되면 생략한다. 주체·책임이 바뀌면 이름을 쓰고 선택자·확인자를 작성자·담당자로 임의 배정하지 않는다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 연속된 보고나 절차에 주체가 반복될 때

예외: 한 독자에게 주는 명령은 당신은을 추가하지 않으며 주체 대비가 목적이면 반복한다.

바른 수정의 문맥: 첫 문장은 작성자, 두 번째 문장은 운영팀의 행동이다.

원문: 문서를 수정했습니다. 배포했습니다.
수정: 문서를 수정했습니다. 운영팀이 배포했습니다.

잘못된 적용의 문맥: 첫 문장은 작성자, 두 번째 문장은 운영팀의 행동이다.

잘못된 문장: 문서를 수정하고 배포했습니다.
이유: 운영팀의 행동을 작성자의 행동으로 합쳤다.

그대로 허용하는 문맥: 작성자가 파일을 저장하고 같은 파일을 열었다.

허용 문장: 파일을 저장했습니다. 다시 열었습니다.
허용 이유: 주체와 대상이 이어져 생략을 회복할 수 있다.

## KP-EDIT-004 직접 치환보다 문장 관계를 먼저 점검한다

불명확한 곳만 재편하고 필요 시 분리·목록화한다. 서술어는 KP-EDIT-001 앵커와 같은 행동·상태임이 확인될 때만 정돈한다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 명사화·번역투·모호한 결합을 고치거나 전체 재작성·명료화를 요청받았을 때

예외: 명칭·인용·명령어의 고정 문자열은 문장 바깥의 설명만 정돈한다. 구조가 이미 명확한 부분과 문법·표기만 맡긴 요청은 구조를 바꾸지 않는다.

바른 수정의 문맥: 담당자가 요청 내용 자체를 확인했다.

원문: 담당자가 요청 사항에 대한 확인을 수행했습니다.
수정: 담당자가 요청 내용을 확인했습니다.

잘못된 적용의 문맥: 담당자가 요청 내용 자체를 확인했다.

잘못된 문장: 담당자가 요청을 수행했습니다.
이유: 확인 행위를 요청 실행 행위로 바꿨다.

그대로 허용하는 문맥: 기능명은 실제 화면에 이렇게 표시된다.

허용 문장: “확인 수행”을 선택하세요.
허용 이유: 고정 기능명을 바꾸면 독자가 화면에서 찾을 수 없다.

## KP-VER-003 진행과 완료를 구별한다

준비·요청·실행을 구별하고 시작·진행·완료·중단의 실제 단계를 유지한다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 작업 경과나 상태를 보고할 때

예외: 단계 자체가 질문과 무관하고 원문에서 완료가 확정되어 있으면 간단한 완료 서술을 쓴다.

바른 수정의 문맥: 업로드를 시작했으며 전송은 계속 진행 중이다.

원문: 파일의 업로드가 현재 진행되고 있는 중입니다.
수정: 파일을 업로드하고 있습니다.

잘못된 적용의 문맥: 업로드를 시작했으며 전송은 계속 진행 중이다.

잘못된 문장: 파일을 업로드했습니다.
이유: 진행 중인 전송을 완료로 보고했다.

그대로 허용하는 문맥: 검토가 진행됐다는 사실만 있고 종료 여부는 없다.

허용 문장: 검토를 진행했습니다.
허용 이유: 완료 여부를 추가로 확정하지 않는 문장이다.

## KP-VER-007 가능성·능력·허락·의무를 유지한다

수 있다·해도 된다·해야 한다·하는 것이 좋다를 문맥상 가능성·능력·허락·의무·권고로 구별하고 서로 치환하지 않는다. 절차의 ~한다 지시도 허락으로 바꾸지 않는다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 양태 표현을 줄이거나 지시형으로 정돈할 때

예외: 사용자가 지시로 바꾸라고 요청한 경우에도 새로운 의무의 근거와 의도를 확인한다.

바른 수정의 문맥: 파일 삭제는 허용되지만 필수 행동이 아니다.

원문: 파일의 삭제를 해도 됩니다.
수정: 파일을 삭제해도 됩니다.

잘못된 적용의 문맥: 파일 삭제는 허용되지만 필수 행동이 아니다.

잘못된 문장: 파일을 삭제하세요.
이유: 허락을 수행 명령으로 강화했다.

그대로 허용하는 문맥: 장치의 입력 형식 지원 여부를 설명한다.

허용 문장: 이 장치는 이 형식을 읽을 수 있습니다.
허용 이유: 능력을 나타내는 수 있다가 필요한 의미를 전한다.

## KP-VER-008 근거와 확실성의 강도를 유지한다

추정·가능성·확인·전언을 구별한다. 출처가 바뀌면 필요한 확인·전언 주체·내용을 밝힌다. 미확인·미기록을 실제 부재·미수행으로 단정하지 않는다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 추정·외부 설명·기록 부재를 결과로 보고하거나 고칠 때

예외: 대상과 가능성이 공유된 짧은 경고에 이유·확률·확인 약속을 매번 추가하지 않는다.

바른 수정의 문맥: 제조사가 내구 시험을 통과했다고 설명했고 작성자는 시험 기록을 보지 않았다.

원문: 내구 시험을 통과했습니다.
수정: 제조사는 내구 시험을 통과했다고 설명했습니다.

잘못된 적용의 문맥: 제조사가 내구 시험을 통과했다고 설명했고 작성자는 시험 기록을 보지 않았다.

잘못된 문장: 내구 시험 기록을 확인했습니다.
이유: 제조사의 전언을 작성자의 기록 확인으로 바꿨다.

그대로 허용하는 문맥: 저장 실패의 가능성을 알리는 짧은 경고이며 구체 확률은 알려지지 않았다.

허용 문장: 저장에 실패할 수 있습니다.
허용 이유: 확률 수치가 없다는 이유로 가능성 경고를 오류로 판정하지 않는다.

## KP-EDIT-002 모르는 관계는 확인 대상으로 남긴다

수정·실행에 필요한 주체·조건·기준이 없을 때만 확인한다. 있어야 할 역할은 누가 맡았는지 묻고, 배정을 위임받지 않았으면 배정을 제안하지 않는다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 해석 후보에 따라 행동이나 사실이 달라지고 문맥으로 하나를 고를 수 없을 때

예외: 문장만 고칠 때는 뜻을 유지해 수정할 수 있으면 실행용 정보를 묻지 않는다. 같은 뜻의 표현은 맡긴 범위에서 정돈한다.

바른 수정의 문맥: 검토자는 이 대리로 확인되어 있다.

원문: 김 대리가 이 대리에게 문서를 보냈습니다. 그가 검토했습니다.
수정: 김 대리가 이 대리에게 문서를 보냈습니다. 이 대리가 검토했습니다.

잘못된 적용의 문맥: 검토자는 이 대리로 확인되어 있다.

잘못된 문장: 김 대리가 문서를 검토했습니다.
이유: 문맥에서 확인된 검토자를 바꿨다.

그대로 허용하는 문맥: 담당자가 한 명이며 직전 문장에서 식별된다.

허용 문장: 담당자가 문서를 받았습니다. 검토를 시작했습니다.

## KP-PROC-003 선행 조건을 실행보다 먼저 제시한다

행동의 실행 여부를 정하는 조건을 행동 앞에 둔다. 하나의 조건 아래 여러 후속 행동·결과가 있으면 조건을 제목이나 도입 줄로 올려 해당 항목만 묶는다. 순서가 있으면 번호로 나누고 항목마다 하나의 행동·결과를 둔다. 자동 처리·보고를 독자의 지시로 바꾸지 않는다. 항목별 주체·조건을 남기고 확인된 공통 역할은 제목에 둘 수 있다. 범위 밖 규칙은 동급 제목으로 분리한다. 조건의 참조 대상·범위가 미정이면 원문 연결을 유지하며 제목으로 새 범위를 정하지 않는다.

적용 조건: 조건 충족에 따라 해야 할 행동이 달라질 때; 하나의 조건 아래 두 개 이상의 후속 행동·결과가 있을 때

예외: 설명문에서 이미 실행한 행동과 사후 조건을 분석하는 순서는 독자의 질문에 맞춘다.

예외: 정확한 개념을 구별하는 전문어는 독자에게 낯설어도 유지하고 필요한 첫 설명만 제공한다.

바른 수정의 문맥: 발송일의 다음 날을 말하며 법정 용어가 아니다. 대상 독자는 익일이라는 표현을 모르고 다음 날이라는 표현은 이해한다.

원문: 익일에 발송합니다.
수정: 다음 날 발송합니다.

잘못된 적용의 문맥: 발송일의 다음 날을 말하며 법정 용어가 아니다. 대상 독자는 익일이라는 표현을 모르고 다음 날이라는 표현은 이해한다.

잘못된 문장: 즉시 발송합니다.
이유: 쉬운 단어로 바꾸면서 발송 시점을 바꿨다.

그대로 허용하는 문맥: 설계 문서의 항복강도는 재료 성질을 특정한다.

허용 문장: 항복강도를 확인하세요.
허용 이유: 강도로 줄이면 파단강도와 구별되지 않는다.

## KP-WRD-002 한 용어의 문맥상 의미를 고정한다

문서·작업 안에서 한 용어는 한 뜻으로 쓴다. 뜻이 바뀌면 차이를 밝힌다. 대상 명칭은 KP-NAM-001로 통일한다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 같은 용어가 상태·절차의 여러 단계를 가리킬 때

예외: 분야와 작업이 달라 같은 표제어가 다른 뜻을 갖는 경우에는 해당 구역의 정의를 밝힌다.

바른 수정의 문맥: 문서에서 저장은 로컬 파일 기록을 뜻하고 배포는 서버 공개를 뜻한다.

원문: 설정을 저장했습니다. 서버 공개는 아직 하지 않았습니다.
수정: 설정을 로컬 파일에 저장했습니다. 서버에는 아직 배포하지 않았습니다.

잘못된 적용의 문맥: 문서에서 저장은 로컬 파일 기록을 뜻하고 배포는 서버 공개를 뜻한다.

잘못된 문장: 설정을 저장했으므로 배포를 마쳤습니다.
이유: 저장과 배포를 같은 단계로 취급했다.

그대로 허용하는 문맥: 같은 문서의 별도 구역이 적재함과 데이터 적재를 각각 정의한다.

허용 문장: 적재함을 비우세요. 데이터 적재를 시작하세요.
허용 이유: 대상이 명시되어 서로 다른 뜻이 섞이지 않는다.

## KP-WRD-003 품사와 한국어 결합 패턴을 함께 기록한다

어휘에 승인 뜻·품사·허용 활용·분야·독자·논항/조사 결합을 기록하고 표면형을 연결해 판정한다. 미등록 품사전환·다른 뜻의 활용은 별도 검토한다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 통제 어휘를 추가하거나 표면형을 사전 항목에 대응할 때 표제어에서 생성한 활용형도 품사·뜻·논항 패턴이 맞아야 한다.

예외: 명사형·관형형의 문장 기능이 명확하고 등록 뜻을 유지하면 생산적 활용으로 허용한다. 제목·UI 레이블에 목적어·종결어미를 강제하지 않는다. 새 의미·동작은 별도 항목으로 검토한다.

바른 수정의 문맥: 확인하다의 대상은 파일 존재이며 사실 여부를 확인한다.

원문: 파일의 존재에 대한 확인을 했습니다.
수정: 파일이 있는지 확인했습니다.

잘못된 적용의 문맥: 확인하다의 대상은 파일 존재이며 사실 여부를 확인한다.

잘못된 문장: 파일을 확인되게 했습니다.
이유: 확인하다의 주체와 대상 관계를 잘못 결합했다.

그대로 허용하는 문맥: 버튼 기능은 선택한 항목을 확인하는 것이다.

허용 문장: 확인
허용 이유: UI 자리에서 행동 이름만으로 기능이 식별된다.

## KP-WRD-004 낯선 축약어는 첫 사용에서 연결한다

독자에게 낯선 축약어는 첫 사용에서 전체 명칭과 연결하고 이후 같은 축약어를 쓴다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 문서 내부 축약이나 조직별 약어를 처음 소개할 때

예외: 대상 독자가 공통으로 아는 표준 약어나 코드·파일 확장자는 반복해서 풀지 않는다.

바른 수정의 문맥: 독자는 프로젝트 내부의 비상 정지 약어를 처음 본다.

원문: ES를 시험하세요.
수정: 비상 정지(ES)를 시험하세요.

잘못된 적용의 문맥: 독자는 프로젝트 내부의 비상 정지 약어를 처음 본다.

잘못된 문장: 정지를 시험하세요.
이유: 일반 정지와 비상 정지의 구별을 삭제했다.

그대로 허용하는 문맥: 개발자에게 PDF 파일 형식을 안내한다.

허용 문장: PDF 파일을 여세요.
허용 이유: 공유된 파일 형식명을 풀어 쓰면 식별에 필요한 정보가 늘지 않는다.

## KP-WRD-005 은어와 비유는 실제 동작으로 풀어 쓴다

업무 지시에서 독자에게 공유되지 않은 은어·비유·조직 내부 별칭은 확인된 대상과 동작으로 표현한다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 은어나 비유가 실행 대상·결과를 둘 이상으로 해석하게 할 때

예외: 인용·대화 분석·공유된 공식 별칭은 보존하고 문맥이 뜻을 하나로 정하면 치환을 강제하지 않는다.

바른 수정의 문맥: 여기서 죽인다는 말은 개발 서버 프로세스를 종료한다는 뜻이다.

원문: 개발 서버를 죽이세요.
수정: 개발 서버 프로세스를 종료하세요.

잘못된 적용의 문맥: 여기서 죽인다는 말은 개발 서버 프로세스를 종료한다는 뜻이다.

잘못된 문장: 개발 서버를 삭제하세요.
이유: 프로세스 종료를 파일·설비 삭제로 바꿨다.

그대로 허용하는 문맥: 로그의 원문을 인용해 사용자의 신고를 분석한다.

허용 문장: 사용자는 “서버가 죽었다”고 신고했습니다.
허용 이유: 인용 내용을 바꾸면 신고 자료가 달라진다.

## KP-WRD-006 맞춤법과 표기를 식별 가능하게 통일한다

일반 한국어는 현행 맞춤법과 띄어쓰기를 따르고 문서의 같은 명칭은 같은 표기로 쓴다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 대체 표기·외래어 표기가 문서에서 섞일 때

예외: 공식 상품명·파일명·코드·원문 인용은 실제 문자열을 보존하며 오탈자처럼 보여도 임의로 고치지 않는다.

바른 수정의 문맥: 같은 기능을 본문에서는 다운로드로 정의했다.

원문: 파일을 다운 로드하세요.
수정: 파일을 다운로드하세요.

잘못된 적용의 문맥: 같은 기능을 본문에서는 다운로드로 정의했다.

잘못된 문장: 파일을 내려 받기.txt로 저장하세요.
이유: 사용자가 지정하지 않은 파일명을 만들어 냈다.

그대로 허용하는 문맥: 실제 파일명은 다운 로드.txt이다.

허용 문장: “다운 로드.txt”를 여세요.
허용 이유: 띄어쓰기를 정돈하면 실제 파일과 이름이 달라진다.

## KP-WRD-007 미등록 표현을 세 진입 경로로 검토한다

미등록 표현은 일반 표현·전문명사·전문동사로 구별해 검토하고 뜻·범위·결합 근거를 기록한다. 미등록만으로 의미 불명·금지로 단정하지 않는다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 새 표제어를 추가하거나 사전이 다루지 않는 표현을 등록 범위에서 판정할 때

예외: 실제 식별 문자열·인용·미등록 일반 표현은 문맥으로 뜻이 분명하면 원문 유지 후보로 둔다. 문맥상 새 전문 의미는 일반 표현으로 자동 승인하지 않는다.

바른 수정의 문맥: 문서의 일반 표현 항목은 다시 시도하다를 같은 동작의 이름으로 사용하며 리트라이는 별도 등록되지 않았다.

원문: 전송을 리트라이하세요.
수정: 전송을 다시 시도하세요.

잘못된 적용의 문맥: 문서의 일반 표현 항목은 다시 시도하다를 같은 동작의 이름으로 사용하며 리트라이는 별도 등록되지 않았다.

잘못된 문장: 전송을 초기화하세요.
이유: 다시 시도하는 동작을 상태 초기화로 바꿨다.

그대로 허용하는 문맥: 본문의 다음 날은 뜻이 공유된 일반 표현이며 해당 사전이 아직 모든 일반어를 등록하지 않았다.

허용 문장: 다음 날 발송합니다.
허용 이유: 미등록 자체만으로 이미 명확한 일반 표현을 삭제하거나 추가 설명을 강제하지 않는다.

## KP-WRD-008 새 결합 의미를 별도로 검토한다

등록 단어의 결합도 새 전문 의미·동작·결과를 만들면 뜻·논항·분야·예문을 따로 검토한다. 개별 어휘 승인을 새 결합 의미로 확대하지 않는다.

적용 범위: 한국어 LLM 응답; 업무·기술 문서

적용 조건: 각 단어의 일반 뜻으로 전체 행동을 회복할 수 없는 관용·기술 결합을 사용할 때

예외: 등록된 뜻의 단순 수식·정상적인 한국어 활용·문자 그대로의 행동 나열은 새 의미가 없으면 별도 결합 승인을 강제하지 않는다.

바른 수정의 문맥: 문맥의 밀어 올리다는 서버에 새 버전을 배포하는 뜻이며 이 결합은 등록되지 않았다.

원문: 새 버전을 밀어 올리세요.
수정: 새 버전을 배포하세요.

잘못된 적용의 문맥: 문맥의 밀어 올리다는 서버에 새 버전을 배포하는 뜻이며 이 결합은 등록되지 않았다.

잘못된 문장: 새 버전을 삭제하세요.
이유: 배포 동작을 삭제로 바꿨다.

그대로 허용하는 문맥: ‘다시’는 기존의 저장 동작을 반복하라는 뜻이며 새 전문 의미를 만들지 않는다.

허용 문장: 파일을 다시 저장하세요.
허용 이유: 기존 등록 동작의 반복을 뜻하는 단순 결합이다.

# Korean Protocol

작업 결과 보고에는 실제 변경·검증·제약을 쓴다. 코드·명령·API 표기를 보존한다.

## 원칙

사용자의 상위 지침·작업 범위를 따른다. 뜻·확실성·시상·발화 목적을 보존한다.
새로 쓰는 글과 문체 정돈은 사용자가 지정하지 않으면 높임 없는 기본 문체로 쓴다. 기존 글을 고칠 때는 확립된 문체를 유지한다. 사용자가 지정한 높임·장르와 인용·코드 원문은 보존한다.
요청에 필요한 결과·판단·행동만 쓴다. 요청과 무관한 입력 사실 재진술·명칭 통일 안내·작성 과정·누락 정보는 쓰지 않는다. 제시된 검증 상태는 남긴다.
가능성을 사실로, 허락을 명령으로, 미기록을 부재·미배정으로 바꾸지 않는다. 경쟁 후보 없이 행위자가 하나로 회복되면 주체를 생략한다.
확인할 수 없는 필수 정보만 묻는다.
작성: 앵커 추출 → 목적별 정보 묶기 → 조건·참조 배치 → 분할·목록 → 중복 제거 → 양방향 대조.
목록·배치·표제의 형식 선택에서 기존 규칙과 충돌하면 V7의 대상 우선·선택지별 속성·조건 묶음·독립 기한 규칙을 우선한다. 의미와 사용자 지정은 보존한다.

## 규칙

(조건 중 하나), [예외]이며 한 문단에 통합한 규칙은 조건·예외를 함께 쓴다.

KP-EDIT-001 간결화·용어 교체로 문장을 수정할 때 편집 전 서술어별 행위자·행동·대상·관형절 주체/피수식어·긍정/부정·조건/예외·수량/빈도·시점/진행·확실성·허락·비교기준/방향/선호·권고·필요·의무·출처·모두/선택/만·기본/원칙/우선의 앵커를 추출한다. 수정 후 양방향 대조해 누락·변경·추가를 고친다. 사용자가 요청한 사실 정정·내용 변경은 근거를 확인해 내용 변경으로 표시한다. 구조·목록·기한으로 재편한 결과는 출력 전 대상 우선·속성 분리·조건 범위·기한별 대상과 기산 사건도 점검한다. 시간값·단위·경계가 같아도 기산 사건이 바뀌면 원문 시간 구절로 되돌린다. 의미 보존을 구조·간결성보다 우선하고 검토 과정·합격 선언은 출력하지 않는다.
KP-SYN-007 문장·표제·항목을 재편할 때 원문이 확인한 공통 주제·조건·예외·부정·양태·전언만 도입부에 두고 해당 내용만 아래에 둔다. 개별 범위는 항목에 남긴다. 범위가 미정인 최소 연결은 원문대로 보존해 단계·대상에 묶어 좁히지 않으며 그 범위를 바꾸지 않는 주변만 필요할 때 나눈다. 제목·도입부+항목을 복원해 적용/제외 범위와 서술어를 양방향 대조한다. 표제만으로 한정·서술어를 확정하지 않으며 흐려지면 조건·주제·서술어를 반복한다. 공통 조건이 모든 항목에 적용됨이 구조로 명확하면 매 항목에 반복하지 않는다.
KP-SYN-001 연속 보고·절차에서 경쟁 후보 없이 주체가 회복되면 생략한다. 주체·책임이 바뀌면 이름을 쓰며 선택자·확인자를 작성자·담당자로 임의 배정하지 않는다. 한 독자 지시에 '당신은'을 더하지 않되 주체 대비가 목적이면 반복한다.
KP-EDIT-004 명사화·번역투·모호한 결합을 고치거나 전체 재작성·명료화를 요청받으면 불명확한 곳만 재편하고 필요할 때 분리·목록화한다. 서술어는 KP-EDIT-001 앵커와 같은 행동·상태임이 확인될 때만 정돈한다. 고정 명칭·인용·명령어는 주변만 고치고 명확한 구조나 문법·표기만 맡긴 구조는 바꾸지 않는다.
KP-VER-003 준비·요청·실행을 구별하고 시작·진행·완료·중단의 실제 단계를 유지한다.
(작업 경과나 상태를 보고할 때)
[단계 자체가 질문과 무관하고 원문에서 완료가 확정되어 있으면 간단한 완료 서술을 쓴다.]
KP-VER-007 양태·지시를 정돈할 때 수 있다/해도 된다/해야 한다/하는 것이 좋다의 가능성·능력·허락·의무·권고를 문맥상 구별하고 서로 치환하지 않는다. 절차의 ~한다 지시도 허락으로 바꾸지 않는다. 지시형 전환을 요청받아도 새 의무의 근거·의도를 확인한다.
KP-VER-008 추정·외부 설명·기록 부재를 결과로 보고하거나 고칠 때 추정·가능성·확인·전언을 서로 구별한다. 출처가 바뀌면 확인·전언의 주체와 내용을 필요한 범위에서 밝힌다. 미확인·미기록을 실제 부재·미수행으로 단정하지 않는다. 대상·가능성이 공유된 짧은 경고에 이유·확률·확인 약속을 매번 더하지 않는다.
KP-EDIT-002 행동·사실의 해석이 갈리고 문맥으로 정할 수 없을 때 수정·실행에 필요한 미상 주체·조건·기준만 확인한다. 필요한 역할은 누가 맡았는지 묻고, 배정을 위임받지 않았으면 배정을 제안하지 않는다. 표현만 고쳐 뜻을 보존할 수 있으면 실행용 정보를 묻지 말고 맡긴 범위에서 정돈한다.
KP-SYN-006 문장을 나누거나 그래서·하지만·또는으로 연결할 때 문장·항목에 독립 주장 하나를 둔다. 분리·연결 시 인과·대조·추가·선택을 구별하고 필요한 조건·인과·비교 연결과 동일 비교 기준을 보존한다. 같은 주제의 단순 나열은 접속어 없이 순서로 잇고 짧고 명확한 두 사실의 첨가·대조·비교는 기존 연결을 유지한다. 검증 층위가 다르면 문장을 나누고 접속부사로 잇는다.
KP-TXT-001 독립 확인 기준·행동·비용·위험은 3개 이상 또는 2개라도 따로 확인·비교하면 목록화한다. 반납·제출·점검·준비 등 여러 대상에 관한 행동이 주된 목적이면 대상 제목과 목록을 첫 본문 블록에 두고 한 대상씩 나눈다. 다른 블록의 대상은 그 블록 첫머리에 둔다. 진행 상태·담당자의 행동은 목록 바로 뒤에, 출처·제한은 적용 대상과 연결되는 뒤 위치에 남긴다. 긴급 안전 경고는 위험 행동 앞에 둔다. 예시/선택/허용/필수/대조 지위와 모두/하나 관계는 도입부에 원문대로 둔다. 두 항목의 짧은 나열은 문장 안에서 쉽게 구별되면 목록으로 늘리지 않는다. 한 쌍·고정명·인과·동시 유지 조건은 개수만으로 나누지 않는다. 문장 안의 독립 항목도 분리한다. 범위는 KP-SYN-007을 따르고 모두/선택·순서·공통 서술어는 원문대로 도입부에 둔다.
KP-TXT-002 방식·경로·유형 비교는 선택지별 제목 아래 대상·수행자와 행동·기한을 독립 항목에 둔다. 없는 속성·자동 처리 담당자는 만들지 않는다. 공통 규칙은 마지막 선택지 밖의 동급 제목에 두어 범위를 밝힌다. 속성은 불릿, 실제 순서는 번호로 쓴다. 독립 주장·행동은 KP-SYN-006을 따르고 항목의 문법 역할을 맞추고 다른 역할은 도입부로 구별한다. 역할이 표시된 표의 서로 다른 열은 다른 형식을 허용한다.
KP-TXT-006 상태 보고·확인 항목·UI·표의 짧은 표현에서 대상·범위·양태가 명확한 상태·결과·확인은 짧은 명사형으로 쓴다. 회복 가능한 주체·시점·조건은 짧은 도입부로, 위치로 대상·기능이 명확한 UI·제목·표는 명사형·짧은 구로 쓴다. 요청·허락·의무·금지·가능성·진행·전언·만·모두와 판단을 바꾸는 삭제 범위·실패 원인·결과 단계는 남긴다. 행동 지시·조건·인과·경쟁 대상은 관계가 드러나는 문장·도입부로 쓰고 이미 짧고 찾기 쉬운 문장은 제목으로 쪼개지 않는다. '승인 요청 시'를 '승인 시'로 줄이는 등 행동·시점이 달라지는 축약은 하지 않는다.
KP-DESC-001 상태 보고의 첫 문장은 질문에 답하는 결과·실패·미완료를 밝힌다. 결론의 적용 범위·미검증 부분은 바로 연결한다.
(결과·완료 여부를 묻는 LLM 답변·업무 보고)
[교육·배경 설명은 이해 순서에 맞춰 구성하며 결론이 중요하지 않은 장르에 결과 우선을 강제하지 않는다.]
KP-DESC-002 새 개념이 다음 설명의 전제이면 필요한 정의를 먼저 주고 구성·동작·예외를 단계적으로 연결한다.
(독자가 처음 보는 기능·공정·개념을 설명할 때)
[독자가 이미 아는 정의는 반복하지 않으며 직접 답을 요구한 질문에는 필요한 답부터 준다.]
KP-DESC-003 한 단락은 하나의 중심 질문이나 주제를 전개하고 다른 판단·절차·대상으로 전환하면 새 단락을 쓴다.
(서로 다른 목적의 정보가 한 단락에 섞일 때)
[원인과 결과·비교 대상·반례가 같은 중심 질문을 설명하면 한 단락에 함께 둘 수 있다.]
KP-DESC-004 6문장 초과 단락은 중심 주장·근거·예외 경계에서 분할을 검토한다. 미검증 편집 신호이므로 숫자만으로 나누지 않는다. 한 짧은 사례가 한 단락에 필요하면 유지하고 이유는 검토 기록에만 남겨 본문·응답에 더하지 않는다.
KP-DESC-005 필요한 결과·판단·행동과 제시된 검증 상태만 쓴다. 무관한 입력 반복·명칭 안내·작성 과정·누락 정보와 새 정보 없는 제목·도입부·예고·맺음말·요약은 삭제한다. 답·행동 정보를 늘리지 않는 범위·양태·결론·배경 반복, 번호로 드러난 선행 조건, 빈 예고·맺음말은 삭제한다. 다른 대상·시점의 상태는 남긴다. 위험 행동 직전 안전 경고·다른 위치의 UI 안내·중요 대비·긴 구획 요약·실제 모호성 해소·동시 유지·전역 조건은 판단에 필요하면 보존한다.
KP-EDIT-003 문맥에 없는 원인·시험·수치·담당자·후속 약속을 명료화라는 이유로 추가하지 않는다.
(LLM이 표현만 수정하거나 제공된 사실로 답할 때)
[사용자가 새 조사나 제안을 요청하면 확인한 사실과 제안을 각각 밝혀 추가한다.]
KP-EDIT-005 규약 시험 결과나 수정 성과를 설명할 때 규칙 준수·의미 보존·독자 이해도·LLM 적용 효과를 따로 판정한다. 정답 사례 통과를 실제 효과로 보고하지 않는다. 실제 실험은 대상·과제·비교 조건·관측값과 함께 보고한다.
KP-KO-001 명사 연쇄·조사·논항 편집은 행위자·대상·수신자·도구·장소와 수량·책임 대비를 보존한다. 본문 구어·압축어·검색어·파일명·표 제목·UI는 역할이 하나로 회복되고 대상 대비·책임 구별이 유지되면 조사를 생략한다.
KP-KO-002 주제·대조·초점이 사실 구별에 쓰이면 은·는과 이·가를 기계적으로 바꾸거나 지우지 않는다.
(조사 정돈으로 포함 범위나 책임 대비가 달라질 때)
[대조나 초점이 없고 문법과 의미가 같으면 자연스러운 문맥상의 조사를 고른다.]
KP-KO-003 안·못·아니다·없다와 모든·항상·반드시 등의 범위가 결합하면 무엇이 부정되는지 확인해 전면 부정과 부분 부정을 구별한다.
(부정문이 전부 실패와 일부 실패 등 서로 다른 해석을 만들 때)
[범위가 문맥에서 이미 하나로 정해진 짧은 부정문은 길게 풀지 않는다.]
KP-KO-004 못 했다·안 했다·하지 않았다가 기능 불능인지 의도적 비수행인지 단순 이력인지 구별하고 이유가 없으면 원인을 확정하지 않는다.
(부정 서술을 간결하게 바꾸거나 실패 원인을 보고할 때)

(우회적인 서술이 같은 행동을 길게 나타낼 때)
[검토를 진행하다처럼 착수·진행·완료를 구별하는 말과 공정명은 그 구별을 유지한다.]
KP-VER-002 책임·역할·후속 행동을 정하는 문장에서는 확인된 행위자·대상을 드러낸다.
(누가 실행하거나 책임질지 독자의 행동을 결정할 때)
[행위자보다 결과 상태가 중요하거나 행위자가 알려지지 않은 상태 알림은 피동을 유지한다.]
KP-VER-004 여러 시점의 상태를 비교하거나 다른 날 읽는 문서에서 상대 시점의 기준을 식별해야 할 때 과거 사건·현재 상태·예정 행동을 구별하고, 시간 기준이 바뀌면 확인된 날짜나 기준을 밝혀 시제를 맞춘다. 항상 성립하는 기능 설명·제목에는 사건 날짜를 강제하지 않는다.
KP-VER-005 시험·준비 상태·비의도성·변화·진행·결과 상태를 보존한다. '-고 있다'는 동사 뜻과 문맥으로 진행/결과 유지를 구별하고 중복만 줄인다.
(보조서술어·'-고 있다'를 편집할 때)
[문맥에서 의미 차이가 없다는 사실이 확인되면 직접 서술어로 줄인다.]
KP-VER-006 잠긴·닫힌·수정된 등의 관형어가 현재 상태인지 과거 행동 결과인지 확인하고 필요한 시점·행위 관계만 밝힌다.
(관형어가 지시 대상을 고르는 기준일 때)
[공유된 속성 이름이나 한 대상의 현재 상태가 명확하면 긴 관계절로 풀지 않는다.]
KP-WARN-001 제품·업무에 정해진 안전 표지·위험도를 지키고 추정으로 격상·격하하지 않는다. 단순 기능 오류를 인명 안전 체계로 바꾸거나 없는 조직 위험 수준을 만들지 않는다.
KP-WARN-002 안전 행동이 필요한 경고는 해당 행동 전에 배치하고 위험 조건과 확인된 금지·필수 행동을 함께 밝힌다.
(독자가 실행 중 위험에 노출될 수 있는 절차)
[단순 위험 가능성만 전달하는 문맥에는 알려지지 않은 대응 절차를 추가하지 않는다.]
KP-WARN-003 안전 판단에 필요하면 확인된 위험이나 가능한 결과를 해당 조건과 연결하고 가능성을 확정 피해로 바꾸지 않는다.
(독자가 경고의 이유와 행동 결과를 알아야 할 때)
[대상과 위험이 공유된 짧은 경고에서는 이유를 반복하지 않는다.]
KP-WARN-004 안전·업무 금지의 행동·조건을 정확히 써 조건부 허용을 전면 금지·무조건 허용으로 바꾸지 않는다. 확인된 전면 금지에 새 조건을 만들어 완화하지 않는다.
KP-WRD-001 용어는 문맥의 뜻·대상·서술어 결합을 확인해 같은 뜻의 익숙한 표현을 고른다.
(일반어와 전문어 중 표현을 고를 때)
[정확한 개념을 구별하는 전문어는 독자에게 낯설어도 유지하고 필요한 첫 설명만 제공한다.]
KP-WRD-002 문서·작업 안에서 한 용어는 한 뜻으로 쓴다. 뜻이 바뀌면 차이를 밝힌다. 대상 명칭은 KP-NAM-001로 통일한다.
(같은 용어가 상태·절차의 여러 단계를 가리킬 때)
[분야와 작업이 달라 같은 표제어가 다른 뜻을 갖는 경우에는 해당 구역의 정의를 밝힌다.]
KP-WRD-003 어휘 추가·활용 대응은 승인 뜻·품사·활용·분야·독자·논항/조사 패턴을 기록해 표면형과 연결한다. 생성한 활용형도 이 패턴을 지킨다. 명사형·관형형은 문장 기능이 명확하고 등록 뜻을 유지하면 생산적 활용으로 허용하고 제목·UI에 목적어·종결어미를 강제하지 않는다. 미등록 품사전환·다른 뜻의 활용·새 의미·동작은 따로 검토한다.
KP-WRD-004 독자에게 낯선 축약어는 첫 사용에서 전체 명칭과 연결하고 이후 같은 축약어를 쓴다.
(문서 내부 축약이나 조직별 약어를 처음 소개할 때)
[대상 독자가 공통으로 아는 표준 약어나 코드·파일 확장자는 반복해서 풀지 않는다.]
KP-WRD-005 업무 지시에서 독자에게 공유되지 않은 은어·비유·조직 내부 별칭은 확인된 대상과 동작으로 표현한다.
(은어나 비유가 실행 대상·결과를 둘 이상으로 해석하게 할 때)
[인용·대화 분석·공유된 공식 별칭은 보존하고 문맥이 뜻을 하나로 정하면 치환을 강제하지 않는다.]
KP-WRD-006 일반 한국어는 현행 맞춤법과 띄어쓰기를 따르고 문서의 같은 명칭은 같은 표기로 쓴다.
(대체 표기·외래어 표기가 문서에서 섞일 때)
[공식 상품명·파일명·코드·원문 인용은 실제 문자열을 보존하며 오탈자처럼 보여도 임의로 고치지 않는다.]
KP-WRD-007 미등록 표현은 일반 표현·전문명사·전문동사의 해당 경로로 검토해 뜻·범위·결합 근거를 기록한다. 미등록만으로 의미 불명·금지로 단정하지 않는다. 식별 문자열·인용·미등록 일반어는 문맥상 뜻이 명확하면 유지 후보로 두되 새 전문 의미를 일반 표현으로 자동 승인하지 않는다.
KP-WRD-008 등록 단어의 결합도 새 전문 의미·동작·결과를 만들면 뜻·논항·분야·예문을 별도 검토한다. 개별 어휘 승인을 새 결합 의미로 확대하지 않는다. 새 의미 없는 단순 수식·한국어 활용·문자 그대로의 행동 나열에는 별도 승인을 강제하지 않는다.

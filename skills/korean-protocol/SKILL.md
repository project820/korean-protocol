# Korean Protocol

KP 기준의 작성·재작성·정리를 요청받은 작업에만 적용한다. 사용자가 지정한 범위, 장르, 문체, 형식이 이 규약보다 우선한다.

## 우선순위

1. 사용자 지침, 작업 범위, 지정 장르·높임·형식
2. 의미 보존: 사실, 양태, 범위, 주체, 출처
3. 문서 유형별 구조 배치
4. 간결하고 자연스러운 표현

의미와 구조를 각각 지킨다. 윤문으로 구조 개선을 대신하지 않고, 구조 변경으로 윤문을 대신하지 않는다.

## 요청 판별

- **표현 교정**: 구조, 순서, 문체를 유지하고 어색한 부분만 고친다. 명확한 문장은 두고, 명사화·번역투·겹친 피동은 같은 행동임이 확인될 때만 고친다.
- **구조 정리·재작성·새 글**: 문서 유형별 구조를 적용하고 이미 충족한 부분은 유지한다.
- **사실 정정·내용 변경**: 근거를 확인하는 별도 작업으로 다루고 바뀐 내용을 밝힌다.

맡긴 범위를 넘는 윤문은 하지 않는다. 실행에 필수이고 문맥으로 정할 수 없는 정보만 묻는다. 위임받지 않은 담당자를 배정하지 않고, '알아서'처럼 방법이 위임된 지시에 새 행동을 강제하지 않는다.

지정이 없으면 새 글은 높임 없이 쓴다. 설명·보고는 ~다, 번호 절차의 독자 행동은 ~한다, 지시는 ~하라, 금지는 ~하지 마라, 요청은 ~해 주기 바란다, 질문은 ~는가로 쓴다. 기존 글은 확립된 문체를 유지하고 독자나 장르만으로 높임을 추정하지 않는다. 사물에 붙은 높임은 없애되 실제 인물의 주체 높임, 인용, 지정 높임은 보존한다.

## 작성 전 정리와 작성 후 대조

사용자가 지정한 형식·문체와 사실 보존이 이 절차보다 우선한다. 결과·완료 보고의 배치 규칙은 결과·완료 보고에만 쓴다.

작성 전에 원문을 끝까지 읽고 아래를 정리한다. 첫 블록을 쓰기 전에 마지막 문단, 설정·변경 이력, 주석, 괄호까지 읽는다.

1. 주장, 역할, 의무, 조건, 시간, 불확실성, 보존 문자열을 정리한다.
2. 사용 한계를 먼저 추출한다. 사용 한계는 언제까지 또는 어떤 사건이 일어나기 전까지 쓸 수 있는지를 정하는 조건이다. 운영 시간과 별도로 다음 항목을 각각 찾는다.
   - 운영 종료 시각과 종료 조건
   - 운영 기간
   - 만료
   - 자동 중지
   - 자원·용량·권한·상태 변화로 인한 조건부 중단
   - 재시작·재설치·재로그인 같은 사건 뒤 등록·설정·권한의 소멸
   원문이 이 조건을 설정 이력이나 경과 설명 안에서 말해도 추출한다. 원문에 없는 한계는 만들지 않는다.
3. 의존 한계를 추출한다. 의존 한계는 독자가 결과를 믿고 쓰기 전에 알아야 할 제한이다. 다음 항목을 각각 찾는다.
   - 미완료 단계, 미통과·미재현·미실행 검사, 직접 확인하지 못한 근거
   - 자료·견적·조사의 적용 범위 한정
   - 다음 행동 전에 갖출 선행 조건
   - 공개·노출 위험
   원문이 이 한계를 추신·각주·마지막 문단에서 말해도 추출한다. 원문이 상태로 진술한 한계만 추출한다. 원문의 권고·의무·향후 확정 절차(‘실측한 뒤 조정한다’, ‘대조한 뒤 확정해야 한다’)를 ‘실측되지 않았다’, ‘확정되지 않았다’ 같은 상태로 바꾸지 않는다. 그런 항목은 원문의 양태 그대로 둔다.
4. 일반 주장과 하위 기능 주장을 짝지어 정리한다. 같은 속성을 말해도 대상 범위가 다르면 별도 주장으로 둔다. 일반 주장의 원문 대상어와 서술어는 그대로 적어 둔다.

작성 후 의미와 구조를 따로 원문과 양방향으로 대조해 누락·변경·추가를 고친다. 이어 아래 항목을 확인한다. 결함이 있으면 최종 본문에서 고친다.

- 조건 위치: 결과·완료 보고라면 추출한 사용 한계가 모두 첫 결과 다음의 사용 조건 블록에 이름 붙은 독립 행으로 있는가. 설정 이력, 제작 경과, 주석, 마지막 문단에만 남은 한계가 없는가.
- 이력 보존: 사용 한계를 옮긴 뒤에도 설정 이력에 등록 대상, 등록 행위, 주체와 관련 필수 정보가 남아 있는가.
- 포괄 주장 대응: 정리한 일반 주장마다 대상과 서술을 모두 쓴 독립 행이 있는가. 하위 기능 행이 일반 주장을 대신하지 않는가. 대상이 빠진 속성 행이 하위 기능 제목 아래에서 좁은 뜻으로 읽히지 않는가.
- 범위: 원문에 없는 ‘모든’·‘전체’·‘항상’을 넣지 않았는가. 원문의 한정어를 지우지 않았는가.
- 대상 명시: 행만 떼어 읽어도 대상과 주체가 정해지는가. 문맥으로 짐작해야만 정해지면 통과로 보지 않는다. 원문에서 확인된 대상명을 쓰고, 확인할 수 없으면 원문 표현을 그대로 둔다.
- 양태·출처: 옮긴 한계와 주장이 원문의 양태와 출처 표시를 유지하는가. 원문이 전한 내용을 확인된 사실처럼 단정하지 않았는가.
- 첫 판단: 첫 실질 문장이 원문의 핵심 판단을 말하는가. 원문이 결과의 사용·의존을 제한하는 상태를 말하는데 일부 성공·배경·조사 과정으로 시작하지 않았는가.
- 제약 위치: 추출한 의존 한계가 첫 판단 바로 다음 블록에 있는가. 추신·각주·마지막 문단에만 남은 한계가 없는가.
- 문장: 한 문장이 독립된 주장이나 행동을 둘 이상 담지 않는가. 표 셀과 불릿 안도 확인한다.
- 후속 행동: 종료 후 할 행동과 남은 기록 반영이 한 연속 블록에 있는가. 중간에 설정 이력이 끼어 있으면 후속 행동을 다시 모은다.
- 항목: 입력·표시·점검 항목이 각자 한 행이나 이름 붙은 셀에 있는가. 항목 이름들만 한 불릿에 줄줄이 나열하지 않았는가.
- 길이: 이미 짧고 명료한 원문 문장을 늘리지 않았는가.

이 과정, 규칙 번호, 판정 문구는 출력하지 않는다. 최종 본문만 제출한다.

## 첫 판단과 의존 한계

결과·완료 보고뿐 아니라 분석, 검토 판정, 질의 답변, 조사 보고에도 적용한다.

- 첫 실질 문장에는 원문의 핵심 판단을 쓴다. 질문에 답한 원문이면 답을, 검토면 판정을, 조사면 핵심 발견을 쓴다.
- 원문이 결과의 사용·의존을 제한하는 상태를 말하면 그 상태를 첫 실질 문장에 결과와 함께 쓴다. 제한하는 상태는 실패, 금지, 미완료 단계, 미통과·미검증, 보완 필요다. 일부 성공만으로 시작하지 않는다.
- 핵심 판단 자체가 미확인·미해결이면 배경이나 조사 과정보다 그 상태를 먼저 쓴다.
- 첫 판단 바로 다음 블록에 추출한 의존 한계를 한계마다 한 행씩 둔다. 첫 문장에 이미 쓴 제한은 이 블록에 다시 쓰지 않는다. 한계의 상세 근거가 길면 이 블록에는 한계의 대상과 상태만 쓰고 상세는 해당 절에 둔다. 같은 문장을 두 곳에 반복하지 않는다.
- 원문이 통상적인 조건으로 말한 것을 실패로 강화하지 않는다.

## 문장

- 한 문장에는 주장 하나나 행동 하나를 둔다. 독립된 두 주장이나 두 행동을 ‘~고’, ‘~며’, ‘~지만’, ‘~는데’로 잇지 않고 문장을 나눈다. 두 문장의 관계는 ‘그러나’, ‘따라서’, ‘그래서’로 남긴다.
- 조건 하나와 결과 하나, 원인 하나와 결과 하나는 한 문장에 둘 수 있다.
- 불릿, 표 셀, 인용할 질문 문장에도 같은 기준을 쓴다. 질문 하나가 확인 대상이나 확인 속성 셋 이상을 물으면 질문 아래에 하나씩 나열한다.
- 문장을 나눌 때 앞 문장으로 정해지는 주어와 대상은 반복하지 않는다. 문장을 나눈 결과로 분량이 늘면 반복된 말부터 줄인다.
- 원문의 단정 수준을 유지하고, 원문에 없는 완곡어나 강조어를 넣지 않는다.

## 표와 이름표

- 원문의 비교 표는 표로 유지한다. 표의 한 행을 제목과 여러 속성 행으로 풀지 않는다. 한 셀이 독립 속성을 둘 이상 담으면 열이나 행을 나눈다.
- 원문이 구분하지 않은 열·행을 새로 만들지 않는다. 원문 값 하나를 원문이 구분하지 않은 여러 칸에 복제하지 않는다. ‘원문에 없음’, ‘원문 미구분’ 같은 편집 메모를 출력에 쓰지 않는다.
- 속성 이름표(`- 이름: 값`)는 독자가 비교하거나 찾아볼 독립 속성에만 붙인다. 이유·목적·근거·현재 상태를 설명하는 문장에 ‘이유:’, ‘목적:’, ‘현재 상태:’ 같은 이름표를 새로 붙이지 않고 문장으로 쓴다.
- 근거와 그 근거가 뒷받침하는 판단을 떼어 쓰면 ‘근거:’나 ‘따라서’로 관계를 남긴다.

## 의미 보존

- **진실성**: 사실, 추정, 가능성, 확인, 전언과 그 출처를 구별한다. 모호한 주장은 원문의 한정어를 유지하거나 인용한다. 원문이 말한 외부 사실을 편집자가 검증한 것처럼 쓰지 않는다.
- **양태**: 의무, 허락, 가능, 권고를 서로 바꾸지 않는다. '수 있다'를 확정으로, 허락을 명령으로 바꾸지 않는다. '할 수 있다'가 능력·가능성·허락 중 어느 뜻인지 원문에서 확정되지 않으면 그 서술을 그대로 둔다. 새 제목이나 속성명으로 뜻을 확정하지 않는다. 특히 '권한'·'허용'·'자격'은 원문이 그 의미를 명시할 때만 쓴다. 가능한 행위와 그 행위를 허가받은 상태는 같은 주장이 아니다.
- **부정·부분**: 전면 부정과 부분 부정, 모두·각각·적어도·만·일부, 및·또는, 항목별 값과 합계를 보존한다. 못 했다·안 했다의 원인을 근거 없이 확정하지 않는다.
- **주체**: 행위자, 대상, 수신자, 소유를 보존하고 주체가 바뀌면 이름을 쓴다. 시스템 자동 처리와 독자 행동을 구별한다. 원문 작성자가 독자에게 보고한 실행을 편집자의 새 실행 주장으로 바꾸지 않는다.
- **단계**: 준비·요청·실행, 시작·진행·완료·중단을 유지한다.
- **시험의 범위**: 시험 대상·방법·시도·관측 결과·성공 판정을 구별한다. '찾는 방식으로 시험했다'는 방법이며 '찾았다'는 성공 결과다. 원문이 방법이나 시도만 보고하면 그 서술을 보존하고 결과를 만들지 않는다. 시험 항목을 목록으로 나눌 때도 공통 서술이 각 항목에 적용되게 한다. '시험 방법' 아래 항목을 두거나 각 항목에 시험했다는 서술을 남긴다. '확인'·'성공'·'완료'라는 표제도 원문이 보고한 결과를 넘지 않아야 한다.
- **조건**: 조건, 예외가 면제하는 대상, 기본·우선, 비교 방향을 유지한다. 선택적 행동은 원문의 조건부 시점과 함께 둔다. 서로 이웃한 권고와 후속 가능 행동을 새 조건문으로 연결하지 않는다. 원문에 없는 ‘~했다면’·‘~해야만’을 넣지 않는다. 원문이 권고 시점을 정하지 않았으면 ‘작업 전 권고’나 ‘종료 후 권고’ 같은 제목을 새로 붙이지 않는다. 시점 없는 권고는 시간 단계 밖의 별도 권고 항목으로 둔다. 권고와 후속 가능 행동은 각각 보존한다.
- **수치·시간**: 대상, 단위, 정밀도, 경계와 약·최대·평균·기본값의 성격을 보존한다. 반복 주기, 처리 시간의 실측 표본, 지연 상한, 운영 시간, 종료 조건은 서로 다른 사실로 둔다. 원문이 주장한 상한과 허용은 삭제·강화·약화하지 않는다. 근거 없는 새 숫자나 보장을 만들지 않는다.
- **모순**: 원문 안의 모순을 임의로 해소하지 않는다. 양쪽을 남기거나 불일치를 밝힌다.

미표기, 미확인, 확인된 부재를 구별한다. 원인, 시험, 수치, 담당자, 날짜, 후속 약속을 명료화를 이유로 더하지 않는다. 편집 결과를 알릴 때는 실제로 한 변경만 쓴다.

## 보존과 일관성

인용, 코드, 명령, 경로, 링크, 버전, ID, 공식 명칭, 파일명, 수치 문자열은 부호·대소문자·공백까지 그대로 둔다. 오탈자처럼 보여도 고치지 않는다.

안전 표지, 위험 등급, 조건부 허용과 전면 금지의 구분을 바꾸지 않는다. 경고는 위험 행동 앞에 둔다. 주석·팁에 있는 필수 행동, 안전 조치, 필수 요구조건, 허용 한계는 본문 절차나 사양으로 옮긴다.

같은 대상에는 같은 명칭을, 같은 행동에는 같은 동작어를 쓰고 같은 문맥에서 한 용어는 한 뜻으로 쓴다. 낯선 줄임말은 처음 나올 때 전체 명칭을 붙인다. 지시어나 생략된 대상의 후보가 둘 이상이면 확인된 대상명을 쓴다.

## 주장 범위를 보존한다

같은 대상, 같은 속성, 같은 범위·조건의 반복만 합친다. 일반 주장과 특정 하위 기능·단계의 주장은 같은 속성을 말해도 중복이 아니다. 둘 다 보존한다.

- 일반 주장은 원문의 대상어와 서술을 그대로 쓴 독립 행에 둔다. 연결어미는 종결형으로 바꿀 수 있지만 대상·서술·양태는 유지한다. 하위 기능 제목 아래에 두지 않는다. 대상을 생략한 속성 행으로 바꾸지 않는다. 대상이 빠진 행은 앞 제목의 좁은 범위로 읽힌다.
- 하위 기능 주장은 일반 주장 다음의 별도 행에 둔다. 행 이름이나 문장에 하위 기능명을 쓴다. 하위 기능 주장만 남겨 일반 주장을 대신하지 않는다.
- 범위를 넓히거나 좁히지 않는다. 원문에 없는 ‘모든’·‘전체’·‘항상’을 넣지 않는다. 원문의 한정어를 지우지 않는다. 하위 기능의 조건이나 시점을 일반 주장에 옮기지 않는다.
- 이미 짧고 명료한 일반 주장은 그대로 둔다. 설명을 붙여 늘리지 않는다.
- 중복인지 확정할 수 없으면 두 주장을 모두 원문대로 보존한다.
- 단계·기산점·조건이 다른 사실은 합치지 않는다. ‘끝나면’ 같은 원문의 기산 사건을 확인되지 않은 특정 도구·작업의 종료로 바꾸지 않는다.

대조 예시(가상이며 원문에 적용하지 않는다):
- 원문: ‘메시지는 암호화된다.’ ‘첨부 메시지는 전송 전에 암호화된다.’
- 잘못된 결과 1: 첨부 메시지 제목 아래 ‘- 암호화: 전송 전’만 남긴다.
- 잘못된 결과 2: ‘모든 메시지는 전송 전에 암호화된다.’로 합친다.
- 바른 결과:
  - 메시지는 암호화된다.
  - 첨부 메시지 암호화 시점: 전송 전

## 문서 구조

### 결과·완료 보고

결과·완료 보고에만 이 틀을 쓴다. 사용자가 형식·문체를 지정하면 그것을 따르고, 그 형식이 허용하는 범위에서 아래 배치를 적용한다.

첫 결과는 다음 둘 중 원문에 해당하는 하나로 결정한다.
- 원문이 결과의 사용·의존을 제한하는 상태(실패, 금지, 미완료 단계, 미통과·미검증, 보완 필요)를 말하면 그 제한을 첫 실질 문장에 쓴다. 일부 실행·시험의 성공은 뒤에서 별도로 보고한다. ‘정상 실행’로 시작한 뒤 사용 조건 블록에서 금지를 밝히지 않는다.
- 그런 실패·금지가 없으면 완료 대상과 접근 위치를 짧게 쓴다. 원문의 통상적인 사용 조건을 최종 실패로 바꾸지 않는다.

운영 시간·주기·조건을 도입 문장에 한꺼번에 넣지 않는다.

바로 다음 첫 실질 블록은 사용 조건 블록이다. 이 블록에 다음 항목을 둔다.
- 사전 권한·접근 조건
- 사용 가능 조건
- 운영 필수조건
- 사용 중 계속 지킬 조건
- 운영 시간
- 사용 한계
- 공유·노출 범위

사용 한계는 작성 전 정리에서 원문 전체로부터 추출한 조건이다. 운영 종료 시각·종료 조건, 운영 기간, 만료, 자동 중지, 사건 뒤 등록·설정·권한의 소멸이 여기에 속한다. 원문 어디에 있었든 이 블록으로 옮긴다. 자원 부족이나 상태 변화로 처리가 멈추는 조건도 사용 한계다. 중단 조건과 함께 정해진 결과·보존 상태는 같은 행이나 바로 다음 행에 둔다. 단순 오류 안내나 복구 동작과 혼동해 뒤쪽 기능 설명에만 남기지 않는다. 운영 시간만 앞에 두고 종료·만료·소멸 조건을 뒤 블록에 남기지 않는다.

다음 항목은 각각 이름 붙은 독립 행으로 둔다.
- 운영 시간
- 운영 종료
- 만료
- 소멸 조건
- 확인 주체
- 확인 주기

행 이름에는 무엇이 끝나거나 사라지는지 대상을 쓴다. 원문이 한 구절로 말한 시작·종료 범위는 운영 시간 행에 그대로 둔다. 원문이 따로 말한 종료·만료·소멸은 별도 행으로 둔다. 기산 사건, 경계, 양태, 출처는 원문대로 둔다.

설정 이력에는 누가 무엇을 등록·변경했는지 둔다. 사용 한계를 옮긴 뒤에도 등록 대상, 주체, 행위, 등록에 쓰인 값 같은 관련 필수 정보는 지우지 않는다. 옮긴 한계를 이력에 다시 쓰지 않는다.

배치 예시(가상이며 원문에 적용하지 않는다):
- 원문 배치: 앞부분에 ‘공용 프린터 대기열을 열었다. 평일 업무 시간에 쓸 수 있다.’가 있다. 끝부분 설정 이력에 ‘관리자가 임시 출력 권한을 등록했다. 서버를 재시작하면 이 권한은 사라진다. 대기열은 학기 말에 닫힌다.’가 있다.
- 작성 결과:
  - 첫머리: 공용 프린터 대기열을 열었다.
  - 사용 조건:
    - 운영 시간: 평일 업무 시간
    - 대기열 운영 종료: 학기 말에 닫힌다
    - 임시 출력 권한 소멸: 서버를 재시작하면 사라진다
  - 설정 이력:
    - 임시 출력 권한 등록: 관리자가 등록했다

녹음·수집 간격과 분석·확인 주기는 같은 값이어도 별도 속성이다. 보고된 지연과 그 원인의 관계는 유지한다. 확인 주기 행과 지연 행은 구별한다.

기능 상세, 설계 근거, 제작 경과, 도구 사용 설명은 사용 조건 블록 뒤에 둔다. 첫 결과는 위의 실패·금지 우선 분기를 따른다. 성공과 실패는 대상·단계·검증 수준별로 나눈다. 원문에 없는 최종 판정은 추론하지 않는다.

남은 조치와 사용·미팅 종료 후 할 행동은 기능 설명이나 설정 변경 이력과 분리한다. 이 행동은 해당 시점의 후속 행동 묶음에 모은다. 종료 후 실행 가능한 행동과 나중에 반영할 기록은 하나의 연속된 후속 블록에 둔다. 그 사이에 설정 이력·기능 설명·시험 기록을 끼우지 않는다. 세부 제목은 허용하지만 관련 후속 행동이 문서의 서로 다른 곳에 흩어지면 다시 모은다. 권고·가능·의무의 차이는 유지한다.

### 대상별 행동 안내

행동 대상이 여럿이면 첫 본문 블록에서 대상을 하나씩 별도 불릿으로 나열한다. 문서 중간이라도 독자가 확인·질문·비교·포함 여부 점검을 할 대상이 셋 이상 한 문장·불릿·표 셀에 나열되면 그 자리에서 하나씩 별도 불릿으로 나눈다. 대상이 둘이어도 대상마다 다른 값·결과·행동이 붙으면 나눈다. 나누기 전에 수식 범위를 확인한다. ‘A, B, C와 D의 동작 순서’처럼 수식어가 일부 항목에만 붙으면 그 수식어를 다른 항목에 붙이지 않는다. 범위를 확정할 수 없으면 원문 구절을 한 항목으로 유지한다. ‘대상: A, B, C’처럼 한 행에 합치지 않는다. 공통 담당·기한은 목록 다음에 둔다. 대상별 행동이 다르면 각각 구분한다. 모두·하나, 필수·선택 관계는 도입부에 원문대로 쓴다.

### 방식 비교

선택지마다 제목을 두고 그 아래 속성을 불릿으로 둔다. 원문에 없는 속성은 만들지 않는다. 모든 선택지에 적용되는 규칙은 별도의 동급 제목으로 분리한다.

### 대상·조건별 규정

대상이나 조건에 따라 규칙이 달라지면 대상·조건별 블록을 먼저 만든다. 각 블록에 적용 기한, 판단 기준, 판단 시점, 나중에 바뀌는 조건과 바뀌지 않는 조건을 함께 둔다. 특별 대상의 규칙 일부를 ‘판단 기준’·‘상태 변경’ 같은 동급 제목으로 떼어 내지 않는다. 세부 제목이 필요하면 대상 블록 아래에 종속시킨다. 동급 블록으로 분리해야 하면 제목에 원문의 적용 대상명을 다시 쓴다.

공통 규칙은 원문이 공통이라고 확인한 범위만 별도 블록에 둔다. 바로 앞 문단에서 특정 대상을 언급했다는 이유로 뒤의 독립 블록도 같은 대상에 적용된다고 독자가 추측하게 하지 않는다. 각 규칙의 대상과 적용 범위를 대조한 뒤 제출한다.

### 절차

성격이 다른 항목은 한 번호 목록에 섞지 않고 블록을 나눈다. 안내→응답→미응답 시 후속 처리처럼 실제 시간 순서가 있으면 번호 절차로 쓴다. 자동 처리도 그 단계의 주체를 밝혀 같은 순서에 넣는다. 절차를 속성별 불릿으로 바꾸지 않는다. 조건절의 가정 행위는 새 실행 단계가 아니다. 번호는 그 조건에서 일어나는 처리나 요구된 행동에 붙이고, 조건은 해당 행 앞부분에 붙인다. 가정 행위를 따로 떼어 명령이나 의무로 바꾸지 않는다.

- **사전 준비**: 시작 전에 갖출 것
- **상시 유지 조건**: 사용하는 동안 계속 지킬 것
- **순차 행동**: 실제 선후가 있을 때만 번호를 붙인다. 단계마다 따로 확인할 행동 하나를 두고 실행 동사로 끝낸다.
- **선택적 권고**: 원문의 조건부 시점과 함께 둔다.

부분 대상에만 적용되는 절차·기한·승인 규칙을 새 블록으로 나누면 제목이나 첫 행에 그 대상 범위를 다시 쓴다. 직전 문단에서만 대상을 찾을 수 있거나 공통 규칙처럼 읽히면 분리를 고친다. 원문이 여러 단계에 적용한다고 확인한 조건만 도입 줄에 둔다. 앞 조건을 후속 단계로 확대하지 않는다. 예외는 면제하는 조건 옆에 둔다. 전·후·동안·동시 관계를 드러낸다. 짧은 조건 하나와 행동 하나는 한 문장으로 둘 수 있다.

### 설명·교육

이해 순서를 따르고 뒤 설명의 전제가 되는 정의를 먼저 준다. 직접 답을 요구한 질문에는 답부터 준다.

## 기한

시간 구절이 있다고 모두 행동 기한은 아니다. 먼저 시간의 역할을 구분한다.
- 원문이 행동의 완료 기한·의무를 정하면 기한으로 표시한다.
- 어떤 결과가 생기는 시간 조건이면 그 결과의 ‘적용 조건’으로 쓴다. 조건 안의 선택적 행위에 ‘기한’을 붙이거나 그 행위를 하라는 문장을 더하지 않는다.
- 관측 시간·반복 주기·운영 시간·조건부 중단은 원문의 각 의미대로 표시한다.

예를 들어 ‘주문을 15:00 전에 확정하면 당일 발송한다’는 당일 발송 조건이다. ‘확정 기한: 15:00’이나 ‘주문을 확정한다’라는 의무를 만들지 않는다.

실제 행동 기한은 관련 행동 블록 안에 '○○ 기한: 원문 시간 구절'로 독립 표시하고 수행자와 행동은 다음 줄에 둔다. 기산 사건, 경계, 영업일 여부, 기본 기한과 예외 기한의 대체 관계를 원문대로 보존한다. 새 날짜·시간대·휴일 계산을 만들지 않는다.

행동을 좌우하는 시간 값은 값마다 한 행에 둔다. 제한시간, 최대 대기 시간, 지급 시점, 유효기간, 재기산 규칙, 작업 중지 시간처럼 서로 다른 시간 값을 한 행이나 한 문장에 묶지 않는다.

## 형식 선택

사용자가 지정한 형식이 우선한다. 그다음 행동 대상 목록과 순차 절차 규칙을 먼저 적용한다. 아래 속성 행은 그 밖의 사양·기능·상태·비교 설명에만 적용한다. 별도 지정이 없고 대상에 독립 속성이 둘 이상 있으면 **대상 제목 + 속성별 행**으로 작성한다. 한 행의 형식은 `- 속성명: 해당 값·행동·조건`이다. 비교할 때는 `속성 | 값` 표를 써도 된다. 속성명으로 답을 바로 찾게 하며, ‘내용·상세·구성·변경’ 같은 포괄 이름 아래 여러 속성을 다시 모으지 않는다.

수량, 정렬, 검색 범위, 위치, 총액, 차액, 규격, 방식, 대수, 계산 대상, 기준량, 기준 시간, 입력된 필드, 빈 필드는 서로 다른 질문이다. 원문에 있는 속성만 각각 별도 행으로 만든다. 한 항목에 다른 단위의 수치가 여럿 있거나 동작과 수량이 함께 있으면 독립 속성인지 다시 나눈다. 하나의 값과 단위·조건은 함께 둔다. 입력 칸, 화면 표시 항목, 점검 항목은 이름만 열거돼 있어도 각각 독립 불릿이나 이름 붙은 셀로 쓴다. 서로 다른 날짜·시작 시각·종료 시각·대상 식별자를 ‘입력 항목’ 한 불릿에 나열하지 않는다. 서로 다른 측정값·식별자·갱신 시각을 ‘표시 내용’ 한 불릿에 나열하지 않는다. 공통 주체·상태는 제목이나 도입 한 줄에서 밝히고 항목마다 되풀이하지 않는다. 장비·제품 이름을 속성명으로 삼아 규격·방식·대수를 한 값에 합치지 않는다. 변경 전후가 있는 속성은 해당 행 안에서 변경 방향을 보존한다. 예컨대 한 계산의 대상·기준량·기준 시간도 같은 제목 아래 각각 이름을 붙여 관계를 유지한다. 원인과 결과, 조건과 행동을 나눌 때는 관계를 명시한다. 행을 떼어 읽어도 적용 범위가 같아야 한다. 특정 기능의 사용 여부를 전체 시스템의 사용 여부로 넓히지 않도록 행 이름에 범위를 쓴다. 새 제목·속성명도 주장이다. 원문이 확인하지 않은 작동 범위·정렬 대상·선후·인과를 이름으로 추가하지 않는다. 속성별 행을 쓴 뒤 같은 내용을 설명 문장으로 반복하지 않는다.

속성 분리 예시(가상 수치이며 원문에 적용하지 않는다):
- 묶인 표현: 장치가 40W에서 25W 수랭식 2대로 바뀌었다.
- 분리 결과:
  - 소비전력 변경: 40W → 25W
  - 변경 후 냉각 방식: 수랭식
  - 변경 후 대수: 2대

절차는 앞 절의 번호 규칙을 따른다. 짧은 상태 하나나 짧은 조건 하나와 행동 하나는 문장으로 둔다. 독립 속성이 없는 설명 문장까지 기계적으로 쪼개지 않는다.

출력 전에 초안을 다시 읽는다. 아래 결함이 보이면 최종 본문에서 고친 뒤 제출한다. 점검 과정과 통과 여부는 출력하지 않는다.
- 한 행이나 불릿이 둘 이상의 질문에 답한다. 특히 대상만 목록화하고 수량·위치·정렬·규격·계산 기준을 그 뒤 문장에 몰아넣었다.
- 조건·절차만 나누고 다른 속성은 한 덩어리로 남았다.
- 나누면서 값과 단위, 조건과 행동이 떨어졌다.
- 결과 보고에서 사전 권한이나 유지 조건이 첫 실질 블록 밖에 있다.

상태·결과·표제는 대상·범위·양태가 명확하면 짧은 명사형으로 쓸 수 있다. 요청과 실행처럼 행동·시점을 바꾸는 축약은 하지 않는다. 핵심 조건은 괄호에 숨기지 않고, 슬래시나 세미콜론만으로 조건·선택·인과를 나타내지 않는다. 새 정보 없는 제목·예고·맺음말·요약과 작성 과정 설명은 넣지 않는다.

## 조회 자료

`specification/rules.json`, `lexicon/core.json`, `lexicon/domains/software.json`은 활용형, 조사 패턴, 전문어 등록, 사용 중단 표현 같은 드문 판단에만 해당 항목을 조회한다. 일반 작성에는 읽지 않는다. 조회하지 않았으면 등록 여부나 규칙 충족을 확인했다고 말하지 않는다. 미등록이라는 이유만으로 금지하지 않는다.

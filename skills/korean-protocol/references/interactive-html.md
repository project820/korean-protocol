# 변수와 결과를 연결하는 단일 HTML을 만든다

사용자가 인터랙티브 출력을 요청하거나 변수 조작·상태 전환이 이해에 필요할 때 읽는다. 설명만으로 충분하면 L1·L2를 사용한다. 사용자 지정 파일명이 없으면 `index.html` 파일 하나를 만든다.

## 입력·계산·조건의 근거를 먼저 정한다

- 입력값의 이름·단위·허용 범위·초기값을 정한다. 실제 자료에 없는 가정이나 교육용 수치는 가정·예시로 표시한다. 출처의 기재값과 사용자가 바꾼 값을 구분한다.
- 결과의 이름·단위·산출식·근거값을 연결한다. 예외·세금·포함 범위가 다르면 합계 전체의 공통 조건으로 표시하지 않는다. 모든 입력 조합에 성립한다고 확인하지 않은 결론은 보장으로 쓰지 않는다.
- 사용자 자료를 HTML에 넣을 때 텍스트 노드를 사용하거나 HTML 이스케이프를 수행한다. 문자열을 `innerHTML`에 넣거나 자료를 스크립트로 평가하지 않는다. JavaScript 소스 안에 원문을 넣어야 하면 `</script>` 종료까지 안전하게 직렬화한다.

## 화면 골격과 컨트롤 어휘를 고정한다

화면은 아래 순서로 쌓는다. DOM 순서, 읽기 순서, 초점 순서를 이 순서와 같게 둔다. 내용이 없는 구획은 만들지 않는다.

1. **제목(`h1`):** 화면이 답하는 내용을 '한다' 문장 하나로 쓴다.
2. **대상·범위(`p`):** 적용 대상과 조작하면 바뀌는 결과를 한 줄로 쓴다. 문서 전체에 걸리는 고지는 이 줄 아래에 한 번 쓴다.
3. **결과 패널(`section`):** 현재 입력에 따른 결과를 보인다.
4. **입력 패널(`section`):** 결과를 바꾸는 입력을 모은다.
5. **규칙·산출식(`section`):** 입력과 무관하게 성립하는 규칙 전체와 산출식을 쓴다.
6. **참고(`section`):** 출처, 계산에 넣지 않은 항목, 저장·전송 여부를 쓴다.

패널과 구획의 제목(`h2`)은 '월 전력 소비량'·'사용 조건'·'산출식'·'참고'처럼 명사구 표지로 쓴다.

### 두 패널은 리플로 격자에 둔다

결과 패널과 입력 패널만 격자에 넣는다. 넓은 화면에서는 결과가 왼쪽, 입력이 오른쪽에 온다. 좁은 화면에서는 결과가 위, 입력이 아래에 온다.

```css
.panel_layout {
  display: grid;
  gap: var(--space-4);
  grid-template-columns: repeat(auto-fit, minmax(min(22rem, 100%), 1fr));
  align-items: start;
}
.panel_layout > * { min-inline-size: 0; }
```

- 열 수는 이 격자가 정하고, 시각 순서는 DOM 순서가 정한다. 미디어 쿼리의 열 전환과 `order`·`grid-area`·`row-reverse`·`float` 재배치는 쓰지 않는다.
- 격자 규칙에는 배치 속성만 둔다. 색·테두리·그림자·글자 규칙은 `.panel`에 둔다.
- 스크롤은 문서가 맡는다. 넓은 표의 가로 스크롤 영역만 예외다.
- 패널 높이는 내용이 정한다. `sticky`·`fixed` 고정은 초점이 있는 입력과 오류를 가릴 수 있어 쓰지 않는다.

### 결과 패널은 값·근거·조건 순서로 쓴다

1. **제목:** 결과의 이름을 쓴다.
2. **결과값(`output`):** 수치 결과는 값과 단위를 쓴다. 상태 결과는 '누가 무엇을 한다' 문장 하나로 쓴다. 조치가 순서대로 이어지면 번호 목록으로 쓴다.
3. **근거 한 줄:** 수치 결과에는 현재 값을 대입한 산출식을 쓴다. 상태 결과에는 그 결과를 정한 조건을 쓴다.
4. **조건·경고:** 현재 결과에 걸린 기한·예외·금지를 쓴다. 다른 선택에서만 성립하는 규칙은 규칙·산출식 구획에 둔다.
5. **가정:** 결과값을 바꾸거나 적용 범위를 한정하는 가정을 '가정:' 표지와 함께 쓴다.

- 결과가 독자의 행동을 지시하고 그 행동에 필수 조건·경고·금지가 걸리면, 그 조건을 결과값 앞에 둔다.
- 결과 패널은 하나만 둔다. 조건마다 패널을 나누면 독자가 결과를 여러 곳에서 찾게 된다.
- 결과값·조건·경고·가정은 항상 펼쳐 둔다.
- 결과 패널은 짧게 쓴다. 규칙 표와 긴 설명은 아래 구획으로 보낸다. 좁은 화면에서 입력을 바꾸는 동안 결과값을 화면에 남기려는 것이다.
- 입력 오류가 있으면 결과값 자리에 '계산을 보류한다'를 쓴다.
- `output`의 `for`에 결과를 정하는 입력의 `id`를 적는다. 결과 영역에 `aria-live="polite"`를 둔다.

### 입력 패널은 결과를 바꾸는 입력만 둔다

- 판단을 크게 바꾸는 입력을 앞에 둔다. 핵심 입력은 세 개 안으로 둔다. 나머지는 같은 패널 아래쪽의 '세부 조건' 묶음에 둔다.
- 한 입력은 라벨, 컨트롤, 힌트, 오류 순서로 DOM에서 붙여 둔다.
- 라디오·체크박스 묶음은 `fieldset`과 `legend`로 묶는다. 단일 입력에는 `label`을 잇는다.
- 라벨은 '소비전력(kW)'처럼 이름과 단위를 명사구로 쓴다. 라벨 자리에 placeholder를 쓰지 않는다.
- 선택지 문구는 원자료의 표현을 쓴다.
- 초기 선택은 원자료가 먼저 적은 경우로 둔다. 원자료에 초기값이 없는 수치에는 값을 넣고 힌트에 '가정'을 쓴다.
- 버튼은 초기화 하나만 패널 끝에 둔다.

| 입력의 성격 | 컨트롤 | 지킬 점 |
|---|---|---|
| 서로 배타적인 선택지 2~4개 | 라디오 묶음 | 선택지를 모두 펼쳐 보인다. |
| 서로 배타적인 선택지 5개 이상 | `select` | 첫 항목은 실제 선택지로 둔다. '선택' 같은 빈 항목은 두지 않는다. |
| 켜고 끄는 조건 하나 | 체크박스 | 라벨에 켠 상태의 뜻을 쓴다. |
| 원자료가 경계로 나눈 조건 | 라디오 묶음이나 `select` | 범주를 그대로 선택지로 둔다. 수치 입력으로 바꾸면 원자료에 없는 경계값 판정이 생긴다. |
| 원자료에 없는 수치 | 만들지 않는다. | 남은 시간·경과 시간·인원 수처럼 원자료가 값을 주지 않은 변수는 입력으로 두지 않는다. 상태가 필요하면 원자료가 밝힌 상태를 선택지로 둔다. |
| 수치 | `input type="number"` | `min`·`max`·`step`과 단위를 정한다. |
| 천 단위 구분이 필요한 금액 | `input type="text"`와 `inputmode="numeric"` | 입력하는 동안에는 문자열을 고쳐 쓰지 않는다. 입력이 끝난 뒤(`change`)에 구분 기호를 맞춘다. |
| 근거 있는 범위 안의 수치 탐색 | `input type="range"`와 숫자 입력 한 쌍 | 두 컨트롤이 같은 값을 보인다. 원자료에 없는 범위는 '가정'으로 표시한다. |
| 다른 선택에 딸린 조건 | 같은 컨트롤을 `disabled`로 둔다. | 적용 조건을 힌트에 쓴다. 컨트롤을 숨기지 않는다. |

### 다음 패턴은 쓰지 않는다

| 패턴 | 대신 쓰는 방법 |
|---|---|
| 빈 결과('—', 0, '결과가 여기에 표시된다')로 시작한다. | 초기값으로 계산한 결과를 첫 화면에 보인다. |
| 계산·확인 버튼을 눌러야 결과가 나온다. | `input`·`change` 이벤트에서 바로 다시 계산한다. |
| 어두운 배경을 기본으로 쓰거나 `prefers-color-scheme`으로 테마를 바꾼다. | 예제의 밝은 테마 하나를 쓴다. 사용자가 요청하면 테마를 바꾼다. |
| 입력이나 규칙 표를 결과보다 앞에 둔다. | 결과 패널을 먼저 둔다. |
| 조건마다 패널과 결과를 따로 둔다. | 결과 패널 하나에 현재 결과를 모은다. |
| 원자료의 범주 조건을 수치 입력으로 바꾼다. | 범주를 선택지로 둔다. |
| 조건·경고를 탭·접힌 구역·툴팁·모달에 넣는다. | 결과 패널 안에 펼쳐 둔다. |
| 구획 제목마다 '~를 확인한다'를 되풀이한다. | 명사구 표지를 쓴다. |
| 카드 안에 카드를 넣거나 아이콘·이모지·그라데이션·그림자로 꾸민다. | 예제의 토큰과 `.panel` 하나로 구획을 나눈다. |

### 골격을 바꿔도 되는 경우

- 사용자가 배치를 지정하면 그 지정을 따른다.
- 결과가 표나 차트여서 한 열에 담기지 않으면 결과를 한 줄 전체에 둔다. 입력 패널은 그 아래에 두고 순서는 유지한다.
- 조작할 입력이 없는 자료는 L2로 쓴다.


## 첫 화면에서 의미 있는 비교를 보여준다

- 초기 상태에서 결과가 의미를 갖게 한다. 자료에 없는 값을 사용자가 모두 채워야 결과가 생기는 빈 입력칸 위주의 계산기를 만들지 않는다.
- 판단을 바꾸는 핵심 변수 한두 개를 먼저 조작하게 한다. 손익분기점이나 순위 역전점이 있으면 슬라이더와 기준선으로 보여준다. 자료에 없는 범위를 슬라이더 범위로 쓰면 가정으로 표시한다. 핵심 판단은 결과 패널에 둔다. 핵심 변수는 입력 패널의 앞쪽에 두고 세부 입력은 그 아래에 둔다.
- 금액·수량은 입력칸과 결과 모두 천 단위 구분 기호로 표시한다. ‘[확인불가]’ 같은 보호 문자열과 숫자·단위 묶음은 줄바꿈으로 갈라지지 않게 한다.
- 문서 전체가 가로로 스크롤되지 않게 한다. 넓은 표는 표 자체의 가로 스크롤 영역에 넣거나 좁은 화면에서 대상별 카드로 바꾼다.
- 높이를 맞추려고 카드 안에 큰 빈 공간을 만들지 않는다. 한 카드에만 있는 제어는 카드 아래쪽이나 별도 줄에 둔다.
- 원문 전체를 HTML에 복제하지 않는다. 계산과 판단에 필요한 근거만 넣고, 나머지는 원문 문서명과 절로 연결한다. ‘보고서를 보존했습니다’ 같은 작업 보고 문장을 화면 제목으로 쓰지 않는다.
- 화면의 문장형 안내·상태·경고는 높임말 없이 ‘한다’체로 쓴다. 입력 라벨·버튼·표 머리글은 ‘일반 정산액(원)’·‘전체 초기화’처럼 명사구로 쓴다. ‘일반 정산액을 입력한다(원).’ 같은 문장형 라벨을 쓰지 않는다. 화면의 큰 제목은 ‘4사 견적의 금액과 공사 범위를 함께 비교한다.’처럼 완결된 ‘한다’체 문장으로 쓴다. ‘~하세요’처럼 독자에게 명령하는 제목을 쓰지 않는다. ‘4사 견적, 금액과 범위를 함께.’처럼 끝나지 않은 구를 마침표로 끝내지 않는다. 사용자가 다른 어체를 정하면 그 지정을 따른다. 패널과 구획의 제목은 명사구 표지로 쓴다.

## 외부 의존성 없이 읽고 조작하게 한다

[재사용 예제](../assets/interactive-explainer.html)를 복사해 시작한다. `<style>`의 토큰과 `.panel_layout`은 유지하고 문구·입력·계산을 해당 작업의 자료로 바꾼다. 예제는 교육용 전력 소비량 계산이며 실제 요금·안전·설비 용량의 판단 자료가 아니다. 예제 수치나 경고 문구를 관련 없는 작업에 복제하지 않는다.

- HTML·CSS·JavaScript를 한 파일 안에 둔다. CDN·외부 폰트·패키지 설치·빌드·외부 통신 없이 브라우저에서 실행하게 한다. 외부 연결이 필요한 작업은 이 기본형의 완료로 표시하지 않는다.
- `lang="ko"`, viewport, 의미 있는 제목·제목 계층·레이블·상태 영역을 둔다. 폼 제어는 실제 `label`, `input`, `button`을 사용한다. 키보드 초점과 `focus-visible` 표시를 유지한다.
- 글자·간격·색상 토큰으로 일관된 계층을 만든다. [출력 기본형](output-formats.md)의 읽기 폭과 반응형 배치를 시작점으로 사용한다. UI 장식보다 결과와 조건을 먼저 찾게 한다.
- 경고·가정·중요 조건을 결과·관련 행동 곁에 계속 보인다. 툴팁·접힌 구역·색상만으로 조건을 전달하지 않는다. 긴 출처 문자열과 단위를 좁은 화면에서 잘리지 않게 한다.
- 결과 변경은 필요한 범위에서 `aria-live`로 알린다. 잘못된 입력을 해당 제어와 연결하고, 오류가 있으면 오래된 값을 유효한 현재 결과로 남기지 않는다. 초기화 버튼은 입력·오류·결과를 초기 상태로 되돌린다.
- 폼 제어의 `id`·`name`에 `reset`·`submit`처럼 폼 메서드와 같은 이름을 사용하지 않는다. 같은 이름의 제어가 있으면 `form.reset`이 메서드 대신 제어를 가리킨다. 초기화는 `HTMLFormElement.prototype.reset.call(form)`으로 호출한 뒤 오류와 결과를 다시 계산한다. 예제의 버튼 이름을 바꿀 때도 이 호출을 유지하고, 잘못된 입력에서 초기값으로 돌아가는 동작을 실제로 확인한다.
- 의미 전달에 필요하지 않은 동작 효과는 넣지 않는다. 동작 효과를 넣으면 `prefers-reduced-motion`에서 줄인다. 외부 저장·전송이나 지속성을 구현하지 않았다면 저장·제출 완료 상태를 만들지 않는다.

## 수치와 표시 상태를 함께 확인한다

예제의 초기값은 소비전력 0.8kW, 하루 사용 시간 6시간, 사용 일수 20일이며 결과는 96kWh다. 소비전력을 1.25kW로 바꾸면 결과는 150kWh다. 이는 고정 소비전력 가정의 산술 결과다. 빈 값·음수·범위 밖·소수 허용 규칙 위반은 오류로 표시하며 결과를 보류한다.

실제 산출물에서도 첫 화면이 입력 없이 의미 있는 비교를 보여주는지 확인한다. 초기값·변경값·경계값·잘못된 값·초기화를 검사한다. 새로 연 오프라인 파일, Tab 이동과 버튼 실행, 320px 폭과 200% 확대, 긴 라벨·출처, reduced-motion 상태를 확인한다. 계산 검사는 독립 산출식과 비교한다. 화면 검사는 실제 렌더링으로 확인한다.

보이는 제목·제어 라벨·툴팁·오류·JavaScript가 바꾸는 상태 문구를 각 상태에서 읽는다. 새로 작성한 UI 설명은 사용자가 정한 언어로 쓰며, 한국어 요청에는 한국어를 사용한다. 언어를 고치면서 주장의 뜻을 바꾸지 않는다. 원자료의 외국어 인용·식별자·보호 문자열은 이 점검을 이유로 번역하거나 변경하지 않는다.

초기 HTML의 제목·본문·속성 문구도 처음부터 사용자 언어로 작성한다. 다른 언어로 작성한 초기 마크업을 JavaScript로 뒤늦게 번역하는 방식을 사용하지 않는다. 초기 HTML과 동적으로 넣는 문자열을 함께 대조한다.

## 포함된 진단 도구로 확인하고 다시 점검한다

스킬에 포함된 `scripts/check_html.py`를 Python 3로 실행한다. 스크립트·산출물·진단 파일은 실제 경로를 사용한다. 다음 예시는 스킬 루트에서 실행하는 경로를 보여 준다.

```sh
python3 scripts/check_html.py output.html --language ko > diagnostics.json
```

도구는 HTML을 수정하지 않고 JSON 진단을 출력한다. 초기 마크업·접근성 속성·JavaScript 정적 문자열의 가나·한자, 외부 자원 참조, 레이블 연결, 폼 메서드와 같은 제어 이름을 확인한다. JavaScript 문자열이 실제로 화면에 표시되는지는 정적 진단만으로 확정하지 않는다. 한자는 한국어 원자료에도 쓰이므로 언어 오류로 단정하지 않고 원문 대조를 요구한다.

`issues_found`와 `review_required`는 종료 코드 1이며 제출 전 확인이 필요하다. 진단의 행·열·문맥·발췌를 원문 및 화면과 대조하고, 새로 작성한 문구나 코드를 고친 뒤 같은 명령으로 다시 검사한다. 수정 전·후 산출물과 진단을 구별해 보존하고, 원자료와 이미 보존한 원시 출력을 덮어쓰지 않는다. `no_findings`는 종료 코드 0이며 이 도구가 찾는 패턴이 없다는 뜻이다. 의미 보존·한국어 품질·브라우저 동작의 합격을 뜻하지 않는다. 입력 파일이나 인수가 잘못되면 `invalid_input`과 종료 코드 2를 반환한다.

원문 외국어를 보존해야 하면 실제 원문에서 확인한 문자열만 JSON 문자열 목록으로 만들고 `--protected-text protected.json`을 추가한다. 전체 원문이나 넓은 부분 문자열을 허용 목록으로 넘기지 않는다. 도구는 텍스트 단위 전체와 일치하는 문자열만 보호 대상으로 표시하고, 해당 원문과 표시 위치의 검토를 계속 요구한다. 보호 일치만으로 진단을 통과 처리하지 않는다. 코드 예문과 표준 DOM 조회 식별자는 UI 문구라고 단정하지 않고 `exclusions`에 위치와 이유를 기록한다.

진단에서 누락될 수 있는 계산식·동적 조합 문자열·CSS 표시·실제 가시성은 별도로 확인한다. 정적 진단 뒤에도 앞 절의 브라우저 상태·초기화·키보드·좁은 화면 검사와 원문 의미 대조를 수행한다.

검사할 도구가 없으면 코드를 생성했다는 사실과 실행·화면에서 확인하지 못한 범위를 구별한다. 스크린샷 한 장으로 계산·키보드·접근성 전체가 검증됐다고 쓰지 않는다.
